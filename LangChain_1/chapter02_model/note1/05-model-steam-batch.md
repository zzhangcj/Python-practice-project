# LangChain 模型调用方式小结
## 1. invoke() 同步调用
- 等待模型**全部输出完成**后，一次性返回完整响应
- 缺点：长文本场景用户需要长时间等待，体验差

## 2. stream() 流式调用
- 返回迭代器，循环逐块获取模型输出片段，边生成边返回
- 优点：
  1. 用户无需等待全部完成，感知响应速度更快
  2. 长文本交互体验流畅，可实时展示输出内容
- 前提：所用模型API本身支持流式输出

## 3. batch() 批量调用
- 一次性传入多条独立请求，后台并行处理
- 等待**全部任务执行完毕**，按原始输入顺序返回全部结果列表
- 优点：相比循环逐个invoke，减少网络往返，提升整体性能，节省耗时
- 适用场景：文档摘要、批量问答、文本分类、批量预处理

## 4. batch_as_completed() 按完成顺序接收批量结果
- 任务完成一个就立刻返回一个结果，**返回顺序和输入顺序可能乱序**
- 返回元组格式：`(原始输入索引, 响应对象)`，可依靠索引自行恢复顺序
- 适合各任务耗时差异很大的场景

## 性能对比简要说明
- `batch()`：并行执行，整体耗时远低于循环 `invoke()` 逐个调用，示例测试可节省约50%耗时
- 循环`invoke()`：串行逐个请求，网络往返多，总耗时更长

> 备注：以上为LangChain封装接口；原生OpenAI‑SDK也支持stream流式，不需要依赖LangChain。
