```python
from sqlalchemy.orm import Session
from datetime import datetime

from app.common.exceptions import BusinessException
from app.common.response import PageResponse
from app.models.equipment import Equipment
from app.models.lab import Lab
from app.models.reservation import Reservation
from app.models.user import User
from app.schemas.reservation import ReservationCreateRequest, ReservationResponse

def get_reservation_page_list(
    db: Session,
    current_user: User,
    page: int,
    page_size: int,
    status: int | None = None,
):
    """查询预约的记录"""
    query = db.query(Reservation)
    if current_user.role != "admin":
        query = query.filter(Reservation.user_id == current_user.id)
    if status is not None:
        query = query.filter(Reservation.status == status)
    total = query.count()
    items = (
        query.order_by(Reservation.id.desc())
        .offset((page - 1) * page_size)
        .limit(page_size)
        .all()
    )
    result = []
    for item in items:
        res = ReservationResponse.model_validate(item)
        res.user_name = item.user.name if item.user else None
        res.lab_name = item.lab.name if item.lab else None
        res.equipment_name = item.equipment.name if item.equipment else None
        res.type = "设备" if item.equipment_id else "实验室"
        result.append(res)

    return PageResponse(list=result, total=total)

def cancel_reservation(db: Session, current_user: User, reservation_id: int):
    """学生取消预约"""
    item = db.query(Reservation).filter(Reservation.id == reservation_id).first()
    if not item:
        raise BusinessException(message="预约记录不存在")
    if item.user_id != current_user.id:
        raise BusinessException(message="无权限", code=403)
    if item.status != 0:
        raise BusinessException(message="当前状态无法取消")
    item.status = 3
    db.commit()

def audit_reservation(db: Session, reservation_id: int, status: int):
    """管理员审核预约"""
    if status not in [1, 2]:
        raise BusinessException(message="审核状态错误")
    item = db.query(Reservation).filter(Reservation.id == reservation_id).first()
    if not item:
        raise BusinessException(message="预约记录不存在")
    if item.status != 0:
        raise BusinessException(message="当前状态不支持审核")
    item.status = status
    db.commit()
```



通过传 `status=1`，拒绝传 `status=2`。学生调列表只能看到自己的。管理员能看全部。取消后变成已取消，不能再审。

### reservation API

`api/reservation.py` 追加。`/{reservation_id}/cancel` 写在 `/list` 后面，避免被路径参数抢走。审核接口用 `get_current_admin`：

```python
from fastapi import APIRouter, Depends
from sqlalchemy.orm import Session

from app.common.response import Response
from app.database import get_db
from app.dependencies.auth import get_current_admin, get_current_user
from app.models.user import User
from app.schemas.reservation import AuditReservationRequest, ReservationCreateRequest
from app.services import reservation_service

router = APIRouter(prefix="/reservation", tags=["预约相关接口"])

@router.get("/list")
def get_reservation_page_list(
    page: int = 1,
    page_size: int = 10,
    status: int | None = None,
    current_user: User = Depends(get_current_user),
    db: Session = Depends(get_db),
):
    res = reservation_service.get_reservation_page_list(
        db, current_user, page, page_size, status
    )
    return Response.success(data=res)

@router.put("/{reservation_id}/cancel")
def cancel_reservation(
    reservation_id: int,
    current_user: User = Depends(get_current_user),
    db: Session = Depends(get_db),
):
    reservation_service.cancel_reservation(db, current_user, reservation_id)
    return Response.success()

@router.put("/{reservation_id}/audit")
def audit_reservation(
    reservation_id: int,
    data: AuditReservationRequest,
    current_user: User = Depends(get_current_admin),
    db: Session = Depends(get_db),
):
    reservation_service.audit_reservation(db, reservation_id, data.status)
    return Response.success()
```

**① get_reservation_page_list 预约分页列表**

1. **权限控制在这里做**：`current_user.role != admin` 自动追加 `user_id` 过滤，学生看不到别人预约
2. 外键关联：`item.user / item.lab / item.equipment` 靠模型里的 `relationship`，不需要自己写join(之前研究过的)
3. `type` 字段是**业务衍生字段**，数据库没有，是查出来之后临时组装给前端展示用的
4. 返回统一分页对象 `PageResponse`，和实验室、设备分页接口格式保持一致，前端一套分页组件通用
<br>

 **② cancel_reservation 【学生取消预约】**

- 只有待审核的预约可以取消；已经通过、驳回、已取消的都不能操作
- 权限：**谁预约，谁才能取消**，管理员也不能替学生取消（这段代码逻辑是这样）
- 取消之后 status=3，这条预约不再进入审核流程
<br>

**③ audit_reservation 【管理员审核预约】**

1. 入参校验：防止前端乱传 status，比如传3、4这些非法状态
2. 状态锁：一旦不是待审核，管理员不能重复审核；**已经取消的预约不能审核**（和业务匹配）
3. 这里代码里**没有再判断角色admin** → 角色校验是在路由层 `Depends(get_current_admin)` 控制，service只关心业务校验，符合分层思想
    > 路由层：保证只有管理员能调用这个接口；service不用重复判断角色

<br>

**📋 状态流转图**

```
【0 待审核】
    ├─ 学生取消 → 【3 已取消】（终止，不能审核）
    └─ 管理员审核
        ├─ status=1 → 【1 通过】
        └─ status=2 → 【2 驳回】
【1 通过 / 2 驳回 / 3 已取消】：所有操作都锁死，不能再审核、不能再取消
```
<br>

❗ **隐藏坑点**
### 空值保护

看预约分页里对应的代码：

```python
res.user_name = item.user.name if item.user else None
res.lab_name = item.lab.name if item.lab else None
res.equipment_name = item.equipment.name if item.equipment else None
```

**前提已知**
ORM 的 relationship 关联
`Reservation`预约表里面有外键：`user_id` 关联 `users.id`，并且写了 `relationship` 
正常情况： `item.user` 就是这条预约对应的用户对象，直接 `.name` 拿到用户名。
<br>

**什么时候会出事？**

**主表数据被删掉了，但是子表预约记录还在（脏数据）** 
举例子： 
后台管理员把某个用户删掉了，但是他之前的预约记录没有跟着删除。 
数据库里 reservation 的 `user_id = 5`，但是 users 表里面 id=5 的用户已经不存在了

此时： `item.user` → **是 None** 如果你直接写：

```python
# ❌ 危险写法
res.user_name = item.user.name
```

程序会执行 `None.name` → 直接抛出异常，整个分页接口 500 报错，页面刷不出来！

✅ `item.user.name if item.user else None` 的含义：

- 如果 `item.user` 有对象（用户存在）→ 取 `.name`
- 如果 `item.user` 是 None（用户已经删掉）→ 赋值 None，不报错

> 一句话：做**空值保护**，防止外键关联丢失导致接口崩溃。 这个现象术语叫：**外键软删除 / 没有级联删除产生孤立数据**

### ref/reactive
**需求情景**

`ref` 就是 **Vue 给普通 JS 变量套一个「响应式盒子」**。
> 原生 JS：变量改了，页面不会自动更新 包上 `ref`：盒子里面的值一变，Vue 自动去刷新页面上用到它的地方
>

**1. 基础写法**

```
import { ref } from 'vue'

// 盒子里面放布尔
const loading = ref(false)
// 盒子里面放数组
const tableData = ref([])
// 盒子里面放数字
const count = ref(0)
// 盒子里面放字符串
const name = ref("张三")
```

✅ ref 里面**可以放任意类型的值**：布尔、数字、字符串、数组、对象全都行。 `ref(xxx)` → xxx 是**盒子里面装的原始数据**。

**2. 最重要区别**
脚本里访问要加 `.value`，模板里不用

```javascript
// script 里面（JS代码）
loading.value = true   // ✅ 打开盒子，修改里面的值
tableData.value = [{}, {}] 

// template 模板里面（HTML部分）
v-loading="loading"   // ✅ 直接写loading，不用 .value
```

原因：Vue模板会自动帮你把ref的盒子拆开，不用手动写`.value`。
<br>

**3. 那为什么还有 reactive？**

`reactive` 不套单层盒子，它**专门直接包裹对象**，不使用 `.value`

```javascript
import { reactive } from 'vue'
const params = reactive({
  page:1,
  status:null
})
// 修改的时候直接点属性，不用 .value
params.page = 2
```

> 简单区分

1. **ref：万能盒子** 里面可以放：布尔、数字、字符串、数组、对象。 
	1. ✅ JS代码读写：`.value` 
	2. ✅ 适合：单个独立数据（loading、表格数组、数字）
2. **reactive：只适合对象** 里面只能放对象 `{a:1,b:2}` 
	1. ✅ JS代码读写：直接点 `.属性`，不用`.value`
	2. ✅ 适合：打包在一起的一组参数（查询条件params）

> 补充
> ref 也能放对象，但是规范习惯上： 零散单个数据用ref；
> 一组相关参数打包成对象，用reactive

<br>

**5. 原生JS对比（理解响应式到底是什么）**

原生JS（没有ref，不会自动更新页面）

```javascript
let loading = false
loading = true
// 改了loading，页面不会自己变！Vue不知道这个变量变了
```

加ref之后（Vue能监控）

```javascript
const loading = ref(false)
loading.value = true
// Vue监听这个盒子，里面值一变，自动刷新页面
```
<br>

**6. 回到刚才页面里的三个变量，再串一遍**

```javascript
const loading = ref(false)
// 盒子里布尔：控制加载转圈，请求时 loading.value=true

const tableData = ref([])
// 盒子里数组：存后端返回的一堆预约记录，每一行是一个对象
// 接口拿到数据：tableData.value = res.data.list

const params = reactive({page:1,page_size:10,status:null})
// 这是对象，所以用reactive，是发给后端的查询条件
```


### 状态映射函数 
statusType /statusText

```javascript
const statusType = (status) => {
  return { 0: 'warning', 1: 'success', 2: 'danger', 3: 'info' }[status] || '-'
}
const statusText = (status) => {
  return { 0: '待审核', 1: '已通过', 2: '已拒绝', 3: '已取消' }[status] || '-'
}
```

**一句话核心**
这两个就是**翻译函数**，不是点击触发的事件，专门把后端返回的数字，翻译成页面能用的内容。
- `statusText`：数字 → 中文文字
	- 0 → 待审核，1 → 已通过
- `statusType`：数字 → ElementPlus标签颜色标识
	- 0 → warning（黄色），1 → success（绿色）

<br>

**写法解释**
```javascript
{0: 'warning', 1: 'success'}[status]
```

用 `status` 当做字典里面的key，去对象里面找对应的值。
`|| '-'`：万一后端传回一个不存在的数字，就显示 `-`，页面不会炸。
<br>

**使用地方**
```vue
<el-tag :type="statusType(row.status)">
  {{ statusText(row.status) }}
</el-tag>
```

渲染表格的时候自动调用，拿到翻译结果展示
<br>

**重点记住**
- 规则后端说了算，前端只负责翻译展示，**不能靠前端判断业务**。
- 不是点击才跑那种事件绑定按钮，而是表格渲染每一行的时候自动执行


### 加载函数load

```JavaScript
const load = async () => {
  loading.value = true
  try {
    const res = await getReservationPageList(params)
    if (res.code === 200) {
      tableData.value = res.data?.list
      total.value = res.data?.total
    }
  } finally {
    loading.value = false
  }
}
```

✅ 知识点：
- `async / await` 异步请求
- `try...finally`：**不管请求成功还是报错，finally 一定会执行**
- `loading` 关闭写在`finally`这里，不要写在 `try` 里面（请求报错 loading 会一直转）
- 可选链 `res.data?.list`：如果 res.data 是 null，不会报 `Cannot read property 'list' of null`，防止页面崩溃

### v-if
**需求情景**
页面上有一部分内容，**不是一直都要显示**，满足某个条件才展示，不满足就直接不渲染这个元素。

代码例子：
```vue
<el-button v-if="row.status === 0">取消</el-button>
```

业务：只有预约状态是【待审核（0）】，才出现取消按钮；其他状态，这个按钮直接消失。
<br>

**作用**
`v-if`：**条件渲染** 
- 条件成立 → 把这个标签渲染到页面上 
- 条件不成立 → 这个标签直接不存在（DOM里没有这个元素）
<br>

**简单对比**
- 条件 `row.status === 0` 为true：页面能看到取消按钮
- 条件false：按钮直接没有，不是看不见，是根本没生成

### loading、v-loading
**需求情景**

发后端接口的时候，网络有延迟。
用户不知道页面有没有在加载，可能反复点按钮。
于是做**加载遮罩转圈**：请求发起时转圈，请求结束关掉转圈。

 **1. `loading`**
```javascript
const loading = ref(false)
```

`loading` 是**我们自己定义的响应式变量（盒子）**

- 布尔类型：`true` = 加载中；`false` = 加载完成
- 写在script里，用来标记请求状态
- 在 `load()` 里：

```javascript
loading.value = true   // 开始请求，打开加载标记
// 发接口请求
finally {
  loading.value = false // 不管成功失败，关闭标记
}
```

<br>

**2. `v-loading`**

```vue
<el-table v-loading="loading" />
```

`v-loading` 是 **Element Plus 的指令** 
作用：绑定一个布尔变量，自动在这个元素上展示加载转圈遮罩

- 绑定的变量是 `loading`
- 当 `loading === true` → 表格上面出现转圈
- 当 `loading === false` → 转圈消失

<br>

✅ **一句话区别**
- `loading`：**变量（存状态）**，记录是不是正在加载
- `v-loading`：**指令（UI效果）**，读取这个变量，控制转圈显示隐藏

> 关系：v-loading 依赖 loading 变量，二者搭配使用，缺一不可

<br>

**补充知识点 & 坑**

1. 绑定位置：`v-loading` 写在哪个标签上，转圈就盖在哪个区域 你写在 el-table 上，遮罩只盖住表格； 如果写在 el-card 上，整个卡片都会被遮罩盖住。
2. 为什么写在 finally？ 不管接口成功、报错，`loading.value=false` 一定会执行，防止转圈一直卡在页面上。
3. 拓展（了解即可） v-loading 可以加文字：

```vue
<el-table v-loading="loading" element-loading-text="加载中..." />
```
