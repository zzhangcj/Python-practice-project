```python
from sqlalchemy.orm import Session
from datetime import datetime

from app.common.exceptions import BusinessException
from app.common.response import PageResponse
from app.models.equipment import Equipment
from app.models.lab import Lab
from app.models.reservation import Reservation
from app.models.user import User
from app.schemas.reservation import ReservationCreateRequest, ReservationResponse

def get_reservation_page_list(
    db: Session,
    current_user: User,
    page: int,
    page_size: int,
    status: int | None = None,
):
    """查询预约的记录"""
    query = db.query(Reservation)
    if current_user.role != "admin":
        query = query.filter(Reservation.user_id == current_user.id)
    if status is not None:
        query = query.filter(Reservation.status == status)
    total = query.count()
    items = (
        query.order_by(Reservation.id.desc())
        .offset((page - 1) * page_size)
        .limit(page_size)
        .all()
    )
    result = []
    for item in items:
        res = ReservationResponse.model_validate(item)
        res.user_name = item.user.name if item.user else None
        res.lab_name = item.lab.name if item.lab else None
        res.equipment_name = item.equipment.name if item.equipment else None
        res.type = "设备" if item.equipment_id else "实验室"
        result.append(res)

    return PageResponse(list=result, total=total)

def cancel_reservation(db: Session, current_user: User, reservation_id: int):
    """学生取消预约"""
    item = db.query(Reservation).filter(Reservation.id == reservation_id).first()
    if not item:
        raise BusinessException(message="预约记录不存在")
    if item.user_id != current_user.id:
        raise BusinessException(message="无权限", code=403)
    if item.status != 0:
        raise BusinessException(message="当前状态无法取消")
    item.status = 3
    db.commit()

def audit_reservation(db: Session, reservation_id: int, status: int):
    """管理员审核预约"""
    if status not in [1, 2]:
        raise BusinessException(message="审核状态错误")
    item = db.query(Reservation).filter(Reservation.id == reservation_id).first()
    if not item:
        raise BusinessException(message="预约记录不存在")
    if item.status != 0:
        raise BusinessException(message="当前状态不支持审核")
    item.status = status
    db.commit()
```



通过传 `status=1`，拒绝传 `status=2`。学生调列表只能看到自己的。管理员能看全部。取消后变成已取消，不能再审。

### reservation API

`api/reservation.py` 追加。`/{reservation_id}/cancel` 写在 `/list` 后面，避免被路径参数抢走。审核接口用 `get_current_admin`：

```python
from fastapi import APIRouter, Depends
from sqlalchemy.orm import Session

from app.common.response import Response
from app.database import get_db
from app.dependencies.auth import get_current_admin, get_current_user
from app.models.user import User
from app.schemas.reservation import AuditReservationRequest, ReservationCreateRequest
from app.services import reservation_service

router = APIRouter(prefix="/reservation", tags=["预约相关接口"])

@router.get("/list")
def get_reservation_page_list(
    page: int = 1,
    page_size: int = 10,
    status: int | None = None,
    current_user: User = Depends(get_current_user),
    db: Session = Depends(get_db),
):
    res = reservation_service.get_reservation_page_list(
        db, current_user, page, page_size, status
    )
    return Response.success(data=res)

@router.put("/{reservation_id}/cancel")
def cancel_reservation(
    reservation_id: int,
    current_user: User = Depends(get_current_user),
    db: Session = Depends(get_db),
):
    reservation_service.cancel_reservation(db, current_user, reservation_id)
    return Response.success()

@router.put("/{reservation_id}/audit")
def audit_reservation(
    reservation_id: int,
    data: AuditReservationRequest,
    current_user: User = Depends(get_current_admin),
    db: Session = Depends(get_db),
):
    reservation_service.audit_reservation(db, reservation_id, data.status)
    return Response.success()
```

**① get_reservation_page_list 预约分页列表**

1. **权限控制在这里做**：`current_user.role != admin` 自动追加 `user_id` 过滤，学生看不到别人预约
2. 外键关联：`item.user / item.lab / item.equipment` 靠模型里的 `relationship`，不需要自己写join(之前研究过的)
3. `type` 字段是**业务衍生字段**，数据库没有，是查出来之后临时组装给前端展示用的
4. 返回统一分页对象 `PageResponse`，和实验室、设备分页接口格式保持一致，前端一套分页组件通用
<br>

 **② cancel_reservation 【学生取消预约】**

- 只有待审核的预约可以取消；已经通过、驳回、已取消的都不能操作
- 权限：**谁预约，谁才能取消**，管理员也不能替学生取消（这段代码逻辑是这样）
- 取消之后 status=3，这条预约不再进入审核流程
<br>

**③ audit_reservation 【管理员审核预约】**

1. 入参校验：防止前端乱传 status，比如传3、4这些非法状态
2. 状态锁：一旦不是待审核，管理员不能重复审核；**已经取消的预约不能审核**（和业务匹配）
3. 这里代码里**没有再判断角色admin** → 角色校验是在路由层 `Depends(get_current_admin)` 控制，service只关心业务校验，符合分层思想
    > 路由层：保证只有管理员能调用这个接口；service不用重复判断角色

<br>

**📋 状态流转图**

```
【0 待审核】
    ├─ 学生取消 → 【3 已取消】（终止，不能审核）
    └─ 管理员审核
        ├─ status=1 → 【1 通过】
        └─ status=2 → 【2 驳回】
【1 通过 / 2 驳回 / 3 已取消】：所有操作都锁死，不能再审核、不能再取消
```
<br>

❗ **隐藏坑点**
### 空值保护

看预约分页里对应的代码：

```python
res.user_name = item.user.name if item.user else None
res.lab_name = item.lab.name if item.lab else None
res.equipment_name = item.equipment.name if item.equipment else None
```

**前提已知**
ORM 的 relationship 关联
`Reservation`预约表里面有外键：`user_id` 关联 `users.id`，并且写了 `relationship` 
正常情况： `item.user` 就是这条预约对应的用户对象，直接 `.name` 拿到用户名。
<br>

**什么时候会出事？**

**主表数据被删掉了，但是子表预约记录还在（脏数据）** 
举例子： 
后台管理员把某个用户删掉了，但是他之前的预约记录没有跟着删除。 
数据库里 reservation 的 `user_id = 5`，但是 users 表里面 id=5 的用户已经不存在了

此时： `item.user` → **是 None** 如果你直接写：

```python
# ❌ 危险写法
res.user_name = item.user.name
```

程序会执行 `None.name` → 直接抛出异常，整个分页接口 500 报错，页面刷不出来！

✅ `item.user.name if item.user else None` 的含义：

- 如果 `item.user` 有对象（用户存在）→ 取 `.name`
- 如果 `item.user` 是 None（用户已经删掉）→ 赋值 None，不报错

> 一句话：做**空值保护**，防止外键关联丢失导致接口崩溃。 这个现象术语叫：**外键软删除 / 没有级联删除产生孤立数据**


### 两层权限控制
>说白了，就一句话
>
>管理员、普通用户**都要用**的业务函数（接口），路由统一用 `get_current_user`（只校验登录），**数据 / 行权限在 service 里面用if语句判断**； 
>
>**专属管理员的**的业务函数（接口），路由直接用 `get_current_admin` 前置鉴权，在入口就拦住普通用户，service 里面不再重复判断角色


1、属于管理员、普通用户共有的
- 预约列表接口 `@router.get("/list")`
- 取消预约接口 `@router.put("/{reservation_id}/cancel")`
```python
#在路由层
current_user: User = Depends(get_current_user)
```
✅ 路由层：只要求登录，学生、管理员都可以访问这个接口
但是我们需要做两件事：
- 管理员进来：不追加过滤，查到全部预约记录
- 学生进来：自动加上 `user_id = 当前用户id`，只能看到自己的预约
所以
```python
# service内部代码
if current_user.role != "admin":
    query = query.filter(Reservation.user_id == current_user.id)
```

<br>

2、专属于管理员的
- 审核接口 `@router.put("/{reservation_id}/audit")`
```python
#在路由层
current_user: User = Depends(get_current_admin)
```

✅ 权限在**路由依赖直接拦截** `get_current_admin` 里面会判断角色，如果是学生，在这里直接报错 403，**根本不会执行函数里面的代码，更不会进到 service 的 audit_reservation** 
✅ 所以 `audit_reservation` 这个 service 函数里面，**完全没有判断角色的代码** 它只负责业务校验：
- 预约记录是否存在
- 状态是不是待审核
- 传入的 status 是不是合法（1/2）


### 衍生字段type

✅**需求情景**
数据库 `reservations` 表里面**没有 type 这个字段**。 数据库只有 `equipment_id`：

- `equipment_id` 有值 → 这条预约是【预约某一台设备】
- `equipment_id` 是 `null` → 这条预约只预约【整个实验室，不指定设备】

前端页面展示的时候，需要一列文字区分这条预约是什么类型：显示 “设备” 或者 “实验室”，方便用户一眼看懂。
所以我们在返回给前端的 `ReservationResponse` 这个 Schema 里面，额外加了一个 `type` 字段。

> 注意： `type` 不是数据库读出来的，**是后端查完 ORM 对象之后，现场算出来，塞到响应对象里的衍生字段**。

>**衍生字段（计算字段）**：不在数据库表内，根据已有字段逻辑计算生成，只用于前端展示

<br>

**联动代码**
```python
#get_reservation_page_list
res.type = "设备" if item.equipment_id else "实验室"
```

- `item`：ORM 模型对象（Reservation），来自数据库
- 判断条件：`item.equipment_id` 是否有值
    - 有 equipment_id → 赋值 `type = "设备"`
    - equipment_id 为 None → 赋值 `type = "实验室"`
