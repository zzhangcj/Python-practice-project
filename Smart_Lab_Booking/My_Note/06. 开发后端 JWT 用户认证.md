```python
from datetime import datetime, timedelta
import jwt
from app.config import settings

def create_access_token(user_id: int) -> str:
    """创建JWT token"""
    expire = datetime.now() + timedelta(hours=settings.JWT_EXPIRE_HOURS)

    payload = {"user_id": user_id, "exp": expire}  # exp是固定key，不能写成别的

    return jwt.encode(
        payload, settings.JWT_SECRET_KEY, algorithm=settings.JWT_ALGORITHM
    )

def decode_access_token(token: str) -> dict:
    """解析jwt token"""
    return jwt.decode(
        token, settings.JWT_SECRET_KEY, algorithms=[settings.JWT_ALGORITHM]
    )
```

### 最终版本的 login api
即api/auth.py
```python
from fastapi import APIRouter, Depends
from app.schemas.auth import LoginRequest
from sqlalchemy.orm import Session
from app.database import get_db
from app.models.user import User
from app.schemas.user import UserResponse
from app.utils.password import verify_password
from app.utils.jwt import create_access_token

router = APIRouter(prefix="/auth", tags=["权限验证"])

@router.post("/login")
def login(data: LoginRequest, db: Session = Depends(get_db)):
    # 根据用户账号查询数据库
    user = db.query(User).filter(User.username == data.username).first()

    # 判断账号和密码是否正确
    if not user or not verify_password(data.password, user.password):
        return {"code": 400, "message": "账号或密码错误"}
    # 验证账号的状态
    if user.status != 1:
        return {"code": 403, "message": "账号已被禁用"}
    # 创建token
    token = create_access_token(user.id)
    # 返回信息
    return {
        "code": 200,
        "message": "操作成功",
        "data": {"token": token, "user": UserResponse.model_validate(user)},
    }
```
注意：这里不能直接复制进去，单纯到这一步，router那里需要改成下面这个，apipost才能成功发送并返回

```python
from fastapi import Depends, HTTPException, status
from fastapi.security import OAuth2PasswordBearer
from sqlalchemy.orm import Session

from app.database import get_db
from app.models.user import User
from app.utils.jwt import decode_access_token

oauth2_scheme = OAuth2PasswordBearer(tokenUrl="/api/auth/login")

def get_current_user(
    token: str = Depends(oauth2_scheme), db: Session = Depends(get_db)
) -> User:
    """JWT token 鉴权验证合法性"""
    try:
        payload = decode_access_token(token)
    except Exception:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED, detail="登录已失效，请重新登录"
        )
    # 获取到用户ID
    user_id = payload.get("user_id")
    if not user_id:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED, detail="无效的登录凭证"
        )
    # 从数据库根据用户ID查询用户信息
    user = db.query(User).filter(User.id == user_id).first()
    if user.status != 1:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED, detail="用户被禁用"
        )
    return user
```

**修正：用户已删除时的鉴权与登录地址**

上面的查询可能返回 `None`，继续访问 `user.status` 会触发异常。应在查询后、状态判断前加入以下代码，使仍持有有效 Token 的已删除用户收到 HTTP 401：

```python
# Token 有效不代表账号仍存在，查不到用户时拒绝本次访问。
if user is None:
    raise HTTPException(
        status_code=status.HTTP_401_UNAUTHORIZED,
        detail="用户不存在，请重新登录",
    )
```

同时将 `OAuth2PasswordBearer` 的 `tokenUrl` 从 `/api/autrh/login` 改为 `/api/auth/login`。该地址用于接口文档中的 OAuth2 登录流程，不改变从请求头提取 Bearer Token 的行为；文档登录能否成功还取决于登录接口是否接收 OAuth2 表单并返回相应的 Token 格式。

# 代码解析

## 1、补充
### （1）这一章到底在做什么
>**保护私有接口，做身份校验，防止陌生人随意操作他人数据**
>**减少密码传输、减少数据库查询**

**情景分析**：
- 我们正在开发智能实验室预约系统。系统里有获取个人信息、预约实验室、查看我的预约记录这类接口，这些接口操作的是用户的私有数据。**如果接口不加任何校验（裸奔），任何人打开 Apipost 直接发请求，就可以随意查看、修改别人的预约和个人信息，数据完全不安全。**
- 同时 HTTP 协议是无状态的，每一次请求都是独立的，**服务器不会自动记住用户已经登录过**。 如果想要限制陌生人访问，笨办法就是每次访问私有接口都带上账号密码，后端反复查询数据库比对密码；
- 但是这个方案**密码多次在网络传输，风险高**，还会**频繁查询数据库，性能差**

所以，我们需要**保护私有接口，做身份校验，防止陌生人随意操作他人数据**，这么做同时还能顺带**减少密码传输、减少数据库查询**

**解决方法：** 
>使用 **JWT + bcrypt** 改造登录流程，实现登录**鉴权**
1. 用户提交账号密码登录，后端从数据库查询用户，用 bcrypt 校验加密密码；
2. 校验通过，生成 JWT 令牌（Token 通行证）返回给前端；
3. 前端保存 Token，之后访问需要保护的私有接口时，在请求头带上这个 Token；
4. 后端通过依赖函数解析、校验 Token，确认是合法登录用户才放行接口；
5. 登录接口、注册接口保持公开，不需要 Token。

### （2）知识点补充
1. **用户认证** 就是校验访问接口的人是谁，确认对方是系统里已经注册登录的合法用户。在本项目里，用来区分：是登录的本人，还是匿名陌生人。

2. **鉴权（新增）** 简单说：**检查通行证是否有效，判断能不能放行本次请求的这个动作，就叫鉴权**。 在我们代码里，`get_current_user` 这个依赖函数，干的就是鉴权：取出 Token、解码校验、查用户、判断是否有效。

> 	区分
> 	认证：登录的时候，核对账号密码，证明 “你是谁”；
> 	鉴权：后续访问接口的时候，核对 Token 通行证，检查 “你有没有资格访问这个接口”

3. **Token（令牌 / 通行证）** 登录成功之后后端下发的一串字符串，相当于临时通行证
>账号密码只在登录的时候提交一次；后续访问私有接口，只传递 Token，不再传递账号密码。Token 带有过期时间，到期失效，需要重新登录获取新 Token

4. **JWT（JSON Web Token）** 是一种标准化的 Token 格式，用来在网络请求里传递身份信息
>分为头部、载荷、签名三部分：
- 头部：记录加密算法（本项目使用 HS256）
- 载荷：存放用户标识 user_id、过期时间`exp`（exp 是固定关键字段，用来控制有效期）
- 签名：用密钥加密生成，防止别人篡改 Token 里面的信息
> ⚠️ 注意：载荷里不要存放密码这类敏感隐私数据

5. **bcrypt** 密码加密工具。数据库不再保存明文密码，只保存加密后的密文；
>校验密码时，对比输入密码和数据库里的密文。就算数据库泄露，别人也无法直接拿到用户原始密码。

6. **HTTP 无状态** HTTP 每一次请求互相独立，请求结束之后服务器不会记住上一次是谁登录的。
>Token 就是用来弥补这个特点

7. 两种接口区分
- 公开接口：登录、注册接口，所有人都可以访问，不需要 Token
- 受保护接口：获取个人信息、预约实验室、查看预约记录，必须携带合法 Token 才能访问

## 2、配置 JWT 环境变量

```
JWT_SECRET_KEY=F2DtkACCejMl6FMnJWEbBBX2uldFIB4r0fPILvAltaf
JWT_EXPIRE_HOURS=24
JWT_ALGORITHM=HS256
```

1. **JWT_SECRET_KEY（密钥）
- 生成Token的时候，后端用这个密钥给Token打上“防伪印章”
- 校验Token的时候，后端拿同一个密钥检查印章是否真实

2. **JWT_EXPIRE_HOURS=24** 
- 代表Token有效期：**24小时**。 
- Token里面自带过期时间，到时间之后，就算Token本身没有被篡改，后端也会判定它失效，需要用户重新登录。 
- 目的：防止一张通行证永久有效，降低被盗用之后的风险。

3. **JWT_ALGORITHM=HS256** 
- 指定加密签名算法：HS256，是JWT最常用的对称加密算法。
    > 对称加密：加密、解密、验签，用的是**同一个密钥（就是上面的SECRET_KEY）**

**为什么要在 config 的 Settings 里面新增 JWT 相关配置**
`.env` 文件只是存放配置字符串的文本文件，Python 代码**不能直接读取.env**
`config.py` 的 `Settings` 类（继承 BaseSettings），专门负责：

1. 自动读取 `.env` 里面的环境变量
2. 做类型校验，把变量转为我们需要的类型（字符串、数字等）
3. 封装成 `settings` 对象，**给项目里所有业务代码（比如 jwt.py）提供统一读取入口**

所以链路是： `.env（写原始配置）` → `config.py Settings（读取+包装）` → `jwt.py 导入settings使用`

额外好处：
1. 集中管理，JWT 密钥、算法、过期时长统一放在一套配置里；修改只改.env，不用到处改业务代码
2. 敏感密钥放在.env，.env 加入 git 忽略，不会上传到 github，保护密钥安全
3. 可以设置默认值：`JWT_ALGORITHM: str = "HS256"`、`JWT_EXPIRE_HOURS: int = 24`，.env 漏写也能正常运行
4. 强制校验：`JWT_SECRET_KEY` 没有默认值，忘记在.env 配置，项目启动直接报错提醒

新建jwt.py和**init**.py

```python
from datetime import datetime, timedelta
import jwt
from app.config import settings

def create_access_token(user_id: int) -> str:
    """创建JWT token"""
    expire = datetime.now() + timedelta(hours=settings.JWT_EXPIRE_HOURS)

    payload = {"user_id": user_id, "exp": expire}  # exp是固定key，不能写成别的

    return jwt.encode(
        payload, settings.JWT_SECRET_KEY, algorithm=settings.JWT_ALGORITHM
    )

def decode_access_token(token: str) -> dict:
    """解析jwt token"""
    return jwt.decode(
        token, settings.JWT_SECRET_KEY, algorithms=[settings.JWT_ALGORITHM]
    )
```

逐行拆解：
1. 导入部分
- `from datetime import datetime, timedelta`：时间工具，用来计算 Token 过期时间
- `import jwt`：pyjwt 库，提供编码、解码 JWT 的能力
- `from app.config import settings`：导入我们在 config.py 实例化好的 settings 对象，用来读取 JWT 的全套配置（密钥、算法、过期小时数）

2. `create_access_token(user_id: int)`：登录成功时调用，生成通行证 Token

- `timedelta(hours=settings.JWT_EXPIRE_HOURS)` timedelta 用来表示一段时间；时长取自 `settings.JWT_EXPIRE_HOURS`，这个值经过 config 读取自.env 文件，方便统一修改有效期
- `payload`：**载荷，存放Token需要携带的信息**
    - `user_id`：自定义内容，标记这个 token 归属哪个用户
    - `exp`：JWT 库识别的固定字段，pyjwt 自动校验这个时间，时间到就判定 token 失效
- `jwt.encode()`：传入载荷、密钥、加密算法，**生成 JWT 字符串**

1. `decode_access_token(token: str)`：
这个函数的作用就是**解析**：前端传过来一个token，后端怎么解析呢

- `jwt.decode` 做两件校验： 
>① 使用 `settings.JWT_SECRET_KEY` 校验签名，判断 Token 有没有被人篡改 
>② 自动校验 payload 里的`exp`过期时间，过期直接抛出异常
- 校验全部通过，返回 payload 字典，我们从中取出 user_id

> 注意坑：decode 的 algorithms 是列表格式 `[settings.JWT_ALGORITHM]`，是 pyjwt 库的固定要求，和 encode 写法不一样

### password.py
```python
import bcrypt

def hash_password(password: str) -> str:
    """对密码加密"""
    return bcrypt.hashpw(password.encode("utf-8"), bcrypt.gensalt()).decode("utf-8")

def verify_password(password: str, hashed_password: str) -> bool:
    """验证密码的有效性"""
    """  "123" -> "xxsdasdasdasfa"  """
    return bcrypt.checkpw(password.encode("utf-8"), hashed_password.encode("utf-8"))
```

- `import bcrypt`：bcrypt 加密库，专门做密码哈希加密

1. `hash_password(明文密码)`
    
    - `password.encode("utf-8")`：bcrypt 只接受 bytes 字节类型，所以需要将字符串转字节
    - `bcrypt.gensalt()`：自动生成盐值（salt）。盐是一串**随机**字符串，作用：相同密码每次加密出来的密文都不一样，防止彩虹表破解
    - `bcrypt.hashpw()`：把明文 + 盐，算出加密后的字节密文
    - `.decode("utf-8")`：把字节密文转回字符串，方便存入 MySQL 数据库
    
    > 返回值：加密后的密文，存到 user 表的 password 字段，**数据库绝不保存明文密码**
    
2. `verify_password(用户输入的明文密码, 数据库取出的密文密码)`
    - `bcrypt.checkpw()`：bcrypt 自带的比对函数
    - 内部逻辑：不用把密文解密回明文！bcrypt 是单向哈希，**不能解密**
    - 它会使用密文中自带的 salt，对输入的密码重新做一次加密运算，然后对比两次结果是否一致
    - 返回布尔值：匹配成功返回 True，失败返回 False

## 5、dependencies/auth.py
```python
from fastapi import Depends, HTTPException, status
from fastapi.security import OAuth2PasswordBearer
from sqlalchemy.orm import Session

from app.database import get_db
from app.models.user import User
from app.utils.jwt import decode_access_token

oauth2_scheme = OAuth2PasswordBearer(tokenUrl="/api/auth/login")

def get_current_user(
    token: str = Depends(oauth2_scheme), db: Session = Depends(get_db)
) -> User:
    """JWT token 鉴权验证合法性"""
    try:
        payload = decode_access_token(token)
    except Exception:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED, detail="登录已失效，请重新登录"
        )
    # 获取到用户ID
    user_id = payload.get("user_id")
    if not user_id:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED, detail="无效的登录凭证"
        )
    # 从数据库根据用户ID查询用户信息
    user = db.query(User).filter(User.id == user_id).first()
    if user.status != 1:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED, detail="用户被禁用"
        )
    return user
```

### 消息的组成
HTTP 请求 = 发给后端的一条消息。 
这条消息分成两块：**请求头（header）** + 请求体（body）
- 请求体：放业务数据，比如登录时的用户名、密码（就是 LoginRequest 接收的内容）
- **请求头：附加的、描述这条请求的附属信息**，比如身份凭证、请求类型、编码等，放在消息最前面。

`Authorization` 就是**请求头（header）**的一种

### OAuth2PasswordBearer
**情景：**
前端发出请求，需要进行认证，那这个时候我该如何获取token呢？

> OAuth2PasswordBearer 是 FastAPI 提供的安全工具

1. **核心作用** 配合 `Depends()`，自动从 `Authorization` 请求头提取 token。
2. **强制约定格式** 只识别：`Authorization: Bearer 空格 token`这一种格式
>（就像写作文，格式要求必须是标题，开头，正文，结尾，缺一不可）

- `Bearer`：固定标识，后面跟一个空格，再放 JWT 字符串
- 格式不对、缺少该请求头，直接抛出 401

3. **参数 tokenUrl**`tokenUrl="/api/auth/login"` 仅为提示地址，告诉前端去哪里获取 token；**不会自动请求、跳转登录接口**。
4. **边界** 它**只负责提取 token，不校验 token**


### 传token的方式
1. token 本身（那一串 JWT 字符串）**内容不变**，变的只是「怎么发给后端」，也就是传输方式。
2. 传 token 有很多种办法：
    - 方式 A：放请求头（当前方案， `OAuth2PasswordBearer` 只支持这个方式）
    - 方式 B：放 URL 参数 `/api/xxx?token=xxxx`
    - 方式 C：放到请求 body（json 里面带 token）
>你现在选了 `OAuth2PasswordBearer`，这个工具**只认方式 A**传输token：
>即
>		**请求头必须命名为 `Authorization`**
>		该请求头内部内容格式： `Authorization: Bearer 空格 token串`

流程如下：
```
GET /api/user/info

Authorization: Bearer eyJhbGciOiJIUzI1NiIs...

token: str=Depends(oauth2_scheme) 就会提取

Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
↓ 
oauth2_scheme
↓ 
token = "eyJhbGciOiJIUzI1NiIs..."
```

**为什么要弄清楚这些问题**

1.  提前明确接口的调用规则：虽然暂时还没有写前端代码，但后端接口已经定下了传token的规则。后续写前端、或者测试接口（比如用Swagger、apipsot）的时候，我就知道：访问受保护接口必须带上 `Authorization: Bearer {token}` 请求头；格式不对就会返回401，避免到时候盲目排查

2.  理解HTTP基础：分清请求头和请求体，理解身份凭证的标准传递方式，这是后端开发、前后端联调的通用基础

已经实现登录接口、JWT 鉴权依赖 `get_current_user`。

```python
from fastapi import APIRouter, Depends
from app.models.user import User
from app.dependencies.auth import get_current_user
from app.schemas.user import UserResponse

router = APIRouter(prefix="/user", tags=["用户信息接口"])

@router.get("/info")

    return {
        "code": 200,
        "message": "请求成功",
        "data": UserResponse.model_validate(current_user),
    }
```


**`Depends(get_current_user)`** 
`Depends` 触发执行 `get_current_user` 这个鉴权依赖函数
- 说明：全部校验通过，把查到的用户对象传给 `current_user`
- return的就是查询到的个人信息

### 验证 token 的示例接口
>注意：此接口是验证 token 的示例接口
>只要有 current_user: User = Depends(get_current_user) 
>那就表示都需要验证 token 合法才可以访问

**这句话在说什么？**
- `current_user: User = Depends(get_current_user)` 就是**开启登录校验的开关**
写了这一行，这个接口就会自动校验 token；不写，就不会校验
- 👉 想让你明白的重点： **哪些接口需要登录保护，不靠别的配置，就看这个参数写没写**

### 路由分组与统一前缀
用**楼栋 + 房间号**这个比喻，层级清晰，贴合路由拼接，不容易混淆：
- `app` = 整个大楼（你的整个后端服务）
- `api` = 大楼里的二楼区域，这块区域统一贴了标牌： `/api`
- `auth`、`user` = 二楼里面的两个独立房间： auth 房间、user 房间
    - auth 房间标牌：`/auth`
    - user 房间标牌：`/user`

👉 以前的做法： auth 房间、user 房间，各自牌子上都要额外写上「二楼 (api)」，重复标注，比如（二楼/201，二楼/202）
👉 现在的改动： 把「二楼」这个标识放在二楼楼梯口，上楼就能看到。 房间 auth、user 只写自己房间名字，不用再写二楼，比如（201，202） 
访客地址自动拼起来：二楼 + auth 房间 → `/api/auth`

好处： 以后想把二楼改成三楼 `/v1/api`，**只改二楼这块区域的标牌，里面所有房间牌子不用动**。
