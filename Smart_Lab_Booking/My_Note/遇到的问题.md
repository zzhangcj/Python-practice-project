## 1、a标签已经写 text-decoration: none，链接依然带下划线
原因
浏览器原生默认样式使用伪类 `a:link` / `a:visited`，伪类选择器优先级高于普通 `a {}`，覆盖了我们写的样式。 

解决方案
修改 global.css
```css
/* 链接 */
a,
a:link,
a:visited {
  color: inherit;
  text-decoration: none;
}
```

# 2、FastAPI 内置 Swagger‑UI 交互式接口文档空白问题

来自  **二、后端相关的知识点总结  5、users.py 和自动建表**


问题现象：
 **`http://127.0.0.1:8000/docs`**
 这个网址的访问效果如下，没有显示，同时浏览器 F12 控制台报错

![[Pasted image 20261026171627.png]]

**根本原因**

FastAPI 默认从**国外 CDN**下载 swagger 的 js、css 静态资源；国内网络访问受限，脚本加载失败，页面空白。
> 根路由不受影响，因为根路由只返回后端 JSON，不依赖外部前端资源。
> 
	这里是说http://127.0.0.1:8000访问正常

**解决方案**


修改 `main.py` FastAPI 实例配置：

```python
from fastapi import FastAPI

app = FastAPI(
    docs_url="/docs",
    swagger_ui_parameters={
        "swaggerJsUrl": "https://cdn.bootcdn.net/ajax/libs/swagger-ui/5.17.12/swagger-ui-bundle.js",
        "swaggerCssUrl": "https://cdn.bootcdn.net/ajax/libs/swagger-ui/5.17.12/swagger-ui.css"
    }
)
```

保存，刷新浏览器即可

# 4、更新邮箱后，仍然带有旧的数据
## 问题现象

使用 PUT 接口实现用户局部信息更新，在 ApiPost 的请求 Body 里修改 JSON 中 `email` 的值并发送请求：

- ApiPost 编辑页面明明填写了新邮箱，但是接口返回、数据库最终保存的邮箱，始终是一串带有问题的数据（新邮箱+旧邮箱数字组合）
- 重启 uvicorn 后端服务后，异常现象依旧存在。

## 排查过程

1. 在 service 更新函数添加日志，打印后端真实接收的更新字典、更新前后数据库对象的值；
2. 发现关键线索：后端日志打印拿到的 `email`，并不是 ApiPost 编辑框输入的新值，而是上一次请求的旧邮箱；
3. 新建一条全新请求，重新配置地址、请求体，后端正常接收新邮箱，更新结果符合预期

## 根本原因

ApiPost 的请求缓存 / 历史请求体残留问题：**编辑面板上展示的 JSON 内容 ≠ 它实际发给后端的请求内容**。 界面上你修改好了新参数，但 ApiPost 底层发送的仍然是上一次的旧请求数据，后端拿到旧值，就把数据库更新成旧邮箱。

## 解决方法

1. 调试铁则：**以后端控制台打印的入参日志，作为真实收到请求的判断标准，不要只相信 ApiPost 界面**；
2. 直接新建一条全新请求，重新配置地址、请求体，避免旧缓存干扰；


## 补充
**为什么是邮箱这一行有问题，而 name 这里没问题呢**

✅ 一句话： 不是 ApiPost 只缓存 email、不缓存 name。**name 新旧内容相同，掩盖了缓存 bug；email 前后值不一样，所以缓存问题一眼就暴露出来了。**


举个例子：

- 旧报文：`{"name":"李四","email":"123456@xx.com"}`
- 你界面改成：`{"name":"李四","email":"new@qq.com"}`
- 但实际发出还是旧报文
    - name：都是李四 → 返回看着没问题，你察觉不到
    - email：旧值和你界面写的新值不一样 → 明显看出不对劲


# 5、前端页面头像上传成功但页面无法显示

来自 11. 开发用户修改个人信息功能

## 现象

头像文件可以正常保存到后端 `uploads` 文件夹，数据库 avatar 字段也存入了路径；但是前端页面头像不展示。

## 排查步骤

1. 先用调试工具（Bruno）调用上传接口，拿到接口返回的完整响应 JSON，重点看返回的 `url` 字段
2. 对比后端静态挂载规则：`app.mount("/uploads", ...)`
    - 挂载规则约定：访问图片必须以 `/uploads/` 开头
3. 核对返回的 url：发现返回值是 `/upload/xxx.jpg`（只有 upload，**少末尾 s**，路径前缀不匹配挂载路由）

## 根因

上传接口 files.py 里面拼接图片地址代码写错：

```python
# 错误
url=f"/upload/{disk_name}"
# 正确
url=f"/uploads/{disk_name}"
```

# 6、RuntimeError

## 报错结论

`RuntimeError: 'cryptography' package is required for sha256_password or caching_sha2_password auth methods` 

👉 **你的 MySQL 用户用的是 `caching_sha2_password` 加密方式，pymysql 连接这种认证方式，必须额外装 cryptography 包**

## 原因拆解

MySQL8.0 默认账号密码插件是 `caching_sha2_password`，不是老的 `mysql_native_password`。 pymysql 原生不支持这个加密的密码握手，需要 `cryptography` 库做 RSA 加密，缺少它就启动直接报错。 报错触发点：

```
Base.metadata.create_all(bind=engine)
```

启动 main.py 的时候，一尝试连接数据库、建表，立刻连库失败。

## 解决方案

虚拟环境里面直接安装：

```bash
pip install cryptography
```

装完，重新执行

```bash
uvicorn app.main:app --reload
```

大概率直接解决。
