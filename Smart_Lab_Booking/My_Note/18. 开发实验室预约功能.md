新建 models/reservation.py：
```python
from sqlalchemy import ForeignKey, String
from sqlalchemy.orm import Mapped, mapped_column, relationship

from app.database import Base
from app.models.equipment import Equipment
from app.models.lab import Lab
from app.models.user import User

class Reservation(Base):
    __tablename__ = "reservations"
    __table_args__ = {"comment": "预约信息"}

    user_id: Mapped[int] = mapped_column(
        ForeignKey("users.id"), comment="预约人", nullable=False
    )
    lab_id: Mapped[int] = mapped_column(
        ForeignKey("labs.id"), comment="实验室", nullable=False
    )
    equipment_id: Mapped[int] = mapped_column(
        ForeignKey("equipments.id"), comment="设备，空表示预约实验室", nullable=True
    )
    date: Mapped[str] = mapped_column(String(20), comment="预约日期", nullable=False)
    start_time: Mapped[str] = mapped_column(
        String(20), comment="开始时间", nullable=False
    )
    end_time: Mapped[str] = mapped_column(
        String(20), comment="结束时间", nullable=False
    )
    remark: Mapped[str] = mapped_column(String(255), comment="备注", nullable=True)
    status: Mapped[int] = mapped_column(
        comment="预约状态 0待审核，1已通过，2已拒绝，3已取消", default=0
    )

    user: Mapped[User] = relationship()
    lab: Mapped[Lab] = relationship()
    equipment: Mapped[Equipment] = relationship()
```

### reservation_service

新建 `services/reservation_service.py`：

```python
from sqlalchemy.orm import Session
from datetime import datetime

from app.common.exceptions import BusinessException
from app.models.equipment import Equipment
from app.models.lab import Lab
from app.models.reservation import Reservation
from app.models.user import User
from app.schemas.reservation import ReservationCreateRequest

def create_reservation(db: Session, current_user: User, data: ReservationCreateRequest):
    """创建预约记录"""
    now = datetime.now()
    current_date = now.strftime("%Y-%m-%d")
    current_time = now.strftime("%H:%M")
    if data.date < current_date:
        raise BusinessException(message="预约日期不能小于当前的日期")
    if data.end_time < data.start_time:
        raise BusinessException(message="预约的结束时间不能小于开始时间")
    if data.date == current_date and data.start_time < current_time:
        raise BusinessException(message="预约开始时间不能小于当前的时间")
    lab = db.query(Lab).filter(Lab.id == data.lab_id).first()
    if not lab:
        raise BusinessException(message="实验室不存在")
    if lab.status != 1:
        raise BusinessException(message="实验室已关闭")
    if lab.open_time and data.start_time < lab.open_time:
        raise BusinessException(message="预约时间不能早于实验室的开放时间")
    if lab.close_time and data.end_time > lab.close_time:
        raise BusinessException(message="预约时间不能晚于实验室的关闭时间")

    # equipment_id 不为空 则表示这次是预约的实验室设备
    if data.equipment_id:
        equipment = (
            db.query(Equipment).filter(Equipment.id == data.equipment_id).first()
        )
        if not equipment:
            raise BusinessException(message="实验室设备不存在")
        if equipment.status != 1:
            raise BusinessException(message="实验室设备正在维修")

    # 实验室或者设备是否是可预约的状态
    query = db.query(Reservation).filter(
        Reservation.lab_id == data.lab_id,
        Reservation.date == data.date,
        Reservation.status.in_([0, 1]),  # 0表示待审核  1已通过
        Reservation.start_time < data.end_time,
        Reservation.end_time > data.start_time,
    )
    if data.equipment_id:
        query = query.filter(
            Reservation.equipment_id == data.equipment_id
        )  # 预约实验室设备
    else:
        query = query.filter(Reservation.equipment_id.is_(None))  # 只预约实验室
    res = query.first()
    if res:
        raise BusinessException(message="该时段已预约")

    resvervation_model = Reservation(
        user_id=current_user.id,
        lab_id=data.lab_id,
        equipment_id=data.equipment_id,
        date=data.date,
        start_time=data.start_time,
        end_time=data.end_time,
        remark=data.remark,
        status=0,
    )
    db.add(resvervation_model)
    db.commit()
```

冲突规则：待审核、已通过算占用。只约实验室和约设备分开判断，互不影响。

# 解析

## 1、Reservation 模型
### sort_order再理解

在database.py里面修改，让主键的sort_order赋值-1
第一次记录于 05. 开发后端登录api接口
sort_order 越小越靠前：id 用 -1 固定第一列，业务字段默认是 0，时间字段用 1、2 留在最后

✅**需求情景**

我们在 `database.py` 的公共基类 `Base` 里统一定义了公共字段：`id`（主键）、`create_time`、`update_time`

SQLAlchemy 自动生成表结构、或者某些工具（自动生成 CRUD、查看表结构、序列化展示字段）的时候，**字段顺序默认是按代码书写顺序来的**

我们想要固定顺序：**id 主键永远放在表的第一列，创建时间、更新时间放在末尾，中间放业务字段（name、lab_id 这类）**，所以用 `sort_order` 控制

<br>

📝知识点补充
1. sort_order 属于 SQLAlchemy ORM 参数，**不是 MySQL 数据库属性**，不会修改数据库表真实字段顺序。Navicat 查看表不受这个配置影响。
2. 作用范围：只影响 ORM 内部遍历字段、自动生成文档 / 表单、代码生成工具的字段排序


## 2、Schema

### user_id再理解
**问题情景**
为什么`models/reservation.py`这里写了`user_id`,而这里的Schema不用传`user_id`?
>Reservation 预约模型数据库必须存在 user_id 外键，记录预约人；
>但是新增预约的入参 DTO `ReservationCreateRequest` 不包含 user_id

<br>

**核心逻辑**
1. 数据库 / ORM 模型：`user_id` 是必填外键，必须存在，用来关联用户。
2. 前端不传递 user_id： 如果前端可以传入 user_id，用户可以随意修改 id，冒充其他用户创建预约，产生安全漏洞。
3. **user_id 的来源**：后端鉴权依赖 `get_current_user`，从 token 读取当前登录用户，自动拿到 `current_user.id` 赋值入库
<br>


**一句话浓缩**
>user_id 是登录人身份，后端从 token 自动获取，防止冒充，所以前端不需要传

### 主键id再理解

也就是主键 id 在 Schema 里的处理规则

**问题情景**
User、Lab 的 Response 都包含 id，
但是 CreateRequest、UpdateRequest 都没有 id
需要理解 id 的来源与传递规则


**规则**
1. Response（出参 DTO）带 id：后端查询出数据后返回给前端，前端拿到 id 用来做编辑、删除、查看详情。
2. CreateRequest（新增入参）不带 id：id 是自增主键，由数据库自动生成，不允许前端自己指定 id。
3. UpdateRequest（修改入参）不带 id：目标记录的 id 放在路由路径参数（`/{id}`），不在请求体传递，防止 id 冲突。

**区分对比（重点）**
- 主键 id：前端**只读**，新增后端自动生成，更新从 url 拿
- user_id（预约人身份）：后端从 token 读取，安全层面禁止前端传入

<br>

**一句话浓缩** 
>id 是主键，前端只读取不负责传入；
新增数据库自增生成 id
更新通过 url 路径传递 id

## 3、service

**结构骨架**
1. 获取当下的时间
2. 错误或异常判断/校验
	1. 预约时间不能自身冲突
	2. 校验前端传过来的lab_id
	3. 预约时间不能和实验室时间冲突
	4. 实验设备是否存在
	5. 预约时间段是否被占用
3. 新增预约记录


### 预约时段冲突校验
（这里可以再回去看 `16. 开发实验室设备管理功能 解析 第2点 同名校验 更新校验`）

✅需求情景 新增预约的时候，要判断同一个实验室（或者同一个设备）在用户选的时间段里，有没有已经存在有效的预约。 有效预约：待审核 0、已通过 1；已经拒绝、取消的预约不参与冲突判断。 分两种预约模式：

1. 指定 equipment_id：预约这个实验室下面某一台设备
2. 不传 equipment_id：直接预约整个实验室（不绑定设备） 如果查到重叠预约，直接抛出异常，禁止重复预约


📝**代码解析**

```python
    # 实验室或者设备是否可预约的状态
    query = db.query(Reservation).filter(
        Reservation.lab_id == data.lab_id,
        Reservation.date == data.date,
        Reservation.status.in_([0, 1]),  # 0表示待审核  1已通过
        Reservation.start_time < data.end_time,
        Reservation.end_time > data.start_time,
    )
```

**前三条在进行匹配，后面两条在进行校验**
1. `Reservation.lab_id == data.lab_id`：锁定同一个实验室
2. `Reservation.date == data.date`：只看同一天的预约（日期是单独字段，时分是 start_time、end_time）
3. `Reservation.status.in_([0, 1])`：只拿【待审核、已通过】的预约，已拒绝、已取消（2、3）不用校验冲突
4. `Reservation.start_time < data.end_time` 和 `Reservation.end_time > data.start_time`：**时间段重叠判断核心条件** 
>现有预约的开始时间 ＜ 用户预约的结束时间 
>现有预约的结束时间 ＞ 用户预约的开始时间 
>满足这两条 = 两个时间段发生重叠
>
>	可以画时间轴，小的在左边，大的在右边


```python
    if data.equipment_id:
        query = query.filter(
            Reservation.equipment_id == data.equipment_id
        )  # 预约实验室设备
    else:
        query = query.filter(Reservation.equipment_id.is_(None))  # 只预约实验室
    res = query.first()
    if res:
        raise BusinessException(message="该时段已被别人预约")
```

1. if 分支：用户传了 equipment_id → 校验【该实验室下这台设备】的时段冲突
2. else 分支：equipment_id 为空 → 校验【整个实验室】的预约，只匹配预约实验室（equipment_id is null）的记录
3. `query.first()`：找到任意一条冲突记录就够了
4. if res：查到冲突，抛出业务异常，提示该时段已预约

### db.refresh()再理解

**问题情景**
这里预约新增 service结尾部分，add+commit 之后没有写 db.refresh ()
对比之前设备新增接口带 refresh
>什么时候需要 db.refresh ()

<br>

**原理**
db.refresh (对象)：执行一次 SELECT，把数据库最新数据（自增主键 id 等）同步到 Python 的 ORM 实例。 
commit 本身不会自动把数据库生成的 id 回填到本地对象。

<br>

**使用规则**

1. 需要 refresh：commit 之后，还要使用这个 ORM 实例（序列化 Response、拿 id 继续业务操作）
2. 不需要 refresh：commit 之后，函数流程结束，不再读取、使用这个实例，不需要拿到自增 id

<br>

**本案例原因**
预约提交完成后没有后续代码读取 resvervation_model，不需要序列化返回，因此可以省略 refresh。

<br>

**一句话浓缩**
refresh 按需使用，目的是回填数据库生成字段；
提交后不再使用该对象，就不用写 refresh。


### 关键字后面加下划线
SQLAlchemy 常用查询运算符速查表

> 核心前提：`== > < >= <= !=` 可以直接写，已经被ORM重载；
>  `is / in / and / or / not` 是Python原生关键字，**不能直接用**，要用ORM提供的带下划线后缀版本

|写法|翻译成SQL|说明|错误写法|
|---|---|---|---|
|col.is_(None)|`IS NULL`|判断为空|`col == None`|
|col.is_not(None)|`IS NOT NULL`|判断非空|`col != None`|
|col.in_([1,2,3])|`IN (1,2,3)`|在集合内|`col in [1,2,3]`|
|col.not_in([1,2,3])|`NOT IN (1,2,3)`|不在集合内|`col not in [1,2,3]`|
|and_(条件1,条件2)|`条件1 AND 条件2`|多个条件同时满足|`条件1 and 条件2`|
|or_(条件1,条件2)|`条件1 OR 条件2`|满足任意一个|`条件1 or 条件2`|
|not_(条件)|`NOT 条件`|取反|`not 条件`|

**代码示例**
```python
# and_ 多条件同时满足
db.query(User).filter(
    and_(
        User.role == "admin",
        User.status == 1
    )
)

# or_ 满足其一
db.query(User).filter(
    or_(
        User.role == "admin",
        User.role == "teacher"
    )
)

# not_ 取反：不是管理员
db.query(User).filter(
    not_(User.role == "admin")
)

# 组合混用
db.query(User).filter(
    and_(
        User.status == 1,
        or_(
            User.role.in_(["admin", "teacher"]),
            User.phone.is_(None)
        )
    )
)
```

<br>

**总结**
就是相当于用python完成SQL语句的功能，有些关键字要加下划线


✅ 什么时候要带下划线（核心原因：和 Python 原生关键字冲突，没法直接重载）
`is_`、`in_`、`and_`、`or_`、`not_`
- `is、in、and、or、not` 是 Python 保留关键字，你直接写，Python 会当场执行布尔判断，不会交给 SQLAlchemy 生成 SQL。
- 所以库里面改名，末尾加下划线区分。

<br>

✅ 不用下划线，可以直接写的（运算符被 ORM 重载了）
`==`、`>`、`<`、`>=`、`<=`、`!=`

<br>

📌 补充
还有一些是方法，不是因为关键字冲突：
- `like()`、`between()` 这类，本身就不是 Python 关键字，**不加下划线**
