```python
from app.models.user import User
from app.schemas.user import UserResponse, UserUpdateRequest
from sqlalchemy.orm import Session

def get_user_info(user: User) -> UserResponse:
    return UserResponse.model_validate(user)

def update_user_info(db: Session, user: User, data: UserUpdateRequest):
    user_dict = data.model_dump(exclude_none=True)  # pydatic对象转换成字典
    for field, value in user_dict.items():
        setattr(user, field, value)
    db.commit()
    db.refresh(user)
    return UserResponse.model_validate(user)
```

**(1)需求场景（什么时候来 schemas 新建模型）**

记住这个判断标准：

> 只要接口**需要约定入参格式 / 约定返回给前端的出参格式**，就来 schemas 新建对应的 Pydantic 模型。

细分 3 种触发场景：

1. **接收前端提交的数据（请求体）** 比如登录、注册、修改个人信息：前端 POST/PUT 发 JSON，你需要规定有哪些字段、字段是什么类型、哪些必填。对应 `LoginRequest`、`RegisterRequest`、`UserUpdateRequest` 这类 `xxxRequest`。
2. **返回数据给前端（响应体格式化）** 接口查库之后，不能直接把数据库的 model 对象丢出去：
    - 数据库模型字段很多，有时候不想全部返回（比如密码绝对不能返回）
    - 想固定返回字段、固定类型，前后端对齐
    - 自动在 Swagger 文档展示返回结构 对应 `UserResponse`、`LoginResponse`、`FileResponse` 这类 `xxxResponse`。
3. **嵌套返回结构** 像登录返回：`{token:xxx, user:{用户对象}}`，里面 user 复用已经写好的 `UserResponse`，就需要在 `LoginResponse` 里直接引入别的 Schema，就是你 auth.py 里的写法。

> 一句话记忆： 
> Request = 前端传给后端 ✅ 
> Response = 后端返回给前端 ✅

<br>

**（2）区分容易混淆的点**

- SQLAlchemy `models`：**映射数据库表**，代表数据库里有哪些列（包含密码、各种数据库字段）
- Pydantic `schemas`：**接口传输契约**，控制前后端之间收发哪些字段、校验规则（过滤敏感字段，比如密码不会放到 UserResponse）

<br>

### model_validate 与 model_dump 转换方法
（1）是什么：Pydantic v2 提供的两个**实例转换方法**
（2）需求情景：
我们有两种对象：
ORM 模型（models 里面的 User）：映射数据库表，里面包含数据库全部字段（例如 password 敏感字段）
Pydantic Schema（UserResponse）：接口对外输出的契约，规定前端能拿到哪些字段

需要把查出来的ORM对象安全转成接口返回结构：
model_validate 就是这座桥梁，实现 ORM → Schema 的转换。
> 注意：使用 model_validate 读取ORM属性，Schema必须配置 `model_config = ConfigDict(from_attributes=True)`

（3）二者区分
- `model_validate(外部对象)`：外部对象（ORM） → Schema 实例
  作用：读外部对象的数据，创建Schema
- `model_dump()`：Schema 实例 → Python 字典
  作用：把Schema拆开，转为普通字典
>因为Schema 对象不方便循环遍历；转成字典后，可以拿到键值对，批量动态给 ORM 对象赋值，实现局部更新


### 局部更新
（4）**为什么要局部更新（这才是用`model_dump()`的根本原因）**
 
 方案 1：
 **全量提交（不做局部更新）** 修改个人资料时，前端必须把用户**所有信息全部传上来**：name、email、phone、avatar 一个都不能少。 哪怕用户只改头像，也要把姓名、邮箱、手机号原样再发一遍。 后端收到之后，直接覆盖整条记录。
缺点非常明显：
1. 麻烦：前端表单每次提交，都要先去拉取一遍用户全部信息回填，少一个字段就会把数据库里原来的值清空（变成 null）。
2. 容易出 bug：如果拉取数据失败、漏传某个字段，数据库里原本存在的数据直接丢了。
3. 用户体验不好，逻辑笨重。

方案 2：
**局部更新（我们现在的方案 + exclude_none=True）** 用户改哪个，前端就只传哪个字段。 比如只换头像 → 请求里只带 `avatar` 这一个字段。 后端拿到 `UserUpdateRequest`，用 `model_dump(exclude_none=True)`，**自动过滤掉所有没传、值为 None 的字段**。 循环只更新传过来的字段，没传的字段，数据库保持原样不动。

✅ 一句话总结局部更新的目的： **用户只提交需要修改的字段，未提交的字段保留数据库原有数据，不会被清空**


### Pydantic 数据转换两条链路
**前情提要**
 - 数据库**不接收字典**。
 - SQLAlchemy ORM 是靠 ORM 对象（`user = User(...)`）和数据库打交道，不是字典。
 - 存入数据库不需要把 schema 转字典


 **链路 A（查询，后端返回给前端，用 model_validate）**
数据库 → SQLAlchemy ORM 对象 → `model_validate()` → Response Schema 实例

> 这里很多时候**甚至不需要 model_dump**！ 因为你的统一响应工具 `Response.success()` 内部会自动处理，把 Schema 转成 json 返回前端。 
> 
> 👉 对应：查用户信息 `get_user_info`

**链路 B（前端提交，后端更新数据库，用 model_dump）**

前端 json → Request Schema 实例（UserUpdateRequest） → `model_dump()` → 字典 → 循环给 ORM 对象赋值 → commit 入库 

>👉 对应：修改个人信息 `update_user_info`

**一句话区分记忆**
`model_validate`：ORM → Schema（查完数据，包装对外输出）
`model_dump`：Schema → 字典（拿到前端提交的数据，拆出来方便批量处理）


### 什么时候写返回类型注解
 像这种`-> XxxResponse`，就是返回类型注解
**需求场景**
FastAPI 里类型注解 `-> 模型类`，主要服务两件事：
1. 给人看：一眼看懂这个接口 / 函数最终返回什么结构，提升代码可读性
2. 给 Swagger 接口文档识别：自动识别响应模型，文档里展示返回字段

<br>

✅ **建议标注（优先写上）**
1. **Service 层函数（强烈建议写）** service 是数据转换的地方，专门把 ORM 对象转成 Response Schema。

```python
def get_user_info(user: User) -> UserResponse:
    return UserResponse.model_validate(user)
```

理由：service 是可复用的工具函数，加注解，别人调用的时候一眼知道返回什么；同时给 IDE 提示

❌ **可以不标注的情况**
1. 简单函数、临时辅助函数，逻辑很短，一眼就能看懂返回值
2. 函数返回类型不固定：有时返回 A、有时返回别的B，没有唯一固定返回类型，没法标注
3. 接口使用统一返回包装 `Response.success()`： 接口外层返回的是包装对象，不是直接返回 Schema。这种情况下返回类型注解**不能驱动 Swagger 生成文档**；就算写上，作用仅仅是给自己阅读提示。

```python
def get_user_info(current_user: User = Depends(get_current_user)):
    """获取当前登录用户信息"""
    return Response.success(data=user_service.get_user_info(current_user))

@router.put("/update")
def update_user_info(
    data: UserUpdateRequest,
    current_user: User = Depends(get_current_user),
    db: Session = Depends(get_db),
):
    """更新当前用户信息"""
    res = user_service.update_user_info(db, current_user, data)
    return Response.success(data=res)
```

### 请求方法语义/REST 方法（了解）
- `GET`：只需要知道**查询，获取信息**的时候用
- `PUT`：**更新资源**的时候用

补充：（这里可以不看）
- `PUT`：**完整替换资源**。要求你把这个资源的所有字段全部传过来，用新的一整套数据覆盖原来整条记录，少传的字段视为删掉。
- `PATCH`：**局部更新资源**。只传你想要修改的字段，没传的字段保持原样
>**一个项目内部要统一**：
>要么统一用 PUT 做更新，要么用 PATCH，最怕混用。
  这个项目选择 PUT，只是大家提前说好的规则
