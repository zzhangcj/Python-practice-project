```python
from sqlalchemy.orm import Session

from app.common.exceptions import BusinessException
from app.models.user import User
from app.schemas.auth import LoginRequest, LoginResponse, RegisterRequest
from app.schemas.user import UserResponse
from app.utils.jwt import create_access_token
from app.utils.password import hash_password, verify_password

def login(db: Session, data: LoginRequest) -> LoginResponse:
    user = db.query(User).filter(User.username == data.username).first()

    if not user or not verify_password(data.password, user.password):
        raise BusinessException(message="账号或密码错误")

    if user.status != 1:
        raise BusinessException(message="账号被禁用")

    token = create_access_token(user.id)
    return LoginResponse(
        token=token,
        user=UserResponse.model_validate(user),
    )

def register(db: Session, data: RegisterRequest) -> None:
    exists = db.query(User).filter(User.username == data.username).first()
    if exists:
        raise BusinessException(message="账号已存在")

    user = User(
        username=data.username,
        password=hash_password(data.password),
        name=data.name or data.username,
        role="student",
        status=1,
    )
    db.add(user)
    db.commit()
    db.refresh(user)
```

# 解析

## 1、优化建议

- 使用 `router-link`替换a标签, 同时herf改成to
>原生 a 标签会触发**页面整页刷新**；
>router-link 是 Vue 路由组件，做 SPA 单页跳转，无刷新、速度快，不会丢失前端状态，符合 Vue 项目路由规范
>
>	效果就是，在登录页面点击注册，注册页面切回登录，不会再刷新页面，性能好

- 登录函数改成 `try...finally` 包裹、使用 `await router.push`
在Login.vue里面改写：
```vue
const login = async () => {
  loadingValue.value = true
  try {
    const res = await loginApi(form)
    if (res.code === 200) {
      saveLoginData(res.data)
      ElMessage.success('登录成功')
      await router.push('/manager/home')
    }
  } finally {
    loadingValue.value = false
  }
}
```
> `finally` 保证**无论登录成功还是失败**，loading 加载状态一定会关闭，避免按钮一直转圈卡死；
>`await router.push()` 等待路由跳转完成，逻辑顺序更可控，防止跳转还没完成就执行后续代码。

✅ 需求场景 

原先登录页没有前端表单校验：账号、密码为空的时候，点击登录会直接把空数据发给后端，后端返回账号密码错误的提示，白白发起一次无效请求，用户体验不好。 所以我们加上 Element Plus 表单校验，在**前端本地先做检查**，不满足条件就不调用登录接口。

📝代码做了什么

1. 给 el-form 绑定 ref、校验规则 rules；每个 el-form-item 加上 prop，和校验规则里的字段对应；同时设置 label-width 和宽度样式，适配登录页面布局。
2. 定义校验规则 rules：username 和 password 都是必填项，失去焦点的时候触发校验，提示用户输入内容。
3. 在登录点击事件里，先执行 `formRef.value.validate()` 做表单校验：
    - 如果校验不通过（为空），直接终止代码，**不会发送请求给后端**；
    - 校验通过，才继续发起登录 api 请求。

一句话概括：在请求后端之前，前端先拦截空表单，提前提示，减少无效请求。

## 3、实现用户注册后端接口

✅ 需求场景 

原来的后端代码把登录的业务判断逻辑（查用户、校验密码、生成 token 等）直接写在了 API 路由接口层里面。
这种写法不规范：接口层只应该负责接收参数、调用业务、返回统一响应，不该堆大量业务判断；
而且后续新增注册功能时，如果业务逻辑都堆在 api 层，代码会杂乱、不方便复用和维护。

所以这次改动做两件事：

1. **解耦分层，规范代码结构**：把登录的业务逻辑抽离出来，放到 `services/auth_service.py`（服务层）；API 层只保留很薄的代码：接收前端参数、拿到数据库会话、调用 service 里面的方法、返回统一格式响应。做到路由层和业务逻辑分离。
2. **新增注册能力**：增加注册的业务逻辑与注册接口。注册逻辑写在 service 里：先判断用户名是否已经存在，存在就抛出业务异常；不存在则对密码哈希加密，新建用户入库。API 层新增 `/auth/register` 路由，对外提供注册接口，配合前端注册页面完成注册功能。


📝重要知识点

1、**后端分层思想**：路由层（API） 和 Service 服务层分离（最核心）
原来：查询数据库、判断账号密码、校验状态、生成token全部写在接口函数
`@router.post`
改动后：
- **API层（路由）：只做“搬运”** 职责：接收请求参数、拿到db会话、调用service函数、包装返回统一响应。**不写业务判断、不写数据库查询**。 它就相当于快递前台，只负责收包裹、转交后台处理、最后把结果打包返回，不处理里面的业务审核。
- **Service层：存放业务逻辑** 所有业务规则：查重、密码校验、账号禁用判断、密码加密、新增用户入库，全部放这里

> 一句话：路由层负责http交互，service层封装业务逻辑

2、**`db.commit()` 和 `db.refresh(user)` 这一对（新增注册逻辑重点）**

```python
db.add(user)      # 只是把对象加到sqlalchemy的会话缓存，还没真正提交到数据库
db.commit()       # ✅真正提交事务，数据写入mysql
db.refresh(user)  # 去数据库刷新这个user对象，拿到数据库自动生成的id、创建时间等字段
```

坑点：不加`refresh`，commit之后user对象里面部分数据库自生成字段可能拿不到。

3、**密码哈希 `hash_password`**
这里前面章节解析过了，这里可以复习一下

注册的时候**绝对不能明文存密码**！
前端传明文密码 → service调用hash_password加密 → 存加密后的字符串到数据库。 登录的时候，再用`verify_password(前端输入密码, 数据库里面加密后的密码)`对比。

> 知识点：不可逆哈希，不能反向解密出原始密码，就算数据库泄露，别人看不到真实密码，是Web安全基础规范

**4、`RegisterRequest` 这个Pydantic Schema**

```
class RegisterRequest(BaseModel):
    username: str
    password: str
    name: str | None = None
```

作用：自动接收、校验前端传过来的注册参数。
- 自动校验类型：username必须是字符串
- `name: str | None = None`：代表这个参数**可选**，前端可以不传name
- FastAPI自动返回参数错误提示，不用自己写if判断参数有没有传

**5、SQLAlchemy查询判断：注册查重**

```python
exists = db.query(User).filter(User.username == data.username).first()
if exists:
    raise BusinessException(message="账号已存在")
```

知识点：注册必须先查重，用户名唯一，是业务约束；这是注册接口必备逻辑

**6、返回值设计：register函数返回 `None`**

```
def register(db: Session, data: RegisterRequest) -> None:
```

注册成功之后，不需要返回token、用户信息（注册≠登录），只需要告诉前端“注册成功”，所以service不用返回数据，由api层固定返回成功提示。 对比login：登录成功要返回token和用户信息，所以返回`LoginResponse`。


**✅7、 区分容易混淆的点**

- 登录：校验账号密码 + 生成JWT令牌
- 注册：查重 + 密码哈希 + 新增用户入库，**不生成token**（注册完一般需要用户自己去登录页面登录）

✅**需求场景**

- 改动之前的注册页面只有布局和输入框，**没有任何前端校验，也不能和后端交互**。

const loadingValue = ref(false)
const formRef = ref()

const validatePass = (rule, value, callback) => {
  if (value === '') {
    callback(new Error('请确认密码'))
  } else {
    if (value !== form.password) {

    } else {

const rules = {
  username: [{ required: true, message: '请输入账号', trigger: 'blur' }],
  password: [{ required: true, message: '请输入密码', trigger: 'blur' }],
  confirmPassword: [{ validator: validatePass, trigger: 'blur' }]
}

const register = async () => {
  const valid = await formRef.value.validate().catch(() => false)
  if (!valid) return

  } finally {

📝 **重要知识点**

1. **Element Plus 表单校验配套属性**`ref` 获取表单实例、`:rules` 绑定校验规则、`prop` 绑定字段名，三者配合才能开启表单校验，缺一不可。
2. **自定义校验器 validator** 注册有独特业务要求：两次密码必须保持一致，基础的必填规则实现不了，所以写自定义校验函数 `validatePass`。校验不匹配时返回提示，匹配才放行。
3. **表单校验前置拦截** 点击注册时先执行 `formRef.value.validate()` 校验，校验失败直接终止代码，**不会请求后端**，减少无效网络请求。
4. **loading 状态 + try finally**`loadingValue` 控制按钮转圈效果；`finally` 代码块不管接口成功还是报错，都会执行，保证加载状态一定会关闭，避免按钮一直卡住转圈。
5. **调用封装好的接口函数 registerApi** 复用我们统一封装的 axios 请求实例（request.js），自动带上拦截器，统一处理后端返回的 code、报错提示。
6. **路由跳转 router.push** 注册成功后，跳转到登录页面，引导用户去登录；这里是 Vue 单页无刷新跳转。
7. 区分登录、注册校验差异 登录只需要简单必填校验；注册额外增加 “密码二次确认” 的自定义校验规则。

**一句话总结**
原来注册页只是静态页面；改动后增加表单校验（含两次密码比对的自定义校验）、对接后端注册接口，增加加载反馈，注册成功自动跳转登录页，实现完整注册交互。
