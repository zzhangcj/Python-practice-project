## 1. 现象

```
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

执行后长时间没有就绪，`/` 接口打不开。MySQL 是通的，`.env` 也没写错，重装依赖也没用。

## 2. 根因：启动时在下载向量模型

后端启动会预热知识库，构造 `BAAI/bge-small-zh-v1.5` 向量模型，第一次要从 [huggingface.co](http://huggingface.co/) 下载整套文件（约 180MB）。国内直连经常超时重试，看起来就是"卡死"；而且预热完成前服务不会就绪。

```
main.py lifespan → kb_service.warmup()
  → SentenceTransformerEmbeddingFunction("BAAI/bge-small-zh-v1.5")
  → huggingface.co 下载模型（约 180MB）
```

## 3. 解法：换国内镜像

启动进程**之前**设置环境变量：
```powershell
$env:HF_ENDPOINT="https://hf-mirror.com"
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

实测：空缓存全量下载 13 个文件 183MB，约 30 秒；之后走本地缓存（`~/.cache/huggingface`），不再下载。

两个注意点：
```
1. 写进 backend/.env 没用。
   pydantic 只把 .env 喂给 Settings，不会进系统环境变量；
   huggingface_hub 在 import 时就读取 HF_ENDPOINT，进程启动后再设无效。

2. VSCode 按 F5 调试的，在 .vscode/launch.json 加：
   "env": { "HF_ENDPOINT": "https://hf-mirror.com" }
```

模型下好之后，如果还想跳过每次的联网检查，可以再加 `HF_HUB_OFFLINE=1`（只读本地缓存）。

## 4. 部署侧不用动

`docker-compose.yml` 已经配好 `HF_ENDPOINT=https://hf-mirror.com` 和 `model-cache` 卷，容器启动自动走镜像。
