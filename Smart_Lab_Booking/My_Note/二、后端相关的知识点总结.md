# 1、写第一个FastAPI接口 并测试
（来自  04. 搭建后端FastAPI工程）

```python
from fastapi import FastAPI

app = FastAPI()

@app.get("/")
def root():
    return {"message": "Hello FastAPI"}
```

启动测试

```bash
uvicorn app.main:app --reload --port 8000 --host 127.0.0.1
```

---

**第2行：`app = FastAPI()`**

```python
app = FastAPI()
```

- 调用这个类，**实例化，创建一个应用对象**

**第3行：`@app.get("/")` 装饰器（重点）**

```python
@app.get("/")
```

`@xxx` 是 Python 的**装饰器语法**

1. `app.get` 是 app 对象提供的一个装饰器方法
2. `get`：代表 HTTP 请求方法 —— `GET` 请求（浏览器直接在地址栏访问就是GET）
3. `"/"`：接口的路由路径，也就是根路径，对应地址 `[http://127.0.0.1:8000/](http://127.0.0.1:8000/)`

✅ 装饰器做的事情： 把下面这个 `root` 函数，**注册绑定到 app 的路由表里** 告诉app：

> 当收到 GET 请求、访问路径 `/` 的时候，就执行下面这个函数

> 补充：还有 `@app.post()`、`@app.put()`、`@app.delete()` 对应其他请求方式

**第4~5行：接口处理函数**

```python
def root():
    return {"message": "Hello FastAPI"}
```

- `root`：只是函数名字，可以随便取（比如 index、home），没有强制要求
- 这个函数就是**接口的视图函数 / 处理函数**，请求来了就执行它
- `return {"message": "Hello FastAPI"}` 返回一个Python字典； 
- ✨ FastAPI自动做了两件事：
    1. 把字典自动转换成 **JSON 字符串**
    2. 自动设置响应头 `Content-Type: application/json`

## 完整执行流程
**（请求来了之后发生了什么）**

1. 启动服务：`uvicorn app.main:app --reload`，uvicorn 是ASGI服务器，把app跑起来，监听8000端口
2. 浏览器访问 `[http://127.0.0.1:8000/](http://127.0.0.1:8000/)` → 发送一个 GET 请求，路径 `/`
3. uvicorn把请求交给 `app` 这个FastAPI实例
4. app去自己的路由注册表匹配：找到 `@app.get("/")` 绑定的 `root` 函数
5. 执行 `root()`，拿到返回的字典
6. FastAPI自动序列化字典为JSON，返回给浏览器
7. 浏览器收到JSON展示出来

## Pydantic + BaseModel

FastAPI 本身不是从零写的，它是套壳工具： 底层依托两个核心东西：
-  **Starlette：ASGI Web 框架** —— 负责网络通信，接收浏览器 / 前端发过来的 HTTP 请求、最后把响应发回去（相当于网络搬运工）
-  **Pydantic：数据校验库** —— 负责校验请求参数、格式化输出数据（数据检查员）
>`BaseModel` 是 Pydantic 库里面的**基础父类**。 
>只要你的类继承 `BaseModel`，它就自动获得：**数据校验、类型转换、序列化（转 JSON）** 的能力。
> Pydantic 就是做「数据模型、校验」的库，`BaseModel` 是它最核心的起点


### 底层&开发知识点补充
1. 自动打包返回数据给前端
前端只看得懂 JSON 格式的数据。
如果你在接口里 return 字典、列表、或者我们写的 Pydantic 模型对象，FastAPI 会自动帮你把这些 Python 数据，整理成前端能看懂的 JSON，不用我们自己写代码转换。

2. 自动生成接口调试页面

## `__init__.py`
目录下创建`__init__.py`

**为什么这么做？**
>`__init__.py` 是 Python 的**包标识文件**。 只要文件夹里面有 `__init__.py`，这个文件夹就不再只是普通文件夹，变成一个 **Python 包（package）**，可以用 `import` 导入里面的代码。

**总结`__init__.py` 的作用：**
>标记当前文件夹为 Python 包，支持 `import` 导入，保证 `uvicorn app.main:app` 这种导入写法稳定生效，属于 Python 后端项目的规范约定，空文件即可。

`uvicorn app.main:app` 格式为 `包名.模块名:实例对象`，代表导入 `app/main.py` 中名为 `app` 的 FastAPI 实例并启动服务；
依赖`__init__.py`把 app 文件夹识别为 Python 包，才能支持这种导入写法。

**为什么pycharm使用的过程中没这样操作？**
>PyCharm 可手动标记源码根目录，IDE 额外处理导入路径，屏蔽了这个要求；但在终端、uvicorn 等原生 Python 运行环境下，该文件依然是识别 Python 包的标准要求。

关于database.py的代码解析

**绝大多数 FastAPI + SQLAlchemy 2.0 的项目，数据库部分基本都是这套模板**
>固定套路：`create_engine` 创建连接引擎 → `sessionmaker` 生成会话工厂 → `get_db` 作为依赖函数管理会话生命周期 → 定义 `Base` 基础模型类

## database.py

```python
from sqlalchemy.orm import sessionmaker, DeclarativeBase, Mapped, mapped_column
from sqlalchemy import create_engine, DateTime
from app.config import settings
from datetime import datetime

engine = create_engine(settings.DATABASE_URL)
# 数据库session会话的连接工厂
SessionLocal = sessionmaker(bind=engine, autoflush=False)

def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()

class Base(DeclarativeBase):
    id: Mapped[int] = mapped_column(
        primary_key=True, autoincrement=True, comment="主键ID", sort_order=-1
    )
    create_time: Mapped[datetime] = mapped_column(
        DateTime, default=datetime.now, comment="创建时间", sort_order=1
    )
    update_time: Mapped[datetime] = mapped_column(
        DateTime, default=datetime.now, onupdate=datetime.now, comment="更新时间", sort_order=2
    )
````
>Base 类就是所有数据库模型的公共父类，用来统一定义所有表都会拥有的公共字段和数据库配置。

>和FastAPI先关的内容： **依赖注入 Depends**
>`Depends()` 是 FastAPI 内置的依赖注入工具，接收一个函数作为参数

4、
#### 生成器yeild再理解
```python
def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

- 这是**依赖函数**，给 FastAPI 的 Depends 使用
> `Depends()` 是 FastAPI 内置的工具，专门用来做【依赖注入】
>
 使用方式：`Depends(你写好的函数)`，这里就是 `Depends(get_db)`
 >
 逻辑： 当请求进来，走到这个接口的时候，FastAPI 会**自动执行你传给 Depends 的函数（get_db）**，拿到函数 yield 返回的 db 对象，传给接口参数。
>
>比如：def login(db = Depends(get_db))

- `yield`：生成器，先把 db 会话交给接口函数使用
>yield 属于生成器关键字
>生成器常见优势：按需取值，不需要一次性加载全部数据，**节省内存**
>但在 get_db 这个依赖函数里，**使用 yield 不是为了节省内存**，而是利用生成器**暂停、恢复执行**的能力
>
>执行流程：
>1. 创建 db 会话；
>2. 执行 `yield db`：把 db 会话向外传递，**函数在这里暂停，停住不动** → 也就是**「先把 db 交给接口函数使用」**
>3. 接口内部逻辑全部执行完成（正常结束 / 抛出异常都算）
>4. 回到暂停位置，继续往下走，进入 finally，执行 `db.close()`，释放数据库连接。
>
> 关键对比： 
> 如果用 return，return 之后函数直接终止，关闭连接的代码永远无法执行。
> yield 实现了：先给资源，等资源用完，自动收尾释放。
> 
>`finally`：无论接口正常执行还是报错，最后一定会执行 `db.close()`，释放数据库连接，防止连接泄露

5、
```python
class Base(DeclarativeBase):
    id: Mapped[int] = mapped_column(
        primary_key=True, autoincrement=True, comment="主键ID", sort_order=-1
    )
    create_time: Mapped[datetime] = mapped_column(
        DateTime, default=datetime.now, comment="创建时间", sort_order=1
    )
    update_time: Mapped[datetime] = mapped_column(
        DateTime, default=datetime.now, onupdate=datetime.now, comment="更新时间", sort_order=2
    )
```

- 所有模型（User 等）都继承这个 Base，自动带上这三个公共字段
- `sort_order`：控制数据表字段展示顺序，**数值越小，字段越靠前**
    - id 设置 sort_order=-1
    - 我们自己写的业务字段（username、password）没有指定 sort_order，默认值是 0
    - 大小对比：`-1 < 0 < 1 < 2`
    - 需要确保最终顺序：id → username、password → create_time → update_time
    - 如果不设置 sort_order=-1，默认 id 也是 0，那字段顺序就乱了，id 有可能跑到后面去


#### Mapped和mapped_column

✅ `Mapped[类型]`
- 作用：**标记这是数据库表的一个字段，同时声明 Python 侧的类型**
- `Mapped[int]`：
    - 告诉 Python / 类型检查工具：这个变量 `id` 是 `int` 整数类型
    - 告诉 SQLAlchemy：这是一个**映射到数据库的列**，不是普通的类属性
- 对比理解：
    
    ```python
    # 普通变量，只是Python变量，不会生成数据库字段
    name: str
    
    # Mapped包装：这是数据库表字段，会映射到mysql表里的一列
    name: Mapped[str]
    ```

> 简单一句话：`Mapped[]` 是**“标记身份”**：这个属性要同步映射到数据库，附带 Python 类型。

 ✅ `mapped_column(...)`
- 作用：**定义这个数据库列在 MySQL 里的规则、约束、附加配置**
- 里面传的参数，全部是数据库层面的设置：
    - `primary_key=True`：主键
    - `autoincrement=True`：自增
    - `comment="主键ID"`：数据库字段注释
    - `sort_order=-1`：控制生成表时字段先后顺序（前面有解析的）
    - `default=datetime.now`：新增数据时默认值
    - `onupdate=datetime.now`：更新行的时候自动赋值（update_time 专属）

# 5、users.py 和自动建表

models/user.py 是用户表的ORM模型文件，用来映射MySQL里的users表。

**提示**：其中重复性工作，可以直接让ai帮我们写就行
```python
from sqlalchemy.orm import Mapped, mapped_column
from sqlalchemy import String
from app.database import Base

class User(Base):
    __tablename__ = "users"
    __table_args__ = {"comment": "用户信息表"}

    username: Mapped[str] = mapped_column(String(50), comment="账号", nullable=False)
    password: Mapped[str] = mapped_column(String(50), comment="密码", nullable=False)
    name: Mapped[str] = mapped_column(String(50), comment="名称", nullable=False)
    role: Mapped[str] = mapped_column(
        String(50), comment="角色：student-学生，admin-管理员", nullable=False
    )
    email: Mapped[str | None] = mapped_column(String(50), comment="邮箱")
    phone: Mapped[str | None] = mapped_column(String(50), comment="手机号")
    avatar: Mapped[str | None] = mapped_column(String(50), comment="头像")
    status: Mapped[int] = mapped_column(default=1, comment="状态：0-禁用，1-正常")
```

1、先看导入部分： 
```python
from sqlalchemy.orm import Mapped, mapped_column
from sqlalchemy import String
from app.database import Base
```
String 对应 MySQL 的 varchar
从 app.database 导入 Base，Base 是我们之前写的基础模型类，继承它就自动拥有 id、创建时间、更新时间三个公共字段

2、class User (Base) 就是我们的用户模型类： 
- `__tablename__` 指定数据库里的表名叫 users。
- `__table_args__` 给整张表加注释，在 Navicat 里可以看到这个表的说明。

3、下面一行行是表里面的业务字段：
- `nullable=False` 代表这个字段必填，不能是 null。比如账号、密码、姓名、角色都是必填项。
- `str | None` 代表这个字段可以为空，邮箱、手机号、头像不是必填。
- `String(50)` 代表数据库里这个字符串最长 50 个字符。
- `default=1` 是默认值，新增用户时如果不传入 status，自动填 1，代表正常启用。

>字段排序上： 继承过来的 id sort_order=-1 排在最前面；这些业务字段没有设置 sort_order，默认是 0，排在 id 之后、create_time、update_time 之前。

这个文件写完之后，执行建表语句，SQLAlchemy 就会自动在 MySQL 生成 users 这张表，后续增删改查用户数据，直接操作 User 这个类就行，不用手写原生 SQL

#### 补充:什么是ORM模型
**Object Relational Mapping，对象关系映射**
通俗解释： 它就是把 Python 的类和对象，和 MySQL 的数据表做映射。
- 类 → 对应一张数据表
- 类里面的属性 → 对应表里的字段
- 创建这个类的实例对象 → 对应表里的一行数据

#### 怎么理解自动建表？
2、创建数据库 `lab_agent`
初次使用Navicat，需要注册，并连接MySQL，然后再创建

**既然是自动建表，为什么还要我专门取 navicat 新建 lab_agent 这个数据库**

> SQLAlchemy 的 `Base.metadata.create_all()` 只能建「数据表 (table)」，不能创建「数据库 (database)」
- `lab_agent`：这是**数据库（库）**，相当于一个文件夹。

# 6、`schemas目录下auth.py`和user.py

> 前置概念：`schemas` 在 FastAPI 项目里叫**数据模型/序列化模型**，基于 Pydantic。 作用：定义请求要接收什么字段、接口返回给前端什么字段；自动做类型校验；ORM对象 ↔ JSON 数据转换。

---
`schemas/auth.py`

```python
from pydantic import BaseModel

class LoginRequest(BaseModel):
    username: str
    password: str
```

逐行拆解：
1. `from pydantic import BaseModel` 导入Pydantic的基础模型类，所有自定义数据模型都要继承它。
2. `class LoginRequest(BaseModel):` 登录**入参模型**：专门用来接收前端POST提交过来的登录请求体（JSON）。
3. `username: str`：用户名，字符串类型，**必填**
4. `password: str`：密码，字符串类型，**必填**

✅ 功能：

1. 你的 Vue 前端登录的时候，axios 会发一段 JSON 给后端，长这样：
```json
{
  "username": "zhangsan",
  "password": "123456"
}
```

2. `LoginRequest` 就是提前跟 FastAPI 说好：
> 这个接口，我只接收这种格式的请求体（Body），必须有 username、password，而且都得是字符串。
    少字段、类型不对（比如username传数字）直接返回报错


---

`schemas/user.py`

```python
from pydantic import BaseModel, ConfigDict

class UserResponse(BaseModel):
    id: int
    username: str
    name: str
    role: str
    phone: str | None = None
    email: str | None = None
    status: int

    model_config = ConfigDict(from_attributes=True)
```

1、`class UserResponse(BaseModel):` 
>是登录**返回模型**：后端查询到用户数据之后，用来打包、返回给Vue前端的JSON结构

2、
```
id: int
username: str
......
```
这里，就是在**定义返回 JSON 的格式、类型、是否必填**

3、`model_config = ConfigDict(from_attributes=True)` 
>开启ORM自动转换：数据库查出来的SQLAlchemy用户对象，可以直接传给这个模型，自动转为给前端的JSON，不用手动一个个赋值。

✅ 功能： 后端从数据库拿到用户信息，通过 UserResponse 规范返回给Vue前端的JSON格式。
只会返回我们写在这里的字段，**不会返回数据库里的密码等敏感字段**，起到数据过滤保护的作用。 字段会自动校验类型，保证返回给前端的数据格式统一。


**总结**
- LoginRequest：登录**入参模型**，约束前端 → 后端的JSON（接收请求，校验提交的数据）
- UserResponse：登录**返回模型**，约束后端 → 前端的JSON（封装返回，控制向外输出哪些字段）

### Pydantic 库

Pydantic 是 Python 的**数据校验 + 数据格式化库**，FastAPI 默认配套使用，是 FastAPI 实现参数校验的核心依赖。

✅ 核心作用两点：
1. **校验数据**：检查数据类型、是否缺失。比如 LoginRequest 要求 username 是字符串、必填；前端传数字、漏传字段，直接自动报错，不用自己写一堆 if 判断。
2. **转换包装数据**：像user.py里面的UserResponse，把数据库查出来对象，自动转换成标准 JSON，交给前端 Vue；同时控制哪些字段对外暴露，并隐藏敏感信息（比如密码）。

# 7、创建 API 接口
api/auth.py
```python
from fastapi import APIRouter, Depends
from app.schemas.auth import LoginRequest
from sqlalchemy.orm import Session
from app.database import get_db
from app.models.user import User
from app.schemas.user import UserResponse

router = APIRouter(prefix="/api/auth", tags=["权限验证"])

@router.post("/login")
def login(data: LoginRequest, db: Session = Depends(get_db)):
    user = db.query(User).filter(User.username == data.username).first()

    # 判断账号和密码是否正确
    if not user or user.password != data.password:
        return {"code": 400, "message": "账号或密码错误"}
    return {
        "code": 200,
        "message": "操作成功",
        "data": UserResponse.model_validate(user),
    }
```

**1、导入部分逐行拆解**

1. `from fastapi import APIRouter, Depends` 导入路由对象、依赖注入工具。`APIRouter`用来拆分接口路由；`Depends`用来注入数据库会话。
2. `from app.schemas.auth import LoginRequest` 导入**入参模型**，校验前端传过来的账号密码JSON。
3. `from sqlalchemy.orm import Session` SQLAlchemy的数据库会话类型，用来操作数据库。
4. `from app.database import get_db` 导入获取数据库连接的依赖函数。
5. `from app.models.user import User` 导入数据库ORM模型（数据库user表映射对象）。
6. `from app.schemas.user import UserResponse` 导入**出参模型**，包装要返回给Vue的用户数据。
#### 依赖注入Depends

依赖注入（Depends），很多人说它是 FastAPI 的灵魂：
> 简单说：**把接口需要用到的资源（数据库会话、权限校验、配置）单独抽出去，需要的时候自动给你送进来，不用自己手动写重复代码**。

拿你现在代码看：

```python
def login(data: LoginRequest, db: Session = Depends(get_db)):
```
- `db` 就是注入进来的数据库会话。
- `get_db` 是一个函数，作用是创建、提供数据库连接

**通俗比喻**
你写登录接口、后面还要写用户查询接口、修改接口，**全都需要数据库连接**。
- 如果不使用依赖注入：每个接口里面都要重复写：打开数据库、用完关闭数据库，大量重复代码。 
- 依赖注入：单独写好 `get_db` 这个 “供应工具”。哪个接口需要数据库，写上 `Depends(get_db)`，它就自动把数据库会话送过来给这个接口用，接口用完自动回收

# 9、开发后端 JWT 用户认证

 来自 06开发后端 JWT 用户认证
## 为什么要做用户认证/接口保护

>**保护私有接口，做身份校验，防止陌生人随意操作他人数据**
>**减少密码传输、减少数据库查询**

**情景分析**：
- 我们正在开发智能实验室预约系统。系统里有获取个人信息、预约实验室、查看我的预约记录这类接口，这些接口操作的是用户的私有数据。**如果接口不加任何校验（裸奔），任何人打开 Apipost 直接发请求，就可以随意查看、修改别人的预约和个人信息，数据完全不安全。**
- 同时 HTTP 协议是无状态的，每一次请求都是独立的，**服务器不会自动记住用户已经登录过**。 如果想要限制陌生人访问，笨办法就是每次访问私有接口都带上账号密码，后端反复查询数据库比对密码；
- 但是这个方案**密码多次在网络传输，风险高**，还会**频繁查询数据库，性能差**

所以，我们需要**保护私有接口，做身份校验，防止陌生人随意操作他人数据**，这么做同时还能顺带**减少密码传输、减少数据库查询**

**解决方法：** 
>使用 **JWT + bcrypt** 改造登录流程，实现登录**鉴权**
1. 用户提交账号密码登录，后端从数据库查询用户，用 bcrypt 校验加密密码；
2. 校验通过，生成 JWT 令牌（Token 通行证）返回给前端；
3. 前端保存 Token，之后访问需要保护的私有接口时，在请求头带上这个 Token；
4. 后端通过依赖函数解析、校验 Token，确认是合法登录用户才放行接口；
5. 登录接口、注册接口保持公开，不需要 Token。

**知识点补充**
### 认证/鉴权/Token/JWT/bcrypt
1. **用户认证** 就是校验访问接口的人是谁，确认对方是系统里已经注册登录的合法用户。在本项目里，用来区分：是登录的本人，还是匿名陌生人。

2. **鉴权（新增）** 简单说：**检查通行证是否有效，判断能不能放行本次请求的这个动作，就叫鉴权**。 在我们代码里，`get_current_user` 这个依赖函数，干的就是鉴权：取出 Token、解码校验、查用户、判断是否有效。

> 	区分
> 	认证：登录的时候，核对账号密码，证明 “你是谁”；
> 	鉴权：后续访问接口的时候，核对 Token 通行证，检查 “你有没有资格访问这个接口”

3. **Token（令牌 / 通行证）** 登录成功之后后端下发的一串字符串，相当于临时通行证
>账号密码只在登录的时候提交一次；后续访问私有接口，只传递 Token，不再传递账号密码。Token 带有过期时间，到期失效，需要重新登录获取新 Token

4. **JWT（JSON Web Token）** 是一种标准化的 Token 格式，用来在网络请求里传递身份信息
>分为头部、载荷、签名三部分：
- 头部：记录加密算法（本项目使用 HS256）
- 载荷：存放用户标识 user_id、过期时间`exp`（exp 是固定关键字段，用来控制有效期）
- 签名：用密钥加密生成，防止别人篡改 Token 里面的信息
> ⚠️ 注意：载荷里不要存放密码这类敏感隐私数据

5. **bcrypt** 密码加密工具。数据库不再保存明文密码，只保存加密后的密文；
>校验密码时，对比输入密码和数据库里的密文。就算数据库泄露，别人也无法直接拿到用户原始密码。

6. **HTTP 无状态** HTTP 每一次请求互相独立，请求结束之后服务器不会记住上一次是谁登录的。
>Token 就是用来弥补这个特点

7. 两种接口区分
- 公开接口：登录、注册接口，所有人都可以访问，不需要 Token
- 受保护接口：获取个人信息、预约实验室、查看预约记录，必须携带合法 Token 才能访问

## 配置 JWT 环境变量

```
JWT_SECRET_KEY=F2DtkACCejMl6FMnJWEbBBX2uldFIB4r0fPILvAltaf
JWT_EXPIRE_HOURS=24
JWT_ALGORITHM=HS256
```

1. **JWT_SECRET_KEY（密钥）
- 生成Token的时候，后端用这个密钥给Token打上“防伪印章”
- 校验Token的时候，后端拿同一个密钥检查印章是否真实

2. **JWT_EXPIRE_HOURS=24** 
- 代表Token有效期：**24小时**。 
- Token里面自带过期时间，到时间之后，就算Token本身没有被篡改，后端也会判定它失效，需要用户重新登录。 
- 目的：防止一张通行证永久有效，降低被盗用之后的风险。

3. **JWT_ALGORITHM=HS256** 
- 指定加密签名算法：HS256，是JWT最常用的对称加密算法。

```python
from datetime import datetime, timedelta
import jwt
from app.config import settings

def create_access_token(user_id: int) -> str:
    """创建JWT token"""
    expire = datetime.now() + timedelta(hours=settings.JWT_EXPIRE_HOURS)

    payload = {"user_id": user_id, "exp": expire}  # exp是固定key，不能写成别的

    return jwt.encode(
        payload, settings.JWT_SECRET_KEY, algorithm=settings.JWT_ALGORITHM
    )

def decode_access_token(token: str) -> dict:
    """解析jwt token"""
    return jwt.decode(
        token, settings.JWT_SECRET_KEY, algorithms=[settings.JWT_ALGORITHM]
    )
```

逐行拆解：
1. 导入部分
- `from datetime import datetime, timedelta`：时间工具，用来计算 Token 过期时间
- `import jwt`：pyjwt 库，提供编码、解码 JWT 的能力
- `from app.config import settings`：导入我们在 config.py 实例化好的 settings 对象，用来读取 JWT 的全套配置（密钥、算法、过期小时数）

2. `create_access_token(user_id: int)`：登录成功时调用，生成通行证 Token

- `timedelta(hours=settings.JWT_EXPIRE_HOURS)` timedelta 用来表示一段时间；时长取自 `settings.JWT_EXPIRE_HOURS`，这个值经过 config 读取自.env 文件，方便统一修改有效期
- `payload`：**载荷，存放Token需要携带的信息**
    - `user_id`：自定义内容，标记这个 token 归属哪个用户
    - `exp`：JWT 库识别的固定字段，pyjwt 自动校验这个时间，时间到就判定 token 失效
- `jwt.encode()`：传入载荷、密钥、加密算法，**生成 JWT 字符串**

1. `decode_access_token(token: str)`：
这个函数的作用就是**解析**：前端传过来一个token，后端怎么解析呢

- `jwt.decode` 做两件校验： 
>① 使用 `settings.JWT_SECRET_KEY` 校验签名，判断 Token 有没有被人篡改 
>② 自动校验 payload 里的`exp`过期时间，过期直接抛出异常
- 校验全部通过，返回 payload 字典，我们从中取出 user_id

> 注意坑：decode 的 algorithms 是列表格式 `[settings.JWT_ALGORITHM]`，是 pyjwt 库的固定要求，和 encode 写法不一样

**password.py**
```python
import bcrypt

def hash_password(password: str) -> str:
    """对密码加密"""
    return bcrypt.hashpw(password.encode("utf-8"), bcrypt.gensalt()).decode("utf-8")

def verify_password(password: str, hashed_password: str) -> bool:
    """验证密码的有效性"""
    """  "123" -> "xxsdasdasdasfa"  """
    return bcrypt.checkpw(password.encode("utf-8"), hashed_password.encode("utf-8"))
```

- `import bcrypt`：bcrypt 加密库，专门做密码哈希加密

1. `hash_password(明文密码)`
    
    - `password.encode("utf-8")`：bcrypt 只接受 bytes 字节类型，所以需要将字符串转字节
    - `bcrypt.gensalt()`：自动生成盐值（salt）。盐是一串**随机**字符串，作用：相同密码每次加密出来的密文都不一样，防止彩虹表破解
    - `bcrypt.hashpw()`：把明文 + 盐，算出加密后的字节密文
    - `.decode("utf-8")`：把字节密文转回字符串，方便存入 MySQL 数据库
    
    > 返回值：加密后的密文，存到 user 表的 password 字段，**数据库绝不保存明文密码**
    
2. `verify_password(用户输入的明文密码, 数据库取出的密文密码)`
    - `bcrypt.checkpw()`：bcrypt 自带的比对函数
    - 内部逻辑：不用把密文解密回明文！bcrypt 是单向哈希，**不能解密**
    - 它会使用密文中自带的 salt，对输入的密码重新做一次加密运算，然后对比两次结果是否一致
    - 返回布尔值：匹配成功返回 True，失败返回 False


# 10、jwt 鉴权

```python
from fastapi import Depends, HTTPException, status
from fastapi.security import OAuth2PasswordBearer
from sqlalchemy.orm import Session

from app.database import get_db
from app.models.user import User
from app.utils.jwt import decode_access_token

oauth2_scheme = OAuth2PasswordBearer(tokenUrl="/api/auth/login")

def get_current_user(
    token: str = Depends(oauth2_scheme), db: Session = Depends(get_db)
) -> User:
    """JWT token 鉴权验证合法性"""
    try:
        payload = decode_access_token(token)
    except Exception:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED, detail="登录已失效，请重新登录"
        )
    # 获取到用户ID
    user_id = payload.get("user_id")
    if not user_id:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED, detail="无效的登录凭证"
        )
    # 从数据库根据用户ID查询用户信息
    user = db.query(User).filter(User.id == user_id).first()
    if user.status != 1:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED, detail="用户被禁用"
        )
    return user
```

### 消息的组成（请求头+请求体）
HTTP 请求 = 发给后端的一条消息。 
这条消息分成两块：**请求头（header）** + 请求体（body）
- 请求体：放业务数据，比如登录时的用户名、密码（就是 LoginRequest 接收的内容）
- **请求头：附加的、描述这条请求的附属信息**，比如身份凭证、请求类型、编码等，放在消息最前面。

`Authorization` 就是**请求头（header）**的一种

### OAuth2PasswordBearer

**情景：**
前端发出请求，需要进行认证，那这个时候我该如何获取token呢？

> OAuth2PasswordBearer 是 FastAPI 提供的安全工具

1. **核心作用** 配合 `Depends()`，自动从 `Authorization` 请求头提取 token。
2. **强制约定格式** 只识别：`Authorization: Bearer 空格 token`这一种格式
>（就像写作文，格式要求必须是标题，开头，正文，结尾，缺一不可）

- `Bearer`：固定标识，后面跟一个空格，再放 JWT 字符串
- 格式不对、缺少该请求头，直接抛出 401

3. **参数 tokenUrl**`tokenUrl="/api/auth/login"` 仅为提示地址，告诉前端去哪里获取 token；**不会自动请求、跳转登录接口**。
4. **边界** 它**只负责提取 token，不校验 token**


### 传token的方式
1. token 本身（那一串 JWT 字符串）**内容不变**，变的只是「怎么发给后端」，也就是传输方式。
2. 传 token 有很多种办法：
    - 方式 A：放请求头（当前方案， `OAuth2PasswordBearer` 只支持这个方式）
    - 方式 B：放 URL 参数 `/api/xxx?token=xxxx`
    - 方式 C：放到请求 body（json 里面带 token）
>你现在选了 `OAuth2PasswordBearer`，这个工具**只认方式 A**传输token：
>即
>		**请求头必须命名为 `Authorization`**
>		该请求头内部内容格式： `Authorization: Bearer 空格 token串`

流程如下：
```
GET /api/user/info

Authorization: Bearer eyJhbGciOiJIUzI1NiIs...

token: str=Depends(oauth2_scheme) 就会提取

Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
↓ 
oauth2_scheme
↓ 
token = "eyJhbGciOiJIUzI1NiIs..."
```

**为什么要弄清楚这些问题**
1.  提前明确接口的调用规则：虽然暂时还没有写前端代码，但后端接口已经定下了传token的规则。后续写前端、或者测试接口（比如用Swagger、Apipost）的时候，我就知道：访问受保护接口必须带上 `Authorization: Bearer {token}` 请求头；格式不对就会返回401，避免到时候盲目排查

# 12、封装统一返回格式 Response
来自   07. 后端封装统一响应格式+全局异常处理
`common/response.py`

✅ **需求场景**

你现在登录接口里，是**手动手写字典返回**：`return {"code":200, "message":"xxx", "data":xxx}` 问题：(这些代码在api/auth.py)

1. 每个接口都要自己写一遍这个字典结构，容易写错 key（比如有时候写 msg，有时候写 message）
2. 有的接口返回格式不一样，前端对接要写多套解析逻辑
3. 错误返回、成功返回写法不统一，不方便全局管理

所以新增 `common/response.py`：**封装一套全项目统一的返回体工具类** 
以后所有接口（登录、获取用户信息、其他业务接口）统一用 `Response.success()` / `Response.error()`，保证成功、失败的 json 结构一模一样。

```python
from typing import Any
from pydantic import BaseModel

class Response(BaseModel):
    """统一封装的返回格式"""

    code: int
    message: str
    data: Any = None

    @classmethod
    def success(cls, message: str = "请求成功", data: Any = None):
        return cls(code=200, message=message, data=data)

    @classmethod
    def error(cls, code: int = 500, message: str = "请求失败"):
        return cls(code=code, message=message)
```

1. `from typing import Any`
	`Any` 代表任意类型。因为返回的 data 内容不固定：登录时返回 token + 用户信息、查列表返回数组，所以用 Any，表示 data 可以放任何数据。

2. `class Response(BaseModel)` 继承 Pydantic 的 BaseModel。 好处：
- 强制约束返回结构，不会不小心少写 code、message
- FastAPI return 这个对象时，自动变成前端能看懂的 JSON

3. success，请求成功，要返回data
4. error，请求失败，则不用返回data，但要返回错误代码

## 类方法再理解

**1、需求场景（我们为什么这里要用类方法）**

我们有一个模板类 `Response`（Pydantic模型），用来统一返回JSON结构，字段固定：`code、message、data`。 
每次返回成功响应，大部分情况 `code` 永远是 200，只有 `message` 和 `data` 在变。

如果不用快捷方法，每次都要手写：

```python
return Response(code=200, message="登录成功", data=xxx)
```

问题：

1. 重复写固定的 `code=200`，代码啰嗦
2. 有人写错code（写成201、202），返回格式乱掉

👉 我们想要：写一个快捷函数 `success()`，**直接帮我们带上固定的 code=200**，调用只需要传 message、data。 而且希望调用方式简单：`Response.success()`，**不用先新建一个 Response 对象**。 要实现这个能力，就需要 `@classmethod`。

**2、怎么做（代码）**

```python
@classmethod
def success(cls, message: str = "请求成功", data: Any = None):
    return cls(code=200, message=message, data=data)
```

调用：

```python
Response.success(message="登录成功", data=token_data)
```

**3、核心概念 & 细节原理**

（1）**什么是 `@classmethod`**

`@classmethod` 是Python的装饰器
我们已经知道装饰器作用：**不改原函数里面的代码，给函数增加额外能力**

所以`@classmethod`附加的能力是什么：
让这个函数绑定到**类本身**，在不修改函数内部代码的情况下，**给函数增加「作为类方法运行」的能力**`
同时自动帮我们做一件事：调用这个方法的时候，自动把「这个类」传入第一个参数 `cls`


加上 `@classmethod` 装饰器之后（没有改动 success 里面的代码）：
✅ 新增能力 1：调用方式变成 `类名.方法()`
✅ 新增能力 2：Python 自动把当前类传给第一个参数 `cls`
```python
# 1. 实例普通方法（self）：必须先造对象，才能调用
def normal_func(self):
    pass
# 使用
resp = Response(code=200, message="ok")
resp.normal_func()

# 2. 类方法（@classmethod, cls）：类直接调用，用来创建对象/处理类相关逻辑
@classmethod
def success(cls):
    return cls(code=200, message="ok")
# 使用
Response.success()
```
**这里可以在app/api/auth.py的改动体现明显**

（2）**第一个参数 `cls`**（固定约定，必须放第一个）

- `cls` = class 的缩写，代表**这个类本身**，本例里 `cls` 等价于 `Response`
- `cls(xxx)` 等价于 `Response(xxx)`，作用：按照这个类的模板，新建一个实例（对象）

> 注意区分两个容易混淆的参数：
> 
> - 实例普通方法第一个参数是 `self`：`self` 代表**已经造好的那个对象**
> - 类方法第一个参数是 `cls`：`cls` 代表**图纸/类本身**

（3）**执行流程，当你写 `Response.success(...)`**

1. Python找到类 `Response`，找到它身上绑定的类方法 `success`
2. 自动把 `Response` 传给参数 `cls`
3. 方法内部执行 `cls(code=200, ...)` → 创建一个 Response 实例
4. 把这个新建好的实例返回出去，交给FastAPI，最后转成JSON

## 自定义异常+全局异常处理

✅ **需求场景**
在我们项目之前的写法里，报错是手动写的：

```python
if not user or not verify_password(...):
    return Response.error(code=400, message="账号或密码错误")
```

这种写法有局限：

1. **return 只能返回给直接调用它的上层，深层函数传递错误非常麻烦** 
	如果在底层工具函数里面发现业务错误，return 只能传给上一层函数；每一层都要额外写 if 判断，一层一层把错误往上传递。层级一多代码冗余、很容易漏掉判断。

2. **原生各类异常的返回格式不统一** 
	FastAPI 原生 `HTTPException`、Pydantic 参数校验失败（RequestValidationError）、程序意外报错，它们默认返回的 JSON 结构、字段名称都不一样。前端要写多套解析逻辑，非常麻烦。

👉 我们想要做到：

1. 自己定义一种**业务报错（BusinessException）**，在代码任意地方，直接 `raise BusinessException(message="账号已禁用", code=403)` 抛出异常，不用一层层 return 传递错误信息
2. 不管是：我们自己抛的业务异常 / FastAPI 自带的 HTTPException / 参数校验异常 / 程序未知报错 全部拦截下来，**统一转换成我们这套 `{code, message, data}` 的返回格式**，给到前端
3. 前端永远只需要解析同一套 JSON 结构，不用区分是正常返回、手动 return 的错误、抛出异常带来的错误

> 一句话总结场景： 统一捕获各类异常，把所有报错的返回格式对齐我们的 Response 模板；并且支持在代码任意位置抛出业务错误。
> 
   这样还可以达到区分 “报错类型”，知道错哪了

- `return`：是正常返回结果，只传给紧挨着它的上一层，错误要手动层层传递、层层判断。层级深了非常麻烦。
- `raise 异常`：是中断当前流程的报错信号，自动向上冒泡，直达全局异常捕获器，中间代码不用管错误传递。

## `__init__`和`super()`再理解

```python
class BusinessException(Exception):
    """自定义的业务异常"""

    def __init__(self, message: str, code: int = 500):
        self.message = message
        self.code = code
        super().__init__(message)
```


**1. `__init__` 是什么**

`__init__` 叫**构造方法**。 当你 `类名(参数)` 创建对象的时候，Python 会自动调用 `__init__`。
作用：**给刚新建出来的这个实例，初始化、绑定属性**。

```python
# 执行这一句的时候，自动运行 __init__
exc = BusinessException(message="账号禁用", code=403)
```

**2. `super()` 是什么**

`super()`：拿到**父类**

`super().__init__(message)`
1. `super()` 得到【当前这个类 `BusinessException`】的父类，也就是 `Exception`
2. `().__init__(message)` 调用父类 `Exception` 的构造方法 `__init__`，把 `message` 传给它


✅ **需求场景：**
**3、我们为什么要改写父类 Exception 的 `__init__`**？

Python 原生自带的 `Exception`，里面只存错误提示文字（message），**没有 code 这个字段**。

我们现在项目需求： 抛出业务错误的时候，除了文字提示，还需要附带一个**自定义业务码 code**（400、403、500），后面异常处理器要读取 `exc.code` 组装返回体。

👉 原生 Exception 满足不了：它没有 code 属性。 所以我们继承 Exception，重写它的 `__init__`：
1. 保留原生异常原本需要的 message（交给父类处理）
2. **额外新增一个 self.code 属性**，存我们自己的业务码


```python
async def 处理器函数名(request: Request, exc: 要捕获的异常类型):
    return JSONResponse(
        status_code=HTTP状态码,
        content=Response.error(code=业务码, message="提示文字").model_dump(),
    )
```

统一规律：

1. 全部是 `async` 异步函数（FastAPI/Starlette 处理器要求）
2. 固定两个入参：
    - `request: Request`：本次 HTTP 请求对象（框架自动传进来，大部分时候我们不用主动使用它，但参数必须写上）
    - `exc: XxxException`：捕获到的异常实例，名字 exc 就是 exception 缩写，我们从这里读取错误信息
3. 返回 `JSONResponse`：专门用来返回 JSON 格式响应
4. `Response.error(...)`：调用我们之前写的统一返回模板，生成 Pydantic 对象
5. `.model_dump()`：把 Pydantic 模型转成 Python 字典，给到 JSONResponse

---


✅ 通用模板
```python

        status_code=HTTP状态码,

```

统一规律：

1. `async` 标记这是一个**异步函数**
>核心一句话：
不是因为我们现在代码里面有异步任务要跑，而是我们要用异常处理器，而它本身设计就是给 async 函数用的

2. 固定两个入参：
    - `request: Request`：本次 HTTP 请求对象，框架自动传入。多数场景我们不会主动使用它，但是参数必须写上，框架会自动填充。
    - `exc: XxxException`：捕获到的异常实例，我们从这个对象里读取错误信息

3. 返回 `JSONResponse`：专门用来向前端返回 JSON 格式响应。
4. `Response.error(...)`：调用我们写好的统一返回模板，生成 Pydantic 模型对象。
5. `.model_dump()`：把 Pydantic 模型转换成 Python 字典，JSONResponse 接收字典后转为 JSON 字符串发给前端。

# 14、后端配置跨域

来自 08. Vue封装axios并实现前后端接口联调
这里是这个章节的后端部分

```python
from starlette.middleware.cors import CORSMiddleware

origins = [
	"http://localhost:5173",
	"http://127.0.0.1:5173",
]

app.add_middleware(
	CORSMiddleware,
	allow_origins=origins,        # 允许的前端源，不要直接写 ["*"]
	allow_credentials=True,       # ✅ 关键：允许前端携带 Authorization token
	allow_methods=["*"],          # 允许所有请求方法 GET POST PUT DELETE OPTIONS
	allow_headers=["*"],          # 允许所有请求头（包含Authorization）
)
```

✅ **需求场景**

浏览器有**同源策略**这个安全规则： 如果前端页面地址、后端接口地址，**协议、域名、端口有任意一个不一样，就属于跨域**，浏览器会拦住前端发给后端的请求。

我们现在：
- Vue 前端：`http://127.0.0.1:5173`
- FastAPI 后端：`http://127.0.0.1:8000` 端口不一样 → 属于跨域。 
- 如果不做跨域配置，浏览器直接拦截请求，前端连登录接口都发不出去，后面的 token 鉴权、所有接口调用全部无法进行


📝**代码解析**

我们在后端添加 `CORSMiddleware`（跨域中间件），作用就是
后端告诉浏览器：**我信任这两个前端地址，允许它跨域访问我**。

1. `origins`：写清楚允许哪几个前端地址访问后端，这里是只放行我们本地的 5173
>不推荐直接写`["*"]`（`*`代表允许所有来源，而且`*`和`allow_credentials=True`不能同时生效，带 token 的请求会直接失败，这就是注释说不要写`*`的原因）

2. `allow_credentials=True`：重中之重！开启**允许前端携带凭证**，我们的 `Authorization: Bearer token` 身份凭证就是在这里放行，**不开这个，前端带的 token 会被浏览器丢掉，鉴权直接失效**

3. `allow_methods=["*"]`：允许前端使用 GET、POST、PUT、DELETE 等所有请求方式（  *  表示都可以）

4. `allow_headers=["*"]`：允许前端传递所有请求头，包含我们放 token 的`Authorization`请求头
