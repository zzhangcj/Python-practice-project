## lab_service

`get_lab_page_list` 加上 status，再追加 `get_lab`：

```python
def get_lab_page_list(
    db: Session,
    page: int,
    page_size: int,
    keywords: str | None = None,
    status: int | None = None,
):
    """分页模糊查询列表"""
    # select * from lab where name like '%计算机%';
    query = db.query(Lab)
    if keywords:
        query = query.filter(Lab.name.ilike(f"%{keywords}%"))
    if status:
        query = query.filter(Lab.status == status)
    total = query.count()
    items = (
        query.order_by(Lab.id.desc())
        .offset((page - 1) * page_size)
        .limit(page_size)
        .all()
    )
    return PageResponse(
        list=[LabResponse.model_validate(item) for item in items], total=total
    )

def get_lab(db: Session, lab_id: int):
    lab = db.query(Lab).filter(Lab.id == lab_id).first()
    if not lab:
        raise BusinessException(message="实验室不存在")
    return LabResponse.model_validate(lab)
```

# 解析

## 后端接口权限调整


✅**需求情景**

原有系统：
**只有管理员（get_current_admin）才能访问实验室、设备的查询接口**，学生没有权限查看

现在需求：
1. 做**学生端只读功能**，学生登录后，可以看实验室列表、实验室详情、实验室下的设备；
2. 但是**新增、修改、删除（POST/PUT/DELETE）依然仅限管理员**，学生不能改数据；
3. 学生查看实验室列表时，可以传 `status=1`，只加载【开放】的实验室；
4. 前端页面需要一个根据 lab_id 查单条实验室详情的接口（用来在设备页面顶部展示实验室名字）

**这段代码在做的事情**

1、修改接口依赖：把鉴权从 `get_current_admin` → `get_current_user`
- `get_current_admin`：校验必须是管理员角色才能进接口
- `get_current_user`：**只要登录、有合法 token 就可以进**（管理员、学生都属于登录用户）

> ✅ 效果：管理员、学生都能调用这几个 GET 查询接口；
> 增删改接口不动，依旧是`get_current_admin`，学生调用直接报无权限

<br>

2、lab 的两个接口

- `GET /api/lab/list`：实验室分页列表接口
    - 新增参数 `status`，传给 service 层，可以过滤开放 / 关闭实验室（学生前端固定传 status=1，只看开放实验室）
- `GET /api/lab/{lab_id}`：根据 id 查单个实验室详情
    - 用途：进入【某个实验室的设备页面】时，会显这个实验室名称
    - 带判断：查不到就抛出异常「实验室不存在」

<br>

3、 lab_service 业务层改动
- get_lab_page_list`
    - 接收 status 参数，多一层过滤条件 `Lab.status == status`
- 新增 `get_lab` 函数
    - 底层根据 id 查询实验室

**一句话浓缩**
>放开查询接口的权限，登录用户（学生 + 管理员）都能查实验室、设备；
>写操作权限牢牢锁住只给管理员；
>同时增加 status 过滤，满足学生只能看开放实验室的业务规则


## 前端

### el-menu default-active 动态高亮
(这里了解即可)
```vue
<el-menu
  router
  :default-active="router.currentRoute.value.path"
  style="height: 100%"
  default-active="/manager/home"
>
```

**一句话总结**

`:default-active="router.currentRoute.value.path"` 的作用：
浏览器刷新页面之后，菜单高亮不会变回首页，而是保持当前路由对应的菜单高亮


>额外小知识点(了解)
`router.currentRoute` 是 ref 响应式变量，所以要 `.value` 读取里面的路径；
不加 `.value` 拿到的是 ref 对象，不是字符串，高亮失效。


**拆开讲原理**

1. 不加动态绑定，写死的版本：

```vue
<el-menu
  router
  default-active="/manager/home"
>
```

- 不管你点进实验室列表 `/manager/lablist`，高亮是跟着路由变的（临时生效）
- 一旦**刷新浏览器**，Vue 组件重新加载，`default-active` 直接读取写死的值 `/manager/home` 👉 现象：页面明明在实验室列表，但是菜单高亮跳到首页了，体验很差。

2. 改成动态绑定版本：

```vue
<el-menu
  router
  :default-active="router.currentRoute.value.path"
>
```

- 刷新页面后，`vue-router` 第一件事：读取浏览器地址栏的 url，恢复当前路由
- `router.currentRoute.value.path` 自动拿到刷新后的真实路径（比如 `/manager/lablist`）
- el-menu 拿着这个路径去匹配菜单项 index，自动高亮对应菜单 👉 现象：刷新页面，页面留在当前路由，菜单高亮也同步保持，不会跳回首页高亮。
