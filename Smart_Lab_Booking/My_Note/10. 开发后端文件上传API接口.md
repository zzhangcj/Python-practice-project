## 新建文件上传的 api 接口

在api目录下，创建files.py

```python
import os
import time
from pathlib import Path
import uuid
import shutil
from fastapi import APIRouter, File, UploadFile

from app.common.exceptions import BusinessException
from app.common.response import Response
from app.config import ALLOWED_EXTENSIONS, BASE_DIR, MAX_FILE_SIZE, UPLOAD_DIR

router = APIRouter(prefix="/files", tags=["文件管理"])

@router.post("/upload")
def upload(file: UploadFile = File(...)):
    """文件上传的接口"""
    if not file.filename:
        raise BusinessException(message="文件名不能为空")

    # 原始的文件名  用户头像.jpg
    orignal_name = os.path.basename(file.filename)
    # 文件后缀 .jpg
    ext = Path(orignal_name).suffix.lower()
    if ext not in ALLOWED_EXTENSIONS:
        raise BusinessException(message=f"不自持的文件后缀：{ext}")
    # 文件大小校验
    if file.size and file.size > MAX_FILE_SIZE:
        raise BusinessException(
            message=f"文件不能超过 {MAX_FILE_SIZE // 1024 // 1024}MB"
        )
    # 设置唯一的文件名称   199323213213_ddadaqwerq.jpg
    disk_name = f"{int(time.time() * 1000)}_{uuid.uuid4().hex[:8]}{ext}"
    # 文件存储的实际路径
    save_path = UPLOAD_DIR / disk_name

    # 流式写文件
    with open(save_path, "wb") as f:
        shutil.copyfileobj(file.file, f)

    return Response.success(
        data={
            "original_name": orignal_name,
            "disk_name": disk_name,
            "size": file.size,
            "url": f"/uploads/{disk_name}",
        }
    )
```

# 解析

## 1、需求场景

前面我们已经完成登录、注册、用户相关接口，现在系统需要支持**上传文件**（比如头像、预约附件、证明材料等）。

原生FastAPI如果不做封装，直接写上传逻辑会很零散：

- 没有统一限制文件大小，容易上传超大文件占满服务器磁盘
- 没有白名单校验后缀，用户可以上传exe、恶意脚本等危险文件
- 文件名直接用用户原始名称，会出现中文乱码、重名覆盖文件的问题
- 文件保存之后没办法直接通过浏览器地址访问图片/文档

本章目标： **封装一套统一的后端文件上传接口，实现完整安全校验 + 文件落盘存储 + 返回可直接访问的文件url**，配套挂载静态资源，前端拿到url就可以展示、提交给业务表单。

整条流程： 
```
前端选文件 → POST上传到 `/api/files/upload` 
↓ 
后端接口依次校验：文件名非空 → 后缀在允许列表 → 文件大小不超限 
↓ 
生成唯一不重复的磁盘文件名，防止重名覆盖 
↓ 
把文件写入uploads目录 
↓ 
返回成功，带上原始文件名、磁盘文件名、文件大小、访问地址`/uploads/xxx` 
↓ 
静态资源挂载，浏览器直接访问这个url就能打开文件
```


关键点：

1. 配置项统一管理：最大大小、允许后缀、上传目录，方便后期修改；
2. 安全优先：后缀白名单+大小限制，做基础防护；
3. 重命名策略：时间戳+uuid，解决重名冲突；
4. 挂载静态目录，让上传后的文件可以通过http地址访问，给前端使用


## 2、config.py

```python
MAX_FILE_SIZE = 100 * 1024 * 1024  # 100MB
UPLOAD_DIR = BASE_DIR / "uploads"
UPLOAD_DIR.mkdir(parents=True, exist_ok=True)

ALLOWED_EXTENSIONS = {
    ".jpg", ".jpeg", ".png", ".gif", ".webp",
    ".pdf", ".doc", ".docx", ".xls", ".xlsx", ".zip",
}
```

- `MAX_FILE_SIZE`：限制单文件最大体积，100_1024_1024 就是 100MB，防止大文件占用服务器存储空间、带宽。
- `ALLOWED_EXTENSIONS`：文件后缀白名单，**只允许集合里面的后缀上传**，拦截脚本、exe 等危险文件，做安全防护。

### pathlib的写法

```python
UPLOAD_DIR = BASE_DIR / "uploads"
UPLOAD_DIR.mkdir(parents=True, exist_ok=True)
```
这是 **pathlib（Python3.4+ 内置）** 的写法，是新版推荐的路径方案，和旧的 `os.path` 是两套东西

**1. `BASE_DIR / "uploads"` 斜杠拼接路径**

`pathlib.Path` 对象重载了 `/` 运算符，专门用来拼路径，替代旧写法：

- ✅ pathlib（现在这个）：`BASE_DIR / "uploads"`
- ❌ 旧 os.path 写法：`os.path.join(BASE_DIR, "uploads")`

优势： 跨平台自动适配 Windows `\` 和 Linux `/`，不用自己关心斜杠正反，可读性更强

> 注意：只有 `Path` 对象才能用 `/`，普通字符串不行

**2. `mkdir(parents=True, exist_ok=True)` 自动建文件夹**

等价的 os 老式写法：

```
import os
if not os.path.exists(upload_path):
    os.makedirs(upload_path)
```

参数拆开讲：

- `parents=True`：如果上级文件夹不存在，一并创建（比如 `a/b/uploads`，a、b 都没有，也会一次性建好）
- `exist_ok=True`：目录已经存在的时候，**不抛报错**；不加这个，第二次启动项目就会报「文件夹已存在」异常


**为什么这些代码要放到 config.py（配置文件）**
项目分层约定：
config 专门存放常量、路径、开关、限制这类配置； 
service 放业务逻辑、api 放路由接口，各司其职，代码清晰好维护。

✅ **需求分析**

前面已经在 config 配置好了上传目录、文件大小上限、允许后缀白名单。
现在需要开发**上传接口**，接收前端提交的文件，做安全校验之后保存到服务器，并且返回文件访问地址给前端。 要解决这些问题：

1. 防止上传危险类型文件、超大文件，保护服务器；
2. 同名文件上传互相覆盖；
3. 大文件一次性读入内存导致服务器内存溢出；
4. 上传完成后，前端能拿到 url 直接预览图片或者下载文档。

接口完整地址：`POST /api/files/upload`

## 4、app 挂载静态资源目录
### 静态资源挂载mount

✅ **需求场景**

我们把文件存到了服务器本地 `uploads` 文件夹里。 
浏览器默认**不能直接访问服务器本地磁盘文件**（安全限制，不然浏览器随便读电脑文件就危险了）。 
静态资源挂载，就是告诉 FastAPI：

> 有一个文件夹 `uploads`，里面的图片、文件，是可以直接用网址访问的，交给框架帮我托管。

<br>

📝 **通俗类比（快递驿站延续）**

之前： 后端驿站收到快递（文件），放到仓库 `uploads` 柜子里，**但是没有对外取件窗口**，前端拿不到。

- 挂载静态资源 = 给这个仓库开一个对外窗口 `/uploads/` 
- 规则： 网址 `http://127.0.0.1:8000/uploads/xxx.jpg` → 框架自动去后端项目里的 `uploads/xxx.jpg` 文件拿内容，返回给浏览器。

<br>

**对比接口和静态挂载**
- router 接口 = **人工窗口**，来人了才接待，还要判断业务、查数据库 
- mount 静态挂载 = **自助取件柜**，提前装好，只要输入正确编号（url），系统自动拿文件返回，不需要业务员（函数）

<br>

**对应关系**(重点)
- 磁盘真实位置：`uploads/1769991234_abc12345.jpg`
- 浏览器访问地址：`http://127.0.0.1:8000/uploads/1769991234_abc12345.jpg`

<br>

```python
from fastapi.staticfiles import StaticFiles

from app.config import UPLOAD_DIR

# 挂载静态资源：/uploads/xxx.jpg → uploads/xxx.jpg
app.mount("/uploads", StaticFiles(directory=UPLOAD_DIR), name="uploads")
```

作用
提前告诉 FastAPI：以后只要看到 url 前缀 `/uploads/`，就去这个文件夹找文件
>相当于拿到了取件码，自动取件


## 5、`api/__init__.py`

### 配置路由
Python 包（package） + FastAPI 路由模块化拆分、路由嵌套（路由挂载 include_router）

✅ **需求场景**

我们现在拆分了很多接口文件：auth.py、files.py、user.py。 如果每个路由文件里都自己写 `prefix="/api"`：

1. 重复代码很多，每新增一个接口都要重复写一遍前缀
2. 以后如果要改统一前缀（比如改成 `//v1/api`），要一个个改所有文件，维护麻烦
3. main.py 里面会堆一大堆 `include_router`，代码杂乱

**需求目标：** 把所有子路由统一收拢，**只写一次公共前缀 `/api`**，统一注册管理；让 main.py 清爽，新增接口只需要在汇总处登记一行即可。

> 实现方案：利用 `app/api/__init__.py` 作为路由汇总中心

<br>

- `api = APIRouter(prefix="/api")`：创建汇总路由，在这里一次性定义统一前缀
- `include_router`：把各个独立模块的路由挂载进来

<br>

main.py 只需要一行导入挂载：

```python
from app.api import api
app.include_router(api)
```

 **什么时候用这个方案？**

项目接口按模块拆分（登录、文件、用户等，分多个 py 文件），想要统一管理公共路由前缀的时候。

 **为什么放在 `api/__init__.py`？**
- 文件夹放 `__init__.py` → 这个文件夹变成 Python 包
- `from app.api import api`：导入包，本质就是执行 `__init__.py`，导出里面定义的变量（这里就是汇总路由对象）

### FastAPI 路由嵌套：`include_router()`

```python
from fastapi import APIRouter
from app.api.auth import router as auth_router
from app.api.user import router as user_router
from app.api.files import router as files_router

api = APIRouter(prefix="/api")

api.include_router(auth_router)
api.include_router(user_router)
api.include_router(files_router)
```


- 可以把多个子 router 挂载到一个父 router 上
- 在父 router 统一设置 `prefix="/api"`，**一次性给所有子接口加上前缀**
- 好处：统一管理前缀、统一加标签、统一中间件
