

## 1. Vue3 基础

**目标**
掌握 Vue3 单文件组件的标准写法，理解结构、逻辑、样式分离与 scoped 样式隔离

```vue
<template>
  <!-- 模板：写HTML结构，页面长什么样子 -->
</template>

<script setup>
  <!-- 脚本：写JS逻辑，处理数据、事件、导入组件、路由 -->
</script>

<style scoped>
  <!-- 样式：写CSS，控制页面长什么外观 -->
</style>
```

1. **单文件组件(SFC)**：一个 `.vue` 文件，把「页面结构、业务逻辑、CSS样式」全部放在同一个文件里，这就是Vue标准写法。
2. **结构、逻辑、样式分离**
    - `<template>`：只管页面长啥样（标签、按钮、输入框）
    - `<script setup>`：只管业务逻辑（变量、登录函数、导入路由）
    - `<style>`：只管外观（颜色、宽高、居中、阴影）
        
        > 各司其职，不要把js写在template，不要把css写在script。
        
3. **`scoped` 样式隔离（重点）**
    - 加了 `scoped`：**这个css只对当前这个vue文件生效，不会污染别的页面组件**。
    - 去掉 `scoped`：样式变成全局，写的css会影响项目里所有页面，容易出现样式冲突。

> 例子：`Login.vue` 写的 `.login-box` 样式，加了scoped，就不会跑到 Register.vue 里生效。

## 3. 重定向、懒加载、嵌套路由

 **理解 vue‑router 的配置逻辑，掌握重定向、懒加载、嵌套路由三种核心用法**

> vue‑router 作用：管理浏览器地址栏 URL 和页面组件的对应关系。访问 `/login` 就展示 Login.vue。

### ① 重定向 redirect

```javascript
{ path: '/', redirect: '/manager/home' }
```

含义：当访问根地址 `/` 的时候，**自动跳转到 `/manager/home`**。 解决问题：打开首页 `/` 什么页面都不渲染，出现空白页。

### ② 路由懒加载 `() => import('xxx.vue')`

```javascript
component: () => import('@/views/Login.vue')
```

- 不懒加载：程序启动就一次性把所有页面全部加载。
- 懒加载：**只有用户真正访问这个路由地址的时候，才去加载这个页面的代码**。 
>好处：项目初始打开速度更快，后台页面很多的时候效果明显。Vue项目标准写法。

### ③ 嵌套路由 children
**（本项目最关键）**

```javascript
{
  path: '/manager',
  component: () => import('@/layouts/Layout.vue'), //父布局壳
  children: [
    { path: 'home', component: () => import('@/views/Home.vue') }
  ]
}
```

- `Layout.vue`：公共父布局，包含顶部头像栏、侧边菜单栏，页面固定不变。内部必须写 `<router-view />` 占位标签。
- `children` 里面是子页面：Home、Lab。子页面内容会渲染到父组件的 `<router-view/>` 的位置。
- 子路由path**不要写斜杠**，自动拼接父路径：`/manager` + `home` → 最终地址 `/manager/home`

业务场景：管理后台系统。头部侧边栏保持不动，中间区域切换不同业务页面，就是嵌套路由。

> 流程：访问 `/manager/home` → 先加载Layout外壳，再把Home页面塞进Layout的router-view位置显示。

## 4. 「布局壳 + 子页面」的嵌套路由思维

建立「布局壳 + 子页面」的嵌套路由思维有助于实现公共部分复用，减少重复代码

> 属于工程思想，基于嵌套路由语法。
> **就是 `Layout.vue` + `children` + `<router-view />`**

- 不变的内容（顶部导航、侧边栏）统一放到布局壳 `Layout.vue`；
- 每个页面独有的业务内容，写成子页面，配置在 `children` 下；
- 切换页面时只更新中间业务区域，布局壳保持不变。

一句话总结：**不变的放 Layout 壳，变化的放子页面**

## 存取 token、user 的工具方法
### utils/auth.js

```javascript
//  存储token、存储用户信息、获取token、用户信息，删除token、用户信息这些作用
const TOKEN_KEY = 'token'
const USER_KEY = 'userInfo'

export function getToken() {
  return localStorage.getItem(TOKEN_KEY)
}

export function setToken(token) {
  localStorage.setItem(TOKEN_KEY, token)
}

export function removeToken() {
  localStorage.removeItem(TOKEN_KEY)
}

export function getUserInfo() {
  const str = localStorage.getItem(USER_KEY)
  return str ? JSON.parse(str) : null
}

export function setUserInfo(userInfo) {
  localStorage.setItem(USER_KEY, JSON.stringify(userInfo))
}

export function removeUserInfo() {
  localStorage.removeItem(USER_KEY)
}

// 登出
export function logout() {
  removeToken()
  removeUserInfo()
}
```

✅ **需求场景**

登录成功之后，后端返回了 token 和用户信息。
如果只放在页面普通变量里，**页面一刷新，数据直接消失，用户就要重新登录**。
我们需要一个地方，把 token、用户信息持久保存到浏览器里，页面刷新、浏览器关掉重开之后，数据还在，这就写了 auth.js 封装 localStorage 的工具函数。

📝**必要知识点/代码解析**

1. `localStorage` 是什么：浏览器本地存储空间，**存在用户浏览器里，关闭页面、重启浏览器之后数据还在**。
    - 对比：普通 `ref`、变量，页面一刷新直接消失。
    - 👉 这就是为什么登录成功后要存在这里：刷新页面不用重新登录。
2. 只能存**字符串**！！（这个是高频踩坑点）
    - 存对象 `userInfo`：要用 `JSON.stringify()` 转成字符串再存
    - 取对象：要用 `JSON.parse()` 转回 js 对象
    - 存简单字符串 token，不用转，直接放
3. 四个基础 API（你代码里全部用到了）
    - `setItem(key,值)`：存
    - `getItem(key)`：取
    - `removeItem(key)`：删除
    - 配套：`logout` 就是一次性删掉 token 和用户信息，用于退出登录
4. 区分：`TOKEN_KEY / USER_KEY` 是给存储起名字，相当于给柜子的两个抽屉贴标签，防止存的数据互相覆盖。

> 一句话理解 auth.js：封装一套函数，专门统一管理这两个抽屉的读写，页面不用到处写 `localStorage`。

#### API再理解

API = **Application Programming Interface，应用程序编程接口** 

1. **浏览器内置 API（现在这个）** 浏览器给 JS 提供的**可以直接调用的函数**：localStorage、alert、fetch ✅ 直接在前端代码调用，不用联网 
>	例子：`localStorage.setItem()`,`localStorage.removeItem()`

2. **后端接口 API（你 FastAPI 写的接口，/api/auth/login）** 通过 HTTP 网络请求访问的接口，前后端交互用的，就是我们整条登录链路调用的接口

3. **第三方服务 API（大模型、短信、OSS 存储）** 远程线上服务，需要发 http 请求，往往搭配 apikey 作为身份凭证访问


API 是统称：**凡是给代码调用的功能入口，都叫 API,或者说接口**
**“接口” 是日常口语叫法；API 是它的正式学名。大部分场景二者可以混用**

### utils/user.js

```javascript
// 仅供页面  setup 函数使用
import { ref } from 'vue'
import { getUserInfo, setToken, setUserInfo } from './auth'

const userInfo = ref(getUserInfo()) // 响应式对象 可以随时更新最新的值

export function useUser() {
  function saveLoginData(data) {
    setToken(data.token)
    setUserInfo(data.user)
    userInfo.value = data.user
  }

  function updateUser(user) {
    setUserInfo(user)
    userInfo.value = data.user
  }

  function reloadUser() {
    userInfo.value = getUserInfo()
  }

  return {
    userInfo,
    saveLoginData,
    updateUser,
    reloadUser
  }
}
```

✅ 需求场景 

- 前面auth.js 只解决了把用户信息、token 存进 localStorage 的问题。 
- 而Vue 页面想要进行渲染，比如展示用户名（欢迎 xxx），需要用到 Vue 的响应式变量 `ref`；
- 但是 localStorage 里面的数据和vue没联系，vue不知道里面的数据变没变，就**不会自动渲染到页面上**。 
- 所以我们需要**修改存储的时候，同步更新 ref**；ref 变了，Vue 页面才自动渲染

📝代码解析

1. 初始化逻辑：`const userInfo = ref(getUserInfo())` 页面刷新的时候，一开始就从 localStorage 读取已经保存好的用户信息，给响应式变量赋初始值，实现刷新页面用户名还能正常展示

2. 封装函数作用
- `saveLoginData(data)`：**登录成功时调用**。调用 auth 方法把 token、用户信息存入 localStorage，同时更新`userInfo.value`，存储和页面状态同步。

- `updateUser(user)`：**修改用户资料时调用**。更新 localStorage 里的用户数据，同步更新响应式变量，页面立刻展示最新用户信息。

- `reloadUser()`：**重新从 localStorage 读取用户信息**，覆盖当前 ref 的值，用来手动同步最新登录状态。

-  组合式函数 `useUser()` 把用户相关的状态和方法统一封装导出，页面只需要导入`useUser()`就可以直接使用，多处页面复用，不用重复写 ref、读取存储的逻辑。


### utils/request.js

```javascript
import axios from 'axios'
import { getToken, logout } from './auth'
import { ElMessage } from 'element-plus'
import router from '@/router'

const service = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL,
  timeout: 30000 //30s
})

// 请求拦截器的配置
service.interceptors.request.use(
  (config) => {
    const token = getToken()
    if (token) {
      config.headers.Authorization = `Bearer ${token}`
    }
    return config
  },
  (err) => Promise.reject(err)
)

// 返回的拦截器配置
service.interceptors.response.use(
  (res) => {
    const data = res.data
    if (data.code !== 200) {
      ElMessage.error(data.message || '请求失败')
      if (data.code === 401) {
        logout()
        router.push('/login')
        return Promise.reject(data)
      }
    }
    return data
  },
  (err) => {
    if (err.response) {
      const httpStatusCode = err.response.status
      if (httpStatusCode === 401) {
        ElMessage.error('登录状态已失效，请重新登录')
        logout()
        router.push('/login')
      } else {
        ElMessage.error(err.response.data?.message || '请求失败')
      }
    } else {
      // 后端没启动，网络异常了
      ElMessage.error('网络异常，请检查后端服务')
    }
    return Promise.reject(err)
  }
)

export default service
```

#### axios插件
为什么需要这个插件呢，它是做什么用的？
```
类比寄送快递的例子

页面调用 loginApi（寄快递）
→ 进入【请求拦截器】发货检查站：检查有没有 token，贴上身份头
→ 发给后端
→ 后端处理完，返回包裹（{code,message,data}）
→ 包裹回来，进入【响应拦截器】收货检查站：判断 code，处理报错 / 401 跳转
→ 处理完毕，最后把结果给到页面代码
```

（1）我的理解
意思是这样的，这一趟流程我们需要这两个检查站，但原本的传输链上没有
**所以需要我们加装新建，于是需要axios给我们这个介入这个传输链的机会**

（2）豆包解析
原本浏览器发请求、收响应这条传输路线，是光秃秃直接走的，**没有地方让我们统一加检查逻辑**。 axios 给我们开放了两个 “介入点（钩子）”：

1. 请求发出去之前
2. 响应拿到之后、页面拿到数据之前

我们就利用这两个介入点，**自己写代码，加装这两个检查站**。
**检查站不是 axios 自带的，是我们自己写的；axios 只是提供了能插进去的位置**


`baseURL: import.meta.env.VITE_API_BASE_URL`
这一步，和前面 4. 配置环境变量 相联系

还是送快递这个案例，baseURL 相当于预先填好的**后端驿站地址**
这个驿站的**窗口**（`/auth/login`、`/user/info` 这类路由）是固定不变的；

寄快递的时候：使用**驿站地址 + 窗口名称**，拼出完整目标位置，就可以把请求送到后端对应的窗口
之所以要把驿站地址存在环境变量.env里面，是因为后续这个地址会变，但窗口不会变

**好处** 
① 不用每个接口都写一长串完整地址，减少重复代码； 
② 后端地址更换（本地开发 → 服务器上线），只修改环境变量里的 baseURL，接口代码不用改动

## 路由守卫 

在router/index.js修改

```javascript
import { getToken } from '@/utils/auth'

// 路由守卫：验证token
router.beforeEach((to, from) => {
  const token = getToken()

  if (to.path === '/login' || to.path === '/register') {
    return true
  } else {
    return token ? true : '/login'
  }

```
✅ 需求场景 前面我们只做到：登录成功有token、存到浏览器。 但是有一个漏洞：用户可以直接在浏览器地址栏手动输入 `/manager/home`，绕过登录页面直接访问主页。

我们需要在每一次切换页面（路由跳转）之前做拦截检查：
- 去登录、注册页：直接放行
- 去其他需要登录的页面：读取本地token，有token才放行；没有token，强制跳回登录页

它的定位：**全局页面访问权限保护**。 和接口层面的JWT鉴权是两层防护：

- 路由守卫：前端层面，拦住页面入口，没token不让进页面（只是前端拦截，只是体验层防护）
- JWT + 后端接口鉴权：后端接口校验token，是真正的安全防线

> 重点笔记区分：路由守卫拦的是**页面访问**；后端JWT校验拦的是**接口请求**。两个配合使用


整条大链路串起来（补充给你笔记末尾）

跨域配置 → 底层request封装（请求/响应拦截） → auth.js本地存储工具 → useUser维护响应式用户状态 → api层封装接口函数 → Login页面交互发起登录、保存凭证 → 路由守卫拦截非法页面访问 → 页面读取userInfo展示信息 从浏览器请求放行、网络请求、凭证持久化、状态响应、页面交互、页面访问权限，整套登录鉴权闭环全部完成。


# 7、优化建议： `router-link`、`try...finally` 、`await`

来自 09. 开发用户注册功能

- 使用 `router-link`替换a标签, 同时herf改成to
>原生 a 标签会触发**页面整页刷新**；
>router-link 是 Vue 路由组件，做 SPA 单页跳转，无刷新、速度快，不会丢失前端状态，符合 Vue 项目路由规范
>
>	效果就是，在登录页面点击注册，注册页面切回登录，不会再刷新页面，性能好

- 登录函数改成 `try...finally` 包裹、使用 `await router.push`
在Login.vue里面改写：
```vue
const login = async () => {
  loadingValue.value = true
  try {
    const res = await loginApi(form)
    if (res.code === 200) {
      saveLoginData(res.data)
      ElMessage.success('登录成功')
      await router.push('/manager/home')
    }
  } finally {
    loadingValue.value = false
  }
}
```
> `finally` 保证**无论登录成功还是失败**，loading 加载状态一定会关闭，避免按钮一直转圈卡死；
>`await router.push()` 等待路由跳转完成，逻辑顺序更可控，防止跳转还没完成就执行后续代码。

原先登录页没有前端表单校验：账号、密码为空的时候，点击登录会直接把空数据发给后端，后端返回账号密码错误的提示，白白发起一次无效请求，用户体验不好。 所以我们加上 Element Plus 表单校验，在**前端本地先做检查**，不满足条件就不调用登录接口。

📝代码做了什么

1. 给 el-form 绑定 ref、校验规则 rules；每个 el-form-item 加上 prop，和校验规则里的字段对应；同时设置 label-width 和宽度样式，适配登录页面布局。
2. 定义校验规则 rules：username 和 password 都是必填项，失去焦点的时候触发校验，提示用户输入内容。
3. 在登录点击事件里，先执行 `formRef.value.validate()` 做表单校验：
    - 如果校验不通过（为空），直接终止代码，**不会发送请求给后端**；
    - 校验通过，才继续发起登录 api 请求。

一句话概括：在请求后端之前，前端先拦截空表单，提前提示，减少无效请求

**一、请求代理**

### 打包

（1）**什么是打包？**
Vue 写的代码是 **源码**（`.vue`、`.js` 文件），只能在 `npm run dev` 的 Vite 开发服务器上面跑。 浏览器**不能直接读懂 vue 文件、ES6 语法**。 

👉 **打包（build）就是：把你写的前端源码，翻译成浏览器原生能看懂的文件，生成可以放到服务器上直接上线的成品。**

（2）**两条命令对比（最核心）**

```bash
npm run dev   # 开发模式（不打包！）
npm run build # 打包，生成上线文件
```

✅ **npm run dev**（你现在天天在用）

- 启动 Vite 开发服务器
- 不会生成静态成品文件
- 有 proxy 代理、热重载（改代码页面自动刷新）
- 只适合你本地调试，**不能发给别人、不能放到服务器上线**
- 本质：Vite 在内存里实时编译你的代码

✅ **npm run build** 【打包】

执行之后，Vite 会自动做这些事：
1. 编译 `.vue` 组件、新 JS 语法，转为浏览器支持的 JS、CSS
2. 压缩代码（删掉空格、换行、变量改名，文件变小，加载更快）
3. 图片、静态资源自动处理
4. 全部输出到 **dist 文件夹**

> dist 文件夹 = 打包产物！ dist 里面只有：html、js、css、图片，没有 `.vue` 源码。

打包完成之后，**Vite 就不需要了**。dist 是纯静态文件，随便丢给 Nginx 托管


### 代理/联调
(3)**和这一章的知识点串起来**

我们前面在 08. Vue封装axios并实现前后端接口联调 使用了**跨域（CORS）** 的方法来实现了前后端接口联调，但这里我们需要换成**代理**的方法

>把浏览器看成小区保安，同源策略是小区规定：**只允许本小区（同一个域名 + 端口）的人互相串门办事**；外来小区的人直接来敲门，保安会拦住

>那这个时候外面的人要串门办事怎么办？
- 方案 A（跨域CORS ）：提前跟保安打好招呼，给后端办一张通行证
- 方案 B（代理）：找一个中转站，所有请求都先交给中转站，中转站会帮你将请求送达给内部的人

**方案 A 跨域配置**（用 VITE_API_BASE_URL）

- env 里面写死后端地址 `http://127.0.0.1:8000`
- 执行打包 → 这个地址**被写死进 dist 里面的 js 文件**
- 以后后端地址变了：dist 里面的地址已经固化改不了！
- 只能改 env，**重新执行一次 npm run build，重新打包**

**方案 B 代理方案**（不用写 VITE_API_BASE_URL）

-  前端接口统一只写 `/api/xxx`，不写任何 IP 和端口
-  本地开发时：Vite 充当中转站；上线部署时：Nginx 充当中转站
- 后续后端地址变更，**只需要修改中转站（Nginx）的转发配置，前端不用重新打包**

>Vite 代理**仅本地开发的时候生效，打包之后代理失效，上线必须换成 Nginx 反向代理**

#### Vite Proxy 代理
在vite.config.js里面添加

```javascript
server: {
  proxy: {
    // API 接口代理
    '/api': {
      target: 'http://127.0.0.1:8000',
        changeOrigin: true
    },
    // 静态文件代理（头像图片）
    '/uploads': {
      target: 'http://127.0.0.1:8000',
      changeOrigin: true
    }
  }
}
```

删除 VITE_API_BASE_URL 配置 ，让 /api 访问走代理

request.js 修改 请求根路径：

```javascript
const service = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL || '',
  timeout: 30000
})
//这里只是添加了 || ''
```


1、配置 vite proxy
在 `vite.config.js` 写 `server.proxy` 这一段，就是开启 Vite 的代理中转站功能
- 匹配 `/api` 开头的请求 → 转发到 `http://127.0.0.1:8000`
- 匹配 `/uploads` 开头的请求（头像静态资源）→ 转发到同一个后端地址
- `changeOrigin: true`：转发的时候修改请求源，后端能正常识别请求，避免校验报错

2、删除 `.env` 里的 `VITE_API_BASE_URL`
不再写死后端完整地址

3、baseURL 置空（可做可不做）
- 原来方案 A 的时候： `VITE_API_BASE_URL=http://127.0.0.1:8000` ，axios 的 `baseURL` 等于这个地址
- 你写 `url:"/api/user/update"`，axios 会自动拼接： `http://127.0.0.1:8000 + /api/user/update`，得到完整绝对地址，直接发给后端。
- 现在我们要换成代理方案，**不想让 axios 帮我们拼接域名**，希望请求路径就是单纯的 `/api/user/update`，交给 Vite 来转发。
- 所以修改 request.js，目的就是：**让 baseURL 变成空，关闭 axios 自动拼接域名的行为**

上面这三段操作（配置 vite proxy + 删除 VITE_API_BASE_URL + baseURL 置空），就是我们使用 Vite 代理、走中转站模式的完整改造步骤

### 前端接口模板

```javascript
import request from '@/utils/request'

/** 接口注释：写清楚这个接口干什么 */
export function 接口函数名(形参) {
  return request({
    url: '完整路由地址',
    method: '请求方式',
    data: 传给后端的json数据 // POST/PUT才需要，GET一般不用
  })

```

各字段说明

1. `import request from '@/utils/request'` `request` = 包装好的 axios，自带 token 拦截、响应统一处理、配合 Vite 代理，所有接口都要引入它。
2. `export function xxxApi()`
- 规范命名：功能 + Api，例如 `getUserInfoApi`、`updateUserInfoApi`
- 函数作用：给 Vue 页面调用，页面传参进来

3. `url` ✅ 规则：**必须和后端拼接完成的路由完全一模一样** 后端 `router = APIRouter(prefix="/user")` + `@router.put("/update")` 拼接结果：`/api/user/update`，前端 url 就写这个

4. `method` （大小写一般小写，常用 4 种）
- `get`：查询数据（获取用户信息），**一般不带 data**
- `post`：新增、提交
- `put`：更新、修改（局部更新用户信息）
- `delete`：删除

5. `data` PUT/POST 提交 JSON 请求体时使用，对应后端的 Request Schema（UserUpdateRequest）

## （4）前端：封装 api 函数

`api/user.js` 追加：

```javascript
/**
 * 分页模糊查询用户列表
 */
export function getUserPageList(params) {
  return request({
    url: '/api/user/list',
    method: 'get',
    params
  })

```

### 前端的接口再理解/前端API模板

1. `export function` 定义一个可复用的函数，后续页面组件直接调用这个函数，不用重复写 url、请求方式；
2. `url,method`约定请求目标地址 `/api/user/list`、请求方式 GET；
3. `getUserPageList(params)`  接收一个 `params` 对象（包含 `page、page_size、keywords`），axios 自动把它转为 url 后面的查询参数；
4. `return request` 内部交给封装好的 `request`（axios 实例）发网络请求，拿到后端返回的数据，给页面组件使用

### 前端的接口需求情景/前端API作用

后端 API = 快递前台（接收 http 请求、调用 service、返回结果） 
前端 API 函数 = **专门帮页面去发请求的跑腿员**
页面组件 = 柜台（给用户看、收集用户输入、渲染页面）

✅ **前端 API 层的核心职责**

1. **统一封装请求地址、请求方式（GET/POST）、请求头（token）** 把后端接口路径（`/auth/login`、`/equipment/page`）、method、参数格式全部包在函数里面。 页面不用写 `axios.post("/auth/login",xxx)`，直接调用 `loginApi(data)`
>比如：后端接口路径 `url`、请求方法 `get/post/put/delete` 固定写死在函数内部
2. **参数组装、传给后端**：把页面收集的表单、分页参数、keywords，整理成后端 DTO 需要的格式传给后端
>(1)`getUserPageList(params)`：GET 请求，参数放在 `params`（url 查询参数？page=1&keywords=xxx）
   (2)`createEquipmentApi(data)`：POST，参数放在 data（请求体 json）
   (3)`updateEquipmentApi(equipmentId, data)`： 👉 把传入的 equipmentId 拼进 url 路径（路径参数），表单数据放 data
   (4)页面只需要把参数丢给函数，不用自己拼接 url、不用区分 params 和 data
3. **接收后端返回的统一响应**：拿到后端返回的 {code,msg,data}，交给页面
>函数 return `request(...)`，也就是把 `request` 拿到的后端返回结果抛给页面组件
4. **统一处理基础请求配置**：请求拦截器加 token、响应拦截器统一处理 401、统一报错提示（可选）
>放在`utils/request.js`里面的

# 11、动态高亮

来自 17. 开发学生端实验室列表和设备列表
## el-menu default-active 动态高亮
(这里了解即可)
```vue
<el-menu
  router
  :default-active="router.currentRoute.value.path"
  style="height: 100%"
  default-active="/manager/home"
>
```

**一句话总结**

`:default-active="router.currentRoute.value.path"` 的作用：
浏览器刷新页面之后，菜单高亮不会变回首页，而是保持当前路由对应的菜单高亮


>额外小知识点(了解)
`router.currentRoute` 是 ref 响应式变量，所以要 `.value` 读取里面的路径；
不加 `.value` 拿到的是 ref 对象，不是字符串，高亮失效。


**拆开讲原理**

1. 不加动态绑定，写死的版本：

```vue
<el-menu
  router
  default-active="/manager/home"
>
```

- 不管你点进实验室列表 `/manager/lablist`，高亮是跟着路由变的（临时生效）
- 一旦**刷新浏览器**，Vue 组件重新加载，`default-active` 直接读取写死的值 `/manager/home` 👉 现象：页面明明在实验室列表，但是菜单高亮跳到首页了，体验很差。

2. 改成动态绑定版本：

```vue
<el-menu
  router
  :default-active="router.currentRoute.value.path"
>
```

- 刷新页面后，`vue-router` 第一件事：读取浏览器地址栏的 url，恢复当前路由
- `router.currentRoute.value.path` 自动拿到刷新后的真实路径（比如 `/manager/lablist`）
- el-menu 拿着这个路径去匹配菜单项 index，自动高亮对应菜单 👉 现象：刷新页面，页面留在当前路由，菜单高亮也同步保持，不会跳回首页高亮。

- views：路由页面（浏览器一个路由对应一个页面）

### (1)`v-model:visible` 
这是是 Vue3 子组件双向绑定语法糖（重点）

```vue
<reserve-dialog v-model:visible="reserveVisible" />
```

等价于：

```vue
<reserve-dialog :visible="reserveVisible" @update:visible="reserveVisible = $event" />
```

前提：子组件里面必须 `defineEmits(['update:visible'])`，关闭弹窗时 `emit('update:visible', false)`

> 笔记一句话：`v-model:xxx` 对应 props 的 `xxx` + emit `update:xxx`

#### Vue3 子组件双向绑定语法糖
>父组件：`LabList.vue`（views 页面） 
>子组件：`ReserveDialog.vue`（components 里面的弹窗）

<br>

✅**需求情景**
我们有一个子组件（预约弹窗 ReserveDialog），有一个状态 `visible` 控制弹窗显隐，我们想要达到两个效果：
1. **父组件要控制弹窗打开**：父给子传一个值，控制弹窗显示
2. **子组件自己可以关闭弹窗**（点取消、点右上角叉）：子组件要通知父组件，把这个值改成false

如果没有语法糖，只能老老实实写 `属性 + 事件`，写起来重复；
Vue3 提供 `v-model:自定义名称` 简化这个写法
<br>

**底层等价关系**
```vue
<!-- 父模板里，两种写法等价 -->
<!-- 语法糖 -->
<reserve-dialog v-model:visible="reserveVisible" />

<!-- 展开后的完整写法 -->
<reserve-dialog
  :visible="reserveVisible"
  @update:visible="reserveVisible = $event"
/>
```
拆解：
- `:visible="reserveVisible"`：**父传给子**
	- 父把自己的 `reserveVisible` 变量，通过 props 传给子组件
- `@update:visible="reserveVisible = $event"`：**父监听子发出来的事件** 
	- 子一旦抛出 `update:visible` 事件，父就把自己的 `reserveVisible` 改成事件带过来的值（`$event` 就是子传过来的参数，比如 false）

> 总结：`:visible` 是父往外发；`@update:visible` 是父等着接收子的通知
> **这两行都写在父组件**



```javascript
//这里是子组件里面的代码
const props = defineProps(['visible'])
const emit = defineEmits(['update:visible'])

// 子关闭弹窗时执行
emit('update:visible', false)
```
- 子想要通知父修改状态，必须满足两个前提
    1. 子要声明：我接收 `visible` 这个 props（`defineProps`），用来拿到父传过来的值，控制弹窗显隐
	2. 子要声明：我可以抛出 `update:visible` 这个事件（`defineEmits`）
	>子不能直接改 `props.visible`，只能用 `emit` 把新值抛出去交给父处理

<br>

**一句话链路串起来**

1. 父：`reserveVisible = true` → 通过 `:visible` 传给子的 props.visible → 弹窗打开
2. 用户在弹窗点【取消】（子内部）
3. 子执行 `emit('update:visible', false)` → 向外抛出事件，携带新值 false
4. 父这边提前监听了 `@update:visible`，收到事件后自动执行 `reserveVisible = false`
5. 父的变量一变，`:visible` 传给子的 props 跟着变 → 弹窗关闭


**一句话定义**
`v-model:xxx` 是 Vue3 的语法糖, **把「传props属性」和「监听update事件」合并成一行**，专门用来做父子组件之间某一个状态的双向同步

数据的所有权在父组件。子只有 “读” 的权限；想要变更这个状态，只能发消息通知父，由父自己改自己的数据
<br>

**补充重点**
你的项目里只用了一个 `v-model:visible`，是最常见的场景

一、关键：**不是真正的双向修改props！**

 很多人误解：子组件直接改 `props.visible`
❌ 错误：子组件自己就可以 `props.visible = false` 
✅ 正确：子组件不能直接修改props，只能 `emit('update:visible', 新值)`，由父组件自己修改自己的变量。
> 本质依然是**单向数据流**，语法糖只是简化代码，没有打破单向数据流规则。
> 这一点后端非常容易理解：**数据归属权在父组件**

<br>

二、适合的场景（什么时候用） 
适合：**由双方共同控制的布尔/简单状态**
- 弹窗、抽屉的显隐（就是现在这个场景，最典型）
- 子组件内部的开关、选择器 
<br>

**三、什么时候不适合用、回归普通props+事件**

- 复杂业务数据（比如预约表单里面的日期、设备id）
- 数据修改之后，要调用后端接口、校验、报错 这种不要用v-model，单独props传数据，点击提交的时候emit提交事件，交给父去调用接口。 因为这种业务，不是简单同步一个布尔值，中间还有一大段业务逻辑。

#### 单向数据流思想

✅**v-model:visible 完全就是 Vue 单向数据流思想的体现** 
它看着像“双向绑定”，底层根本没有打破单向数据流，只是语法糖包装

**一、什么是单向数据流**

规则： **props 只能父 → 子单向传递。子组件无权直接修改 props**
数据是谁定义的，谁才有资格修改

- reserveVisible 是**父组件 LabList.vue 定义的变量** → 所有权属于父
- 子组件 ReserveDialog 只能读取 props.visible，不能写
- 子想改这个状态，不能自己动手，只能发事件通知父：“请你把你的变量改成false”

类比（后端很好理解）
>  父 = 数据库；子 = 接口。
>  子只能读数据，不能直接改库；
>  要改必须发请求通知服务端，由服务端去更新库。

<br>

**二、那为什么要设计单向数据流？（需求情景）**

**情景1：方便追溯数据变化，排查bug**

如果允许子随便改 props： 父传给子A，子A偷偷改了；
子B也拿到同一个props，也偷偷改。
后面弹窗一会开一会关，你根本不知道**是谁、在哪一行代码改了这个值**，bug很难找。

单向数据流：所有修改都集中在**数据所有者（父组件）**。 `reserveVisible` 只在父这里被修改，所有变更来源清晰，调试简单
<br>

**情景2：一份数据可以给多个子组件共享、保持一致**

假设：父页面同时打开【预约弹窗】和【预约详情弹窗】，共用同一个控制标识。
如果子能私自改props，两个弹窗状态很容易不同步。
单向流：源头只有父的这一个变量，所有子只是读取副本，天然保证数据一致。
<br>

**情景3：符合Vue的设计哲学，降低维护成本（多人协作）**

约定好：**数据在哪定义，在哪修改**。
团队所有人都遵守这个规则，看代码的时候不用猜：子组件不会偷偷篡改上游数据。
<br>

**三、那 v-model:xxx 是干嘛的？既然单向，为什么看起来像双向？**

单向数据流是**底层规则**；
v-model:xxx 只是**简化写法的语法糖**，它没有改变规则

- 没有语法糖的时候：你要手动写 `:visible` + `@update:visible` 两段
- 有语法糖：合并成一行 `v-model:visible` 底层链路没变： 父传props给子（读）→ 子emit事件通知父（请求修改）→ 父自己修改变量

❌ 误区： 不是“双向绑定=子父互相随便改” 
✅ 真实：单向数据流 + 事件通知，模拟出双向同步的效果，方便写弹窗、开关这类简单状态。
<br>

### 一、template 部分知识点
 #### vue再理解/DOM
把**网页 = 一栋房子**

- DOM = **按照图纸建好、放在内存里的实体房子**（浏览器造出来的，不是你写的）
	- DOM = Document Object Model，文档对象模型

**一句话区分**
- HTML(template)：**定义页面有什么结构**
- JS(script)：**定义页面怎么交互、数据怎么变**
- DOM：浏览器在内存里生成的、可以被 JS 修改的页面实体

3. `<style>` → 样式（装修配色、大小）

#### 1.聊天框滚动
(这里可以联系下面 `二 的 第2点`)
**(1) `ref="listRef"` 获取DOM元素**
```html
<div ref="listRef"></div>
```

你可以把 `ref="listRef"` 理解成： **给这个 div 贴一个标签，名字叫 listRef，告诉 Vue：把这个 div 的实体 DOM 盒子，帮我存起来，后面我 JS 代码要用它**

- template 里的 `<div>` 只是图纸上画的盒子
- 浏览器运行之后，会生成真实的 DOM 盒子（就是那个可以滚动的框）
- `ref="listRef"` 就是登记：这个真实盒子，我起名叫 listRef

然后 `const listRef = ref()` 是在 JS 这边，**准备一个柜子，专门用来存放这个盒子**
Vue 会自动把这个 div 的 DOM 盒子，放进 `listRef.value` 里面。
👉 所以： `listRef.value` = 这个真实的滚动 div 盒子（DOM）
<br>

**为什么我们要拿到这个盒子？**

普通 Vue 写法：我们改 `messages` 数组，Vue 自动帮我们渲染消息气泡，**我们不用碰这个盒子**。 
但是有一件事，Vue 没有现成的指令帮你做：

> 让这个滚动框，自动滚到最底下，看到最新消息

这个滚动，是这个 div 盒子**原生自带的能力**，要通过盒子本身的属性 `scrollTop`、`scrollHeight` 控制。 
想要操作这个属性，前提就是：**先拿到这个盒子本身**。
<br>

```html
elem.scrollTop = elem.scrollHeight
```

elem 就是 `listRef.value`，也就是这个 div 盒子。
翻译成大白话：拿到这个盒子，告诉盒子，滚动到最底部。


**(2)滚动容器：`overflow-y: auto`**
固定高度 `height:480px`，内容超出高度就出现垂直滚动条；聊天消息容器标配写法。
<br>

```vue
v-for="(item, index) in messages" :key="index"
          v-for="(item, index) in messages"
          :key="index"
          :style="{
            display: 'flex',
            justifyContent: item.role === 'user' ? 'flex-end' : 'flex-start',
            marginBottom: '12px'
```

#### 2、`nextTick`聊天滚动
（高频重点，聊天滚动必用）

```javascript
const scrollToBottom = () => {
  nextTick(() => {
    const elem = listRef.value
    if (elem) elem.scrollTop = elem.scrollHeight
  })
}
```

✅ 需求场景： 你push一条新消息到messages，**Vue是异步更新DOM**。
直接执行滚动，DOM还没渲染出来，滚动会失效。
`nextTick`：等DOM更新完成之后，再执行滚动到底部。 
`scrollTop = scrollHeight`：原生JS，滚动容器拉到最底部,不用手动去拉

#### 3、为什么发 AI 接口要用 `async / await`（重点）
先记住一句话：
**网络请求是耗时操作，会卡住，属于 IO 等待，要用异步（`async / await`）**

```JavaScript
const res = await chatApi(data)
```

`chatApi` 是 axios，作用：浏览器发 HTTP 请求，跨网络去找后端，后端再去调用大模型。 这个过程很慢：几十毫秒甚至几十秒（AI 生成回答）

>**axios再理解**
axios 是前端 JS 的网络请求库，专门用来发 http 请求，和后端接口通信
简单说：**帮浏览器去调用后端接口的工具**

<br>

**如果不用 async/await（同步写法，不行）**
JS 在浏览器里是**单线程**。 
如果写同步网络请求：浏览器卡住，页面卡死，按钮点不动、滚动动不了，一直等到后端返回结果才恢复。 用户体验极差。

**await 的作用**
`await chatApi(data)`：

- 发出网络请求之后，**JS 先放一放这个任务，不去干等**，先去处理别的事情（比如页面渲染、用户点击）；
- 等后端返回数据了，再回来继续执行后面的代码（拿到 res，追加 AI 消息）。

✅ 一句话：**网络请求是等待类操作，用异步，避免页面卡死**。

- `data = { messages: history }`：把过滤后的对话历史传给后端（和后端schema对应）
- 历史消息会一直带上，**大模型才有上下文记忆**（非常关键！不传history，AI不知道上一句聊了啥）
<br>

**4、try / finally 结构**

```javascript
try {
  // 请求AI接口
} finally {
  loading.value = false
}
```

不管接口成功、报错、超时，finally一定会执行，loading关闭。


#### 5、前置校验：防止空消息、重复点击
```javascript
const text = input.value.trim()
if (!text || loading.value) return
```

- `trim()`：去掉首尾空格，用户只输入空格，直接判定为空，不发起请求
- `!text`：空内容拦截，不发无效请求
- `loading.value` 判断：**防重复提交**。上一次 AI 请求还没返回时，用户多次点发送 / 回车，直接拦截，避免连续调用后端、多发消息。

#### 6、乐观更新
**6. 前端先渲染用户消息（乐观更新，体验优化）**

```javascript
messages.value.push({ role: 'user', content: text })
input.value = ''
scrollToBottom()
```

- 逻辑：**先把用户消息加到聊天列表，清空输入框、滚动到底，再去请求后端**
- 对比悲观更新：等后端返回成功再渲染用户消息（会有明显延迟，用户以为点了没反应）
- 优点：用户一点发送，立刻看到自己的消息，感知更快；AI 回复慢慢等就行。

> 注意：这里只是前端展示，AI 的回答要等接口返回才 push。

#### 7、filter 过滤消息 history

```javascript
const history = messages.value.filter(
  (item) => item.role === 'user' || item.role === 'assistant'
)
```

- `filter`：JS 数组方法，遍历数组，保留满足条件的元素，返回新数组
- 业务意义：只传给后端 `user` 和 `assistant` 的消息，过滤掉其他类型
	>因为消息里面有很多杂七杂八的东西，这里只需要`user` 和 `assistant` 
- 作用：严格对齐后端 `ChatRequest` 的要求，传给后端的消息数组是干净合法的

- marked：解析markdown（换行、粗体）
- DOMPurify：安全过滤，是v-html的标配安全方案
