### 自定义异常+全局异常处理

`common/exceptions.py`

```python
from fastapi import HTTPException, Request
from fastapi.exceptions import RequestValidationError
from fastapi.responses import JSONResponse

from app.common.response import Response

class BusinessException(Exception):
    """自定义的业务异常"""

    def __init__(self, message: str, code: int = 500):
        self.message = message
        self.code = code
        super().__init__(message)

async def business_exception_handler(request: Request, exc: BusinessException):
    """自定义业务异常处理器"""
    return JSONResponse(
        status_code=200,
        content=Response.error(code=exc.code, message=exc.message).model_dump(),
    )

async def http_exception_handler(request: Request, exc: HTTPException):
    """Http异常处理器"""
    return JSONResponse(
        status_code=exc.status_code,
        content=Response.error(code=exc.status_code, message=exc.detail).model_dump(),
    )

async def validation_exception_handler(request: Request, exc: RequestValidationError):
    """参数异常处理器"""
    return JSONResponse(
        status_code=422,
        content=Response.error(code=422, message="请求参数校验错误").model_dump(),
    )

async def global_exception_handler(request: Request, exc: Exception):
    """全局异常处理器"""
    return JSONResponse(
        status_code=500,
        content=Response.error(code=500, message="服务器内部错误").model_dump(),
    )
```

### 修改登录 api 完整版

```python
from fastapi import APIRouter, Depends
from app.common.exceptions import BusinessException
from app.common.response import Response
from app.schemas.auth import LoginRequest,LoginResponse
from sqlalchemy.orm import Session
from app.database import get_db
from app.models.user import User
from app.schemas.user import UserResponse
from app.utils.password import verify_password
from app.utils.jwt import create_access_token

router = APIRouter(prefix="/auth", tags=["权限验证"])

@router.post("/login")
def login(data: LoginRequest, db: Session = Depends(get_db)):
    # 根据用户账号查询数据库
    user = db.query(User).filter(User.username == data.username).first()

    # 判断账号和密码是否正确
    if not user or not verify_password(data.password, user.password):
        raise BusinessException(message="账号或密码错误")
    # 验证账号的状态
    if user.status != 1:
        raise BusinessException(message="账号被禁用")
    # 创建token
    token = create_access_token(user.id)
    # 返回信息
    return Response.success(
        message="登录成功",
        data=LoginResponse(token=token, user=UserResponse.model_validate(user)),
    )
```

# 代码解析

## 1、`common/response.py`

✅ **需求场景**

你现在登录接口里，是**手动手写字典返回**：`return {"code":200, "message":"xxx", "data":xxx}` 问题：(这些代码在api/auth.py)

1. 每个接口都要自己写一遍这个字典结构，容易写错 key（比如有时候写 msg，有时候写 message）
2. 有的接口返回格式不一样，前端对接要写多套解析逻辑
3. 错误返回、成功返回写法不统一，不方便全局管理

所以新增 `common/response.py`：**封装一套全项目统一的返回体工具类** 
以后所有接口（登录、获取用户信息、其他业务接口）统一用 `Response.success()` / `Response.error()`，保证成功、失败的 json 结构一模一样。

```python
from typing import Any
from pydantic import BaseModel

class Response(BaseModel):
    """统一封装的返回格式"""

    code: int
    message: str
    data: Any = None

    @classmethod
    def success(cls, message: str = "请求成功", data: Any = None):
        return cls(code=200, message=message, data=data)

    @classmethod
    def error(cls, code: int = 500, message: str = "请求失败"):
        return cls(code=code, message=message)
```

1. `from typing import Any`
	`Any` 代表任意类型。因为返回的 data 内容不固定：登录时返回 token + 用户信息、查列表返回数组，所以用 Any，表示 data 可以放任何数据。

2. `class Response(BaseModel)` 继承 Pydantic 的 BaseModel。 好处：
- 强制约束返回结构，不会不小心少写 code、message
- FastAPI return 这个对象时，自动变成前端能看懂的 JSON

3. success，请求成功，要返回data
4. error，请求失败，则不用返回data，但要返回错误代码

#### 类方法再理解

**1、需求场景（我们为什么这里要用类方法）**

我们有一个模板类 `Response`（Pydantic模型），用来统一返回JSON结构，字段固定：`code、message、data`。 
每次返回成功响应，大部分情况 `code` 永远是 200，只有 `message` 和 `data` 在变。

如果不用快捷方法，每次都要手写：

```python
return Response(code=200, message="登录成功", data=xxx)
```

问题：

1. 重复写固定的 `code=200`，代码啰嗦
2. 有人写错code（写成201、202），返回格式乱掉

👉 我们想要：写一个快捷函数 `success()`，**直接帮我们带上固定的 code=200**，调用只需要传 message、data。 而且希望调用方式简单：`Response.success()`，**不用先新建一个 Response 对象**。 要实现这个能力，就需要 `@classmethod`。

**2、怎么做（代码）**

```python
@classmethod
def success(cls, message: str = "请求成功", data: Any = None):
    return cls(code=200, message=message, data=data)
```

调用：

```python
Response.success(message="登录成功", data=token_data)
```

**3、核心概念 & 细节原理**

（1）**什么是 `@classmethod`**

`@classmethod` 是Python的装饰器
我们已经知道装饰器作用：**不改原函数里面的代码，给函数增加额外能力**

所以`@classmethod`附加的能力是什么：
让这个函数绑定到**类本身**，在不修改函数内部代码的情况下，**给函数增加「作为类方法运行」的能力**`
同时自动帮我们做一件事：调用这个方法的时候，自动把「这个类」传入第一个参数 `cls`


加上 `@classmethod` 装饰器之后（没有改动 success 里面的代码）：
✅ 新增能力 1：调用方式变成 `类名.方法()`
✅ 新增能力 2：Python 自动把当前类传给第一个参数 `cls`
```python
# 1. 实例普通方法（self）：必须先造对象，才能调用
def normal_func(self):
    pass
# 使用
resp = Response(code=200, message="ok")
resp.normal_func()

# 2. 类方法（@classmethod, cls）：类直接调用，用来创建对象/处理类相关逻辑
@classmethod
def success(cls):
    return cls(code=200, message="ok")
# 使用
Response.success()
```
**这里可以在app/api/auth.py的改动体现明显**

（2）**第一个参数 `cls`**（固定约定，必须放第一个）

- `cls` = class 的缩写，代表**这个类本身**，本例里 `cls` 等价于 `Response`
- `cls(xxx)` 等价于 `Response(xxx)`，作用：按照这个类的模板，新建一个实例（对象）

> 注意区分两个容易混淆的参数：
> 
> - 实例普通方法第一个参数是 `self`：`self` 代表**已经造好的那个对象**
> - 类方法第一个参数是 `cls`：`cls` 代表**图纸/类本身**

（3）**执行流程，当你写 `Response.success(...)`**

1. Python找到类 `Response`，找到它身上绑定的类方法 `success`
2. 自动把 `Response` 传给参数 `cls`
3. 方法内部执行 `cls(code=200, ...)` → 创建一个 Response 实例
4. 把这个新建好的实例返回出去，交给FastAPI，最后转成JSON

### 自定义异常+全局异常处理

✅ **需求场景**
在我们项目之前的写法里，报错是手动写的：

```python
if not user or not verify_password(...):
    return Response.error(code=400, message="账号或密码错误")
```

这种写法有局限：

1. **return 只能返回给直接调用它的上层，深层函数传递错误非常麻烦** 
	如果在底层工具函数里面发现业务错误，return 只能传给上一层函数；每一层都要额外写 if 判断，一层一层把错误往上传递。层级一多代码冗余、很容易漏掉判断。

2. **原生各类异常的返回格式不统一** 
	FastAPI 原生 `HTTPException`、Pydantic 参数校验失败（RequestValidationError）、程序意外报错，它们默认返回的 JSON 结构、字段名称都不一样。前端要写多套解析逻辑，非常麻烦。

👉 我们想要做到：

1. 自己定义一种**业务报错（BusinessException）**，在代码任意地方，直接 `raise BusinessException(message="账号已禁用", code=403)` 抛出异常，不用一层层 return 传递错误信息
2. 不管是：我们自己抛的业务异常 / FastAPI 自带的 HTTPException / 参数校验异常 / 程序未知报错 全部拦截下来，**统一转换成我们这套 `{code, message, data}` 的返回格式**，给到前端
3. 前端永远只需要解析同一套 JSON 结构，不用区分是正常返回、手动 return 的错误、抛出异常带来的错误

> 一句话总结场景： 统一捕获各类异常，把所有报错的返回格式对齐我们的 Response 模板；并且支持在代码任意位置抛出业务错误。
> 
   这样还可以达到区分 “报错类型”，知道错哪了

- `return`：是正常返回结果，只传给紧挨着它的上一层，错误要手动层层传递、层层判断。层级深了非常麻烦。
- `raise 异常`：是中断当前流程的报错信号，自动向上冒泡，直达全局异常捕获器，中间代码不用管错误传递。

### `__init__`和`super()`再理解

```python
class BusinessException(Exception):
    """自定义的业务异常"""

    def __init__(self, message: str, code: int = 500):
        self.message = message
        self.code = code
        super().__init__(message)
```


**1. `__init__` 是什么**

`__init__` 叫**构造方法**。 当你 `类名(参数)` 创建对象的时候，Python 会自动调用 `__init__`。
作用：**给刚新建出来的这个实例，初始化、绑定属性**。

```python
# 执行这一句的时候，自动运行 __init__
exc = BusinessException(message="账号禁用", code=403)
```

**2. `super()` 是什么**

`super()`：拿到**父类**

`super().__init__(message)`
1. `super()` 得到【当前这个类 `BusinessException`】的父类，也就是 `Exception`
2. `().__init__(message)` 调用父类 `Exception` 的构造方法 `__init__`，把 `message` 传给它


✅ **需求场景：**
**3、我们为什么要改写父类 Exception 的 `__init__`**？

Python 原生自带的 `Exception`，里面只存错误提示文字（message），**没有 code 这个字段**。

我们现在项目需求： 抛出业务错误的时候，除了文字提示，还需要附带一个**自定义业务码 code**（400、403、500），后面异常处理器要读取 `exc.code` 组装返回体。

👉 原生 Exception 满足不了：它没有 code 属性。 所以我们继承 Exception，重写它的 `__init__`：
1. 保留原生异常原本需要的 message（交给父类处理）
2. **额外新增一个 self.code 属性**，存我们自己的业务码


```python
async def 处理器函数名(request: Request, exc: 要捕获的异常类型):
    return JSONResponse(
        status_code=HTTP状态码,
        content=Response.error(code=业务码, message="提示文字").model_dump(),
    )
```

统一规律：

1. 全部是 `async` 异步函数（FastAPI/Starlette 处理器要求）
2. 固定两个入参：
    - `request: Request`：本次 HTTP 请求对象（框架自动传进来，大部分时候我们不用主动使用它，但参数必须写上）
    - `exc: XxxException`：捕获到的异常实例，名字 exc 就是 exception 缩写，我们从这里读取错误信息
3. 返回 `JSONResponse`：专门用来返回 JSON 格式响应
4. `Response.error(...)`：调用我们之前写的统一返回模板，生成 Pydantic 对象
5. `.model_dump()`：把 Pydantic 模型转成 Python 字典，给到 JSONResponse

---


✅ 通用模板
```python
async def 处理器函数名(request: Request, exc: 要捕获的异常类型):
    return JSONResponse(
        status_code=HTTP状态码,
        content=Response.error(code=业务码, message="提示文字").model_dump(),
    )
```

统一规律：

1. `async` 标记这是一个**异步函数**
>核心一句话：
不是因为我们现在代码里面有异步任务要跑，而是我们要用异常处理器，而它本身设计就是给 async 函数用的

2. 固定两个入参：
    - `request: Request`：本次 HTTP 请求对象，框架自动传入。多数场景我们不会主动使用它，但是参数必须写上，框架会自动填充。
    - `exc: XxxException`：捕获到的异常实例，我们从这个对象里读取错误信息

3. 返回 `JSONResponse`：专门用来向前端返回 JSON 格式响应。
4. `Response.error(...)`：调用我们写好的统一返回模板，生成 Pydantic 模型对象。
5. `.model_dump()`：把 Pydantic 模型转换成 Python 字典，JSONResponse 接收字典后转为 JSON 字符串发给前端。


### Request
在 HTTP 规范里，客户端发出去的这一条消息，名字就叫 Request（请求）；
后端这边 FastAPI 把这条 HTTP 请求消息，封装成了一个叫 Request 的 Python 对象

✅ 所以： 看到代码里 `Request`，就代表：**这个对象承载的是一条 HTTP 请求报文**
其中包含：
- 请求路径 `/api/auth/login`
- 请求方法 GET / POST
- 请求头 Headers（前面熟悉的 `Authorization: Bearer xxx` 也在这里）
- 请求体 body 原始内容
等等一系列东西


FastAPI 底层 Starlette 在调用异常处理器的时候，**固定会传两个参数**： 
`(request, exc)`
1. request：本次请求对象
2. exc：抓到的异常对象，exc 是 exception 的缩写
