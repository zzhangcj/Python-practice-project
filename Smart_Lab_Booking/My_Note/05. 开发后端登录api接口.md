## 配置 Base 类和数据库会话工厂

在app目录下，创建database.py

Base 类就是所有数据库模型的公共父类，用来统一定义所有表都会拥有的公共字段和数据库配置。

```python
from sqlalchemy.orm import sessionmaker, DeclarativeBase, Mapped, mapped_column
from sqlalchemy import create_engine, DateTime
from app.config import settings
from datetime import datetime

engine = create_engine(settings.DATABASE_URL)

# 数据库session会话的连接工厂
SessionLocal = sessionmaker(bind=engine, autoflush=False)

def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()

class Base(DeclarativeBase):
    id: Mapped[int] = mapped_column(
        primary_key=True, autoincrement=True, comment="主键ID", sort_order=-1
    )
    create_time: Mapped[datetime] = mapped_column(
        DateTime, default=datetime.now, comment="创建时间", sort_order=1
    )
    update_time: Mapped[datetime] = mapped_column(
        DateTime, default=datetime.now, onupdate=datetime.now, comment="更新时间", sort_order=2
    )
```

id 写在 Base 里，建表时子类自己的字段会插到前面，主键就跑到最后了。sort_order 越小越靠前：id 用 -1 固定第一列，业务字段默认是 0，时间字段用 1、2 留在最后。

create_all 不会改已经存在的表。要看到新顺序，需要删表后重启后端重建。

## 创建 API 接口
在app目录下创建`api/auth.py`
（这个也需要`__init__.py`）
```python
from fastapi import APIRouter, Depends
from app.schemas.auth import LoginRequest
from sqlalchemy.orm import Session
from app.database import get_db
from app.models.user import User
from app.schemas.user import UserResponse

router = APIRouter(prefix="/api/auth", tags=["权限验证"])

@router.post("/login")
def login(data: LoginRequest, db: Session = Depends(get_db)):
    user = db.query(User).filter(User.username == data.username).first()

    # 判断账号和密码是否正确
    if not user or user.password != data.password:
        return {"code": 400, "message": "账号或密码错误"}
    return {
        "code": 200,
        "message": "操作成功",
        "data": UserResponse.model_validate(user),
    }
```

4、
#### 生成器yeild再理解
```python
def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

- 这是**依赖函数**，给 FastAPI 的 Depends 使用
> `Depends()` 是 FastAPI 内置的工具，专门用来做【依赖注入】
>
 使用方式：`Depends(你写好的函数)`，这里就是 `Depends(get_db)`
 >
 逻辑： 当请求进来，走到这个接口的时候，FastAPI 会**自动执行你传给 Depends 的函数（get_db）**，拿到函数 yield 返回的 db 对象，传给接口参数。
>
>比如：def login(db = Depends(get_db))

- `yield`：生成器，先把 db 会话交给接口函数使用
>yield 属于生成器关键字
>生成器常见优势：按需取值，不需要一次性加载全部数据，**节省内存**
>但在 get_db 这个依赖函数里，**使用 yield 不是为了节省内存**，而是利用生成器**暂停、恢复执行**的能力
>
>执行流程：
>1. 创建 db 会话；
>2. 执行 `yield db`：把 db 会话向外传递，**函数在这里暂停，停住不动** → 也就是**「先把 db 交给接口函数使用」**
>3. 接口内部逻辑全部执行完成（正常结束 / 抛出异常都算）
>4. 回到暂停位置，继续往下走，进入 finally，执行 `db.close()`，释放数据库连接。
>
> 关键对比： 
> 如果用 return，return 之后函数直接终止，关闭连接的代码永远无法执行。
> yield 实现了：先给资源，等资源用完，自动收尾释放。
> 
>`finally`：无论接口正常执行还是报错，最后一定会执行 `db.close()`，释放数据库连接，防止连接泄露

```python
class Base(DeclarativeBase):
    id: Mapped[int] = mapped_column(
        primary_key=True, autoincrement=True, comment="主键ID", sort_order=-1
    )
    create_time: Mapped[datetime] = mapped_column(
        DateTime, default=datetime.now, comment="创建时间", sort_order=1
    )
    update_time: Mapped[datetime] = mapped_column(
        DateTime, default=datetime.now, onupdate=datetime.now, comment="更新时间", sort_order=2
    )
```

- 所有模型（User 等）都继承这个 Base，自动带上这三个公共字段
- `sort_order`：控制数据表字段展示顺序，**数值越小，字段越靠前**
    - id 设置 sort_order=-1
    - 我们自己写的业务字段（username、password）没有指定 sort_order，默认值是 0
    - 大小对比：`-1 < 0 < 1 < 2`
    - 需要确保最终顺序：id → username、password → create_time → update_time
    - 如果不设置 sort_order=-1，默认 id 也是 0，那字段顺序就乱了，id 有可能跑到后面去


#### Mapped和mapped_column

✅ `Mapped[类型]`
- 作用：**标记这是数据库表的一个字段，同时声明 Python 侧的类型**
- `Mapped[int]`：
    - 告诉 Python / 类型检查工具：这个变量 `id` 是 `int` 整数类型
    - 告诉 SQLAlchemy：这是一个**映射到数据库的列**，不是普通的类属性
- 对比理解：
    
    ```python
    # 普通变量，只是Python变量，不会生成数据库字段
    name: str
    
    # Mapped包装：这是数据库表字段，会映射到mysql表里的一列
    name: Mapped[str]
    ```

> 简单一句话：`Mapped[]` 是**“标记身份”**：这个属性要同步映射到数据库，附带 Python 类型。

 ✅ `mapped_column(...)`
- 作用：**定义这个数据库列在 MySQL 里的规则、约束、附加配置**
- 里面传的参数，全部是数据库层面的设置：
    - `primary_key=True`：主键
    - `autoincrement=True`：自增
    - `comment="主键ID"`：数据库字段注释
    - `sort_order=-1`：控制生成表时字段先后顺序（前面有解析的）
    - `default=datetime.now`：新增数据时默认值
    - `onupdate=datetime.now`：更新行的时候自动赋值（update_time 专属）

#### 补充:什么是ORM模型
**Object Relational Mapping，对象关系映射**
通俗解释： 它就是把 Python 的类和对象，和 MySQL 的数据表做映射。
- 类 → 对应一张数据表
- 类里面的属性 → 对应表里的字段
- 创建这个类的实例对象 → 对应表里的一行数据


#### 怎么理解自动建表？
2、创建数据库 `lab_agent`
初次使用Navicat，需要注册，并连接MySQL，然后再创建

**既然是自动建表，为什么还要我专门取 navicat 新建 lab_agent 这个数据库**

> SQLAlchemy 的 `Base.metadata.create_all()` 只能建「数据表 (table)」，不能创建「数据库 (database)」
- `lab_agent`：这是**数据库（库）**，相当于一个文件夹。

## 4、`schemas目录下auth.py`和user.py

> 前置概念：`schemas` 在 FastAPI 项目里叫**数据模型/序列化模型**，基于 Pydantic。 作用：定义请求要接收什么字段、接口返回给前端什么字段；自动做类型校验；ORM对象 ↔ JSON 数据转换。

---
`schemas/auth.py`

```python
from pydantic import BaseModel

class LoginRequest(BaseModel):
    username: str
    password: str
```

逐行拆解：
1. `from pydantic import BaseModel` 导入Pydantic的基础模型类，所有自定义数据模型都要继承它。
2. `class LoginRequest(BaseModel):` 登录**入参模型**：专门用来接收前端POST提交过来的登录请求体（JSON）。
3. `username: str`：用户名，字符串类型，**必填**
4. `password: str`：密码，字符串类型，**必填**

✅ 功能：

1. 你的 Vue 前端登录的时候，axios 会发一段 JSON 给后端，长这样：
```json
{
  "username": "zhangsan",
  "password": "123456"
}
```

2. `LoginRequest` 就是提前跟 FastAPI 说好：
> 这个接口，我只接收这种格式的请求体（Body），必须有 username、password，而且都得是字符串。
    少字段、类型不对（比如username传数字）直接返回报错


---

`schemas/user.py`

```python
from pydantic import BaseModel, ConfigDict

class UserResponse(BaseModel):
    id: int
    username: str
    name: str
    role: str
    phone: str | None = None
    email: str | None = None
    status: int

    model_config = ConfigDict(from_attributes=True)
```

1、`class UserResponse(BaseModel):` 
>是登录**返回模型**：后端查询到用户数据之后，用来打包、返回给Vue前端的JSON结构

2、
```
id: int
username: str
......
```
这里，就是在**定义返回 JSON 的格式、类型、是否必填**

3、`model_config = ConfigDict(from_attributes=True)` 
>开启ORM自动转换：数据库查出来的SQLAlchemy用户对象，可以直接传给这个模型，自动转为给前端的JSON，不用手动一个个赋值。

✅ 功能： 后端从数据库拿到用户信息，通过 UserResponse 规范返回给Vue前端的JSON格式。
只会返回我们写在这里的字段，**不会返回数据库里的密码等敏感字段**，起到数据过滤保护的作用。 字段会自动校验类型，保证返回给前端的数据格式统一。


**总结**
- LoginRequest：登录**入参模型**，前端 → 后端（接收请求，校验提交的数据）
- UserResponse：登录**出参模型**，后端 → 前端（封装返回，控制向外输出哪些字段）
- schemas这个包就是在**专门给前后端之间传递的数据定下规矩**(该有哪些字段、是什么类型、哪些是必填、哪些可以为空)

### Pydantic 库

Pydantic 是 Python 的**数据校验 + 数据格式化库**，FastAPI 默认配套使用，是 FastAPI 实现参数校验的核心依赖。

✅ 核心作用两点：
1. **校验数据**：检查数据类型、是否缺失。比如 LoginRequest 要求 username 是字符串、必填；前端传数字、漏传字段，直接自动报错，不用自己写一堆 if 判断。
2. **转换包装数据**：像user.py里面的UserResponse，把数据库查出来对象，自动转换成标准 JSON，交给前端 Vue；同时控制哪些字段对外暴露，并隐藏敏感信息（比如密码）。

## 5、api/auth.py

```python
from fastapi import APIRouter, Depends
from app.schemas.auth import LoginRequest
from sqlalchemy.orm import Session
from app.database import get_db
from app.models.user import User
from app.schemas.user import UserResponse

router = APIRouter(prefix="/api/auth", tags=["权限验证"])

@router.post("/login")
def login(data: LoginRequest, db: Session = Depends(get_db)):
    user = db.query(User).filter(User.username == data.username).first()

    # 判断账号和密码是否正确
    if not user or user.password != data.password:
        return {"code": 400, "message": "账号或密码错误"}
    return {
        "code": 200,
        "message": "操作成功",
        "data": UserResponse.model_validate(user),
    }
```

**1、导入部分逐行拆解**

1. `from fastapi import APIRouter, Depends` 导入路由对象、依赖注入工具。`APIRouter`用来拆分接口路由；`Depends`用来注入数据库会话。
2. `from app.schemas.auth import LoginRequest` 导入**入参模型**，校验前端传过来的账号密码JSON。
3. `from sqlalchemy.orm import Session` SQLAlchemy的数据库会话类型，用来操作数据库。
4. `from app.database import get_db` 导入获取数据库连接的依赖函数。
5. `from app.models.user import User` 导入数据库ORM模型（数据库user表映射对象）。
6. `from app.schemas.user import UserResponse` 导入**出参模型**，包装要返回给Vue的用户数据。

#### 依赖注入（Depends）

依赖注入（Depends），很多人说它是 FastAPI 的灵魂：
> 简单说：**把接口需要用到的资源（数据库会话、权限校验、配置）单独抽出去，需要的时候自动给你送进来，不用自己手动写重复代码**。

拿你现在代码看：

```python
def login(data: LoginRequest, db: Session = Depends(get_db)):
```
- `db` 就是注入进来的数据库会话。
- `get_db` 是一个函数，作用是创建、提供数据库连接

**通俗比喻**
你写登录接口、后面还要写用户查询接口、修改接口，**全都需要数据库连接**。
- 如果不使用依赖注入：每个接口里面都要重复写：打开数据库、用完关闭数据库，大量重复代码。 
- 依赖注入：单独写好 `get_db` 这个 “供应工具”。哪个接口需要数据库，写上 `Depends(get_db)`，它就自动把数据库会话送过来给这个接口用，接口用完自动回收

#### 路由router
什么是路由：就是FastAPI 的 APIRouter（代码里的 router），用来就是存放各种接口的一个东西

实例化 APIRouter得到一个路由对象，取名 router。

-  `tags=["权限验证"] `：对在这个路由下的接口进行分组

#### 装饰器知识点再理解
（1）什么是装饰器：`@xxx` 就是**装饰器**，属于 Python 语法糖；
>作用：**不修改函数内部代码，给这个函数附加额外能力**
```python
@router.post("/login")
def login(...):
```
作用：**在不修改 login 函数内部代码的前提下，给函数增加接口能力**，同时把login这个接口放进router这个容器里面

#### HTTP的请求方式
- HTTP 有多种请求方式，常见：GET、POST、PUT、DELETE。
- 请求体（Body）：HTTP 请求里独立存放数据的区域，和网址是分开的。 
- GET：一般用来查询获取数据，它传递的数据会拼在网址后面。
- POST：可以把数据放到请求体 Body 里面传输。

```python
@router.post("/login")
```
(1)`.post`：这里写 post，意思就是**要求前端必须用 POST 这种请求方式来访问这个接口**
- 选用 POST 的原因：POST 可以把账号密码放在请求体（Body）里传输，不会直接拼在网址上，相对安全，也适合传递 JSON 格式的数据。 
- 如果用 GET，数据会拼在网址后面，网址会直接显示账号密码，不安全，也不适合提交这类数据

(2)`("/login")`：接口的子路径，和上面 router 的 prefix 拼接，组成完整访问路径`/api/auth/login`
>我们用电脑 C 盘、文件夹的类比来讲
- `prefix="/api/auth"` → 相当于一个**父文件夹路径**：`C:\api\auth\`
- `("/login")` → 这个就是父文件夹里面的**文件名字**：`login`

>合起来： 父文件夹 + 文件名 = `C:\api\auth\login` 
>对应接口： prefix + 子路径 = `/api/auth/login`
>	`/login` 就是这个文件夹里面的项目
>	同一个父文件夹（同一个 router）下后续再加别的接口（比如logout），只需要"直接创建文件就行"，比如`@router.post("/logout")`

# 整个流程总结

整条登录链路：

1. Vue（前端）发 `{username,password}`,JSON数据
2. ✅ `LoginRequest`（schema 请求模型）：校验发来的 JSON 规矩
3. ✅ `APIRouter`（路由）：装登录这个接口的 “盒子”，统一前缀、统一 docs 分组
4. ✅ `Depends(get_db)`：依赖注入，获取数据库连接，让我们可以查数据库
5. ✅ `Session`：数据库会话，相当于打开数据库的 “操作手”，用来写查询语句
6. ✅ User（models 里的 ORM 模型）：和数据库 user 表一一对应，代表表里面的一行行数据
7. ✅ UserResponse（schema 响应模型）：包装要返回给前端的数据，约定返回 JSON 格式，自动剔除 password 等敏感字段
8. ✅ `model_config(from_attributes=True)`：一个开关，允许直接把数据库查出来的数据丢进 UserResponse

**项目分层结构**
1. **配置层**
- `.env`：存放数据库地址等敏感配置，不提交到代码仓库
- `config.py`：读取`.env`配置，统一管理项目配置

2. **数据库底层（database.py）** 
- 创建数据库引擎、数据库会话；提供`get_db`依赖，自动分配、释放数据库连接；定义 ORM 基类 Base。

3. **数据模型层**
- `models/user.py`：SQLAlchemy ORM 模型，映射 user 数据表，用来和数据库交互
- schemas 目录（Pydantic 数据契约）
    - `auth.py`：入参模型，约束前端传给后端的 JSON
    - `user.py`：出参模型，约束后端返回前端的 JSON

4. **接口业务层（api/auth.py）** 
- 编写 login 登录接口；
- 依靠依赖注入拿到数据库会话；
- 使用 ORM 查询用户、校验账号密码；
- 将 ORM 对象转为 schema 模型后返回给前端。
>ORM 对象 = 数据库里拿出来的数据；
>schema 模型 = 和前端交流的 JSON 规矩

5. **项目入口（main.py）**
-  实例化 FastAPI 主应用，引入并挂载各个 router 路由；用 uvicorn 启动后端服务。

---

**流程梳理**

前端发起登录请求 → FastAPI自动校验请求体 → 注入数据库会话 → ORM查询用户 → 校验账号密码 → 用schema过滤掉密码再返回JSON → 请求结束自动关闭数据库连接。
