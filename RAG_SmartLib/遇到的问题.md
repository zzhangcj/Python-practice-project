## 本次Bug复盘笔记
### Bug现象
1. 现象：程序启动打印`共加载0个文档`，网页端文档数量=0，但是文档块3101能从旧缓存读取。
2. 终端调试打印发现：程序把**DeepSeek的API密钥字符串当成了docs文件夹路径**，去寻找名为sk-xxxx的文件夹，目录不存在，读取txt文档返回空列表。

### 根本原因
Streamlit页面初始化函数里面，实例化RagSystem时代码写了：
```python
rag = RagSystem(st.session_state.api_key)
```
RagSystem类`__init__`第一个形参是`docs_dir`。
> Python位置传参规则：`RagSystem(参数)`，传入的第一个实参，会直接赋值给第一个形参`docs_dir`。
> 于是**API密钥字符串被错误赋值给docs_dir**，程序去磁盘查找名称等于密钥的文件夹，自然找不到任何txt文档。

### 修复操作
把实例化代码改为不传参，使用默认参数：
```python
rag = RagSystem()
```
此时`docs_dir`自动使用默认值`"docs"`，程序读取项目根目录下`docs`文件夹，成功加载里面120个txt文档。

### 踩坑关键点总结
1. 类构造函数参数顺序很关键，**位置传参很容易传错参数**，这是新手非常高频的坑。
2. 缓存会掩盖问题：旧的`doc_chunks.pkl`缓存文件还存在，文档块数据正常加载，让人误以为文档读取模块没问题，干扰排查。
3. 调试技巧：在load_documents打印目录绝对路径、文件夹是否存在、目录内文件列表，可以快速定位文件路径类问题。

### 优化建议（可选）
后续写代码，实例化类的时候，优先使用**关键字传参**，规避位置传参带来的参数错位问题，例如：
```python
rag = RagSystem(docs_dir="docs")
```

### 一句话精简
> Bug描述：RAG系统启动后文档加载数量为0。排查发现是实例化RAG类时，错误将API密钥作为位置参数传入，覆盖了文档目录参数，程序把密钥字符串识别为文件夹名称，找不到文档目录。修改实例化代码，使用构造函数默认参数指定文档目录，成功读取全部文档。
