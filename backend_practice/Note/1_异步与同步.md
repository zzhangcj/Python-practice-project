# FastAPI 同步 & 异步学习笔记
## 一、基础概念
1. **app = FastAPI()**
创建后端Web服务实例，相当于启动网站后台程序。

2. **@app.get("/sync")**
   - `@` 是Python装饰器语法
   - 作用：绑定访问路径 和 处理函数
   - 含义：浏览器发起GET请求访问 `http://127.0.0.1:8000/sync`，自动执行下方定义的函数

3. **127.0.0.1:8000**
   - `127.0.0.1`：本地回环地址，**只有自己电脑可以访问**，专门用于本地开发测试
   - `8000`：端口号，用来区分电脑上同时运行的各类软件
   - 完整地址含义：访问本机8000端口运行的服务，调用 `/sync` 接口

4. **uvicorn.run()**
   - `uvicorn`是ASGI服务器，作用是启动FastAPI后端服务。

5. **async def**
   - 定义异步函数（协程），调用后返回**协程对象**，不会立即执行内部代码
   - 协程对象需要被 `await` 驱动才能真正运行

6. **await**
   - 作用：等待协程执行完毕，获取返回值
   - 特性：等待期间让出控制权，事件循环可执行其他任务
   - 限制：**只能在 `async def` 函数内部使用**

7. **asyncio.gather()**
   - 作用：**并发执行**多个协程，等待全部完成后收集返回值（按传入顺序）
   - 参数要求：接收**多个独立协程作为位置参数**，不能直接传入列表

8. ***tasks 星号解包**
   - `tasks` 是列表：`[协程1, 协程2, 协程3]`
   - `*tasks` 将列表内每个元素**拆开**，依次作为独立参数传入
   - 示例：`gather(*tasks)` 等价于 `gather(协程1, 协程2, 协程3)`

   **❌ 错误写法**
   ```python
   tasks = [asyncio.sleep(1), asyncio.sleep(2)]
   await asyncio.gather(tasks)   # 报错！把整个列表当成1个参数传入了

## 二、同步接口知识点（/sync）
- 函数使用普通 `def` 定义，属于同步函数
- `time.sleep(1)`：阻塞等待。程序会原地卡住，等待期间无法处理其他任何任务
- 执行特点：任务串行，必须一件做完，再执行下一件
- 实验现象：循环休眠10次，总共耗时大约10秒
- 缺陷：多个用户同时访问接口时，请求会排队，服务容易卡顿

## 三、异步接口知识点（/async）
- 函数使用 `async def` 定义，称为异步函数（协程）
- `asyncio.sleep(1)`：非阻塞等待。任务等待时释放线程资源，服务可以处理其他请求
- `asyncio.gather(*tasks)`：并发批量执行多个异步任务；`*tasks` 代表列表解包
- `await`：只能写在 `async def` 函数内部，作用：等待所有异步任务执行完毕
- 实验现象：10个休眠任务同时并发执行，总共耗时大约1秒

## 四、高频易错规则（必记）
1. ❌ 异步函数内不要使用 time.sleep()，依然会阻塞线程，异步优势直接消失
2. ❌ await 不能写在普通 def 同步函数中，直接触发语法错误
3. 异步不是万能提速：仅在IO等待场景生效（休眠、网络请求、数据库操作、读写文件）；纯CPU计算场景无法提速

## 五、同步 vs 异步对比
| 项目 | 同步接口 /sync | 异步接口 /async |
| ---- | -------------- | --------------- |
| 函数定义 | def | async def |
| 等待方式 | time.sleep()（阻塞） | await asyncio.sleep()（非阻塞） |
| 执行方式 | 串行排队执行 | 多任务并发等待 |
| 本次实验耗时 | ≈10s | ≈1s |

## 六、通俗总结
同步：排队办事，一件完成才能开始下一件；
异步：任务等待的时候让出资源，可以同时处理多个等待任务，服务并发能力更强。

## 八、补充：API 交互文档（Swagger UI）

1. **访问地址**
   - 启动 FastAPI 服务后，浏览器访问 `http://127.0.0.1:8000/docs`
   - 自动生成当前项目的**交互式 API 文档页面**，无需额外安装或编写代码


2. **页面能做什么**
   - 列出所有接口（路径、请求方法、函数名）
   - 点击任意接口 → **Try it out** → **Execute**，直接发送请求并查看返回结果
   - 无需在地址栏手动输入 URL，也无需额外使用 Postman


3. **背后的核心知识点**

（1）**FastAPI 自带的优势**
- FastAPI 创建的项目**自带自动文档**，开箱即用
- 对比：Flask / Django 需要额外安装插件才能实现类似功能
- 这是 FastAPI 面试常见优势之一

（2）**HTTP 请求方法 —— GET**
- 蓝色 `GET` 标签表示该接口接收 **GET 请求**
- 简单理解：GET 用于**查询数据**（如获取信息、简单计算）
- 拓展：后续会学到 `POST`，用于**提交新增数据**（如表单、JSON）

（3）**路由（路径）概念**
- `/sync`、`/async` 就是接口路由，对应代码中 `@app.get("/sync")` 的字符串
- 浏览器访问地址最后的路径，用来区分服务中的不同功能

（4）**直观对比同步 / 异步效果**
- 可以同时打开 `/sync` 和 `/async` 两个接口分别测试
- `/sync` 接口会排队阻塞（同步接口），感受串行执行的耗时
- `/async` 接口并发执行（异步接口），感受性能提升

4. **拓展了解（现阶段不用深挖）**
- `OAS 3.1` / `openapi.json`：OpenAPI 规范（旧称 Swagger），一套描述接口信息的通用标准，行业内前后端对接、接口测试工具（如 Postman）都支持
- FastAPI 内部自动生成 `openapi.json`，网页读取该文件渲染出文档界面
- 页面上的 `Func Sync`、`Func Async` 会自动读取函数名作为接口名称，后续可自定义标题描述
